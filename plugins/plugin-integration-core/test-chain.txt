# plugin-integration-core — explicit test chain (one command per line).
#
# This list used to live in package.json's `scripts.test` as one ~14 KB `&&` string. That put a
# high-churn, append-only developer list inside a file whose whole-file sha256 is pinned as
# `runtimeFiles.pluginPackageJson` in
#   lib/sealed-export/vectors/s6a-package-provenance-pins.json
# so EVERY PR that added a test edited the same package.json line AND re-computed that pin —
# two guaranteed conflicts between any two concurrent plugin PRs, and a pin that moved so
# routinely it could no longer signal anything (see the #4801 P1 note in
# __tests__/test-chain-completeness.test.cjs: a disabled suite plus "the routine re-pin" was
# indistinguishable from a legitimate change).
#
# Moving the list here leaves package.json's pin covering exactly what it is for — dependencies,
# the 129 named scripts, and the manifest — and lets it stay still. The chain itself is guarded
# SEMANTICALLY instead of by digest, which is strictly stronger (see scripts/test-chain.cjs and
# __tests__/test-chain-completeness.test.cjs):
#   - every command must match the exact allowlisted shape below — nothing else can be expressed;
#   - it is executed WITHOUT a shell, argv-by-argv, so `&&`, `|`, `;`, `echo ` cannot be smuggled in;
#   - every *.test.{cjs,mjs} in __tests__/ must appear here exactly once, and every line here must
#     name a file that exists.
#
# ADDING A SUITE: insert your line in the "suites" block below, before the ordered sealed-export
# stage tail. Keep one command per line — that, plus `merge=union` in .gitattributes, is what
# lets two concurrent PRs add tests without conflicting.
#
# Allowed shapes (enforced):
#   node __tests__/<name>.test.cjs
#   node --import tsx __tests__/<name>.test.mjs
