## 1. 总览：谁、做什么、按什么顺序

三个角色：

- **宜搭/钉钉管理员**（客户方）：准备测试应用、测试表单和四项凭据材料。
- **运维**（部署 MetaSheet 的人）：部署、核实迁移、用命令行登记“宜搭 owner”、控制发送开关。
- **宜搭 owner**（MetaSheet 内被指定的那一名集成管理员）：配置字段、做本地初始化、审核并发送。

顺序（不能跳步，不能提前做后面的步骤）：

| 步骤 | 谁 | 做什么 | 先要有的批准 | 可逆？ | 发到宜搭？ |
|---|---|---|---|---|---|
| 1 | 宜搭/钉钉管理员 | 建**测试**应用和**测试**表单，准备材料（第 2 章） | — | 是 | 否 |
| 2 | 运维 | 部署、执行迁移 090–096，并用 `--confirm` 核实（3.1） | ① | 迁移不可回滚 | 否 |
| 3 | 运维 | 在生产库登记唯一的宜搭 owner（3.2） | ② | **否** | 否 |
| 4 | 宜搭 owner | 冒烟检查：看到「已确认本地空槽」（3.3） | — | 只读 | 否 |
| 5 | 宜搭 owner | 用自己的配置做本地预演，**先导出**规则草稿并离线归档（4.2） | — | 是 | 否 |
| 6 | 宜搭 owner + 运维 | 逐项勾完「初始化前检查清单」（4.3） | — | — | 否 |

## 2. 客户准备（宜搭 / 钉钉侧）

### 2.1 只用测试应用和测试表单

- 请建一个**测试**宜搭应用和一张**测试**表单，不要用生产表单。（这是 owner 的决策，代码本身不区分测试还是生产。）
- 重要：MetaSheet 一个部署**只能登记一个目标表单，而且登记后永久不能更换**（第 7 章）。如果初始化时登记的是测试表单，以后要换成生产表单，需要开发另行改造，界面里做不到。这一点必须在初始化前由 owner 决定（第 4.3 节检查清单第 I 项、第 8 章）。

### 2.2 MetaSheet 需要的值

| 值 | 是什么（按代码） | 在钉钉/宜搭哪里取 |
|---|---|---|
| `appKey` | 钉钉应用的 AppKey。MetaSheet 用它和 `appSecret` 向钉钉开放平台换取应用访问令牌。最长 4096 字符。**前后的空格、换行会原样永久保存**（第 4.4 节）。 | 向钉钉管理员确认（应用类型、所需接口权限待确认，见第 8 章） |
| `appSecret` | 同上应用的 AppSecret。最长 4096 字符。同样不去空格。 | 向钉钉管理员确认 |
| `systemToken` | 宜搭应用的 systemToken。创建表单记录时随请求一起发送。最长 4096 字符。同样不去空格。 | 向宜搭管理员确认 |
| `userId` | 以谁的身份在宜搭创建记录（钉钉用户 ID）。创建时随请求发送；同时作为“人工确认的执行身份”记录。最长 128 字符，不能有首尾空白或控制字符。 | 向钉钉管理员确认 |
| `organizationId` | 人工确认的组织标识。代码只检查**格式**（1–128 字符、无首尾空白、无控制字符），**不核验含义**；只记录、在预览中显示，不发给宜搭。 | 应填哪个值待确认（第 8 章） |
| `appType` | 宜搭应用标识，写在目标配置里，随创建请求发送。 | 向宜搭管理员确认 |
| `formUuid` | 宜搭表单标识，写在目标配置里，随创建请求发送。 | 向宜搭管理员确认 |
| 表单字段 ID | 表单里每个控件的字段标识，用于“字段目录”和“字段映射”。MetaSheet **不会**去宜搭查询核对。填错时：若宜搭返回非 2xx，结果记为“结果未知”；若宜搭仍返回 2xx，会记为 `acknowledged`，**可能连真实发送时都看不出来**（第 4.7 节）。 | 向宜搭管理员确认，逐个抄准 |
| 控件类型与选项 | 每个字段在界面上选「文本」「数字」「单选」（下拉单选）或「单选按钮」；单选/单选按钮的选项文字要逐字一致。控件类型**不发给宜搭**，只用于本地校验（选项是否匹配、是否为数字）。 | 向宜搭管理员确认 |
| 人工审核编号 | owner 自己的内部审核单号，用来说明“这个目标和执行身份是谁、何时审核过”。1–128 字符，无首尾空白。 | owner 自定 |

**标识符规则**（代码强制）：1–128 个字符，只能由字母（含中文等 Unicode 字母）、数字、下划线、连字符组成；而且**不能包含**以下片段（不区分大小写）：`password`、`token`、`appkey`、`appsecret`、`systemtoken`、`authoritycode`、`credential`、`secret`、`prototype`、`constructor`、`__proto__`。

这条规则适用于：字段目录的字段 ID、映射的 source 和 target、业务键，**以及粘贴数据里每一行的每一个键（包括没有映射的多余列）**。数据里只要有一个键不合格（例如含 `token` 的 `tokenNo`，或含空格），**整份数据**都会被拒绝（`YIDA_STATIC_ROWS_INVALID`）。如果表单字段 ID 恰好含这些片段，当前版本无法映射该字段，请联系开发。

当前版本只支持四种控件：文本、数字、单选、单选按钮。发往宜搭的字段值只能是文本或数字（不支持布尔、日期、附件、子表等）。

### 2.3 网络

MetaSheet 后端需要能以 HTTPS 访问钉钉开放平台接口（固定地址写在代码 `plugins/plugin-integration-core/lib/yida-token-exchange.cjs` 和 `yida-form-transport.cjs` 中）。后端直接使用 Node 内置的 fetch，代码里**没有配置出网代理**。客户防火墙是否放行、是否必须经代理出网，见第 8 章。

### 2.4 如何安全交接

- **绝不**通过聊天、邮件正文、issue、PR、截图、工单附件传递 `appKey`、`appSecret`、`systemToken`。
- 最安全的做法：由持有材料的人**本人**在初始化界面里直接粘贴录入（第 4.4 节），材料不经第三人。
- 若必须交接，使用 owner 指定的安全渠道；具体渠道由 owner 决定，本手册不指定。
- 初始化界面不会把材料存进浏览器，提交后输入框立即清空；离开页面也会清空。

## 3. 运维部署

### 3.1 部署与迁移 090–096（需要批准 ①）

客户主机用部署包和部署脚本（`multitable-onprem-apply-package.ps1`）部署。部署脚本默认会执行迁移（参数 `RunMigrations` 默认是 `1`），执行的是部署包里的 `node packages\core-backend\dist\src\db\migrate.js`。注意：仓库里的 `pnpm --filter … migrate` 是开发用命令（依赖 tsx 和源码），部署包里不能用。

这 7 个迁移是**纯新增**：只建新表、新索引、新触发器，不删除也不修改任何已有业务表。迁移没有回滚（down）步骤。

| 迁移 | 新建内容 | 作用 |
|---|---|---|
| `090_create_integration_yida_delivery_ledger` | 表 `integration_yida_delivery_ledger`、`integration_yida_delivery_audit`，及防改写触发器 | 每一行发送的账本（状态：prepared / dispatching / acknowledged / outcome_unknown / not_sent）与审计 |
| `091_create_integration_yida_create_fence` | 唯一索引 `uniq_integration_yida_delivery_create_business` | 同一租户 + 同一目标 + 同一业务键，只能“创建”一次；**任何状态**都占住这个位置 |
| `092_create_integration_yida_credential_materials` | 表 `integration_yida_credential_materials`、`integration_yida_credential_audit` | 加密保存四项凭据材料及其审计（审计里不含材料） |
| `093_create_integration_yida_draft_plans` | 表 `integration_yida_draft_targets`、`_draft_operations`、`_draft_rows`、`_draft_audit`（均只增不改） | 服务器端草稿 |
| `094_create_integration_yida_approved_target` | 表 `integration_yida_approved_target`（只有 1 个槽位）、`_approved_target_audit` | 人工确认的唯一目标 |
| `095_create_integration_yida_send_approvals` | 表 `integration_yida_send_approvals`、`_send_revocations`、`_send_admissions`、`_send_approval_audit`（均只增不改） | 单次授权、撤销、准入记录 |
| `096_create_integration_yida_initialization` | 表 `integration_yida_initialization_anchor`（owner 锚点，1 个槽位）、`integration_yida_initializations`；并撤销这两张表对 PUBLIC 的权限 | 运维登记的 owner 锚点与初始化结果 |

**部署后核实迁移**（只读）：在部署根目录，按第 3.2 节第 3 步的方法把 `DATABASE_URL` 读进当前窗口，然后：

```powershell
foreach ($m in '090_create_integration_yida_delivery_ledger','091_create_integration_yida_create_fence',
  '092_create_integration_yida_credential_materials','093_create_integration_yida_draft_plans',
  '094_create_integration_yida_approved_target','095_create_integration_yida_send_approvals',
  '096_create_integration_yida_initialization') {
  node .\packages\core-backend\dist\src\db\migrate.js --confirm $m
  "$m 退出码 $LASTEXITCODE"
}
Remove-Item Env:DATABASE_URL
```

退出码：`0` 已执行（打印 `migration "…" is applied`）；`1` 未执行（打印 `is NOT applied (still pending)`）**或命令本身出错**（例如连不上数据库，此时打印错误信息）；`2` 不认识这个名字。退出码为 1 时必须看打印内容区分；打印的是错误时，不能据此认定迁移未执行，请运维排查连接（本片段只读入了 `DATABASE_URL`，没有读入 app.env 里的 `NODE_ENV`、`DB_SSL*`；数据库要求 TLS 时会连不上。反过来，若这台主机在系统层面设置了 `NODE_ENV=production`，迁移命令会默认启用 TLS，数据库不支持 TLS 时也会连不上，此时要按 app.env 的写法在本窗口另设 `DB_SSL=false`，不要改系统设置）。错误输出可能含主机名或端口，不要贴进聊天或 issue。七个都必须是 `0`；至少 `096` 必须是 `0`，否则第 3.2 节的命令会报 `unconfirmed`。也可以用 `--list` 查看待执行项（只读）。

**不要手工改这些表。** 部分手工改动会被触发器拒绝；另一些（账本状态推进、凭据轮换或撤销）数据库是允许的，但做了就不可逆，会让本功能永久不可用（第 5.3 节）。

### 3.2 登记宜搭 owner（运维命令行，需要批准 ②，只做一次）

**作用**：在数据库里写入一个永久锚点，指明“哪个 MetaSheet 用户、在哪个租户下”是宜搭 owner。界面上没有任何入口能建立、转移或清空这个锚点。代码注释原文要求：在生产环境执行、以及真实的 owner/租户，都必须由部署 owner 另行授权。

**前提条件**（命令会在写入前检查，不满足则报 `denied`）：

- owner 已书面指定：哪一个 MetaSheet 用户、哪一个租户（组织）。
- 该用户存在、处于启用状态、通过账号激活检查；
- 该用户在该租户（组织）下有一条**有效**的成员关系；并且建议该用户在**全部组织中恰好只有这一条**有效成员关系，否则登录后会话里没有租户，所有宜搭请求都会被 403 拒绝（第 5.1 节 `YIDA_OWNER_HTTP_DENIED`）；
- 若 owner 用**钉钉登录**：第一次钉钉登录时系统会自动建号或绑定；客户主机没有配置钉钉 corpId 时会被拒绝（409 `auto_provision_corp_required`），有两个账号都能匹配时也会被拒绝（409 `identity_ambiguous`）。所以登记 owner 之前，先确认这个 owner 账号已经存在并已绑定钉钉，或确认 corpId 已配置。
- 该用户是“实时集成管理员”，满足以下任一：
  - 拥有 `admin` 角色（角色分配里的 admin，或用户记录上的角色为 admin）；
  - 持有 `role:admin` 权限；
  - 同时满足三条：持有 `integration:admin` 权限（来自角色、直接授予或用户记录均可）；至少有一个角色属于 `integration` 命名空间；该用户的 `integration` 命名空间准入为“启用”。

**第 1 步：准备清单文件**（JSON，放在服务器上，用**绝对路径**引用）：

```json
{ "ownerId": "<MetaSheet 用户 ID>", "tenantId": "<该用户所属租户 ID>" }
```

- 只能有这两个键，都是非空字符串，最长 128 字符，不能有首尾空白或控制字符；
- 文件不超过 4096 字节，UTF-8 编码（带不带 BOM、换行是 CRLF 还是 LF 都可以）；用记事本另存为 UTF-8，不要用 Windows PowerShell 5.1 的 `>` 或 `Out-File` 生成（默认 UTF-16，命令会报 `input`）；
- `ownerId` 是 MetaSheet 用户的 ID；`tenantId` 是该用户有效成员关系所在的租户（组织）ID。取值方法待确认（第 8 章），不要在聊天里传递。

**第 2 步：确认部署包含 CLI 修复**。（出包时的随包校验 `multitable-onprem-package-verify.sh` 已把这个命令文件和它加载的 `dist\src\integration\yida-initialization-bootstrap.js` 列为必需内容，缺任一个都会报 `Required package content missing` 而不出包；这里的 `Test-Path` 是部署现场的二次确认，仍然要做。）在部署根目录（其下有 `packages\core-backend\dist`）执行：

```powershell
Test-Path -LiteralPath '.\packages\core-backend\dist\scripts\bootstrap-yida-initialization-owner.js'
```

结果必须是 `True`。如果是 `False`，说明这个版本不含 `825a6fbe8`：**停止**，联系开发。不要改用 `tsx`、不要拷贝源码脚本过来运行。

**第 3 步：只把 `DATABASE_URL` 读进当前窗口**。命令只从环境变量 `DATABASE_URL` 读取数据库连接串，**不读 app.env**，也**不要**把连接串写在命令行上或手工输入（会留在命令历史里）。这个命令**只用连接串本身**连接数据库，不看 `NODE_ENV`、`DB_SSL*`：若客户数据库要求 TLS，TLS 设置必须已写在 `DATABASE_URL` 里（例如连接串参数 `sslmode`，由运维按客户数据库的要求确认），否则命令会报 `unconfirmed`。另外，命令自己的连接只用连接串，但登记时会加载服务端模块，这些模块还会读取 `SECRET_PROVIDER`、`SECRET_FILE_PATH`、`NODE_ENV`、`DB_SSL*` 等变量：所以**只把 `DATABASE_URL` 读进这个窗口，不要把整份 app.env 读进来**；若窗口继承了 `SECRET_PROVIDER=file` 而那个文件里没有 `DATABASE_URL`，在 `NODE_ENV=production` 下也会报 `unconfirmed`。判定结果时以输出的**最后一行** JSON 为准（前面可能先打印一行不含业务值的警告）。请开一个新的 PowerShell 窗口，按部署脚本相同的读法从 app.env 读取（去掉首尾空白、去掉一层引号、同名多行取最后一行），不要把值打印出来：

```powershell
Set-Location '<部署根目录>'
$envFile = '<部署根目录>\docker\app.env'   # 部署脚本的默认位置；以现场实际位置为准
$line = Get-Content -LiteralPath $envFile | ForEach-Object { $_.Trim() } |
  Where-Object { $_ -match '^DATABASE_URL\s*=' } | Select-Object -Last 1
if (-not $line) { throw 'app.env 里没有 DATABASE_URL' }
$value = ($line -split '=', 2)[1].Trim()
if ($value.Length -ge 2 -and (($value.StartsWith('"') -and $value.EndsWith('"')) -or ($value.StartsWith("'") -and $value.EndsWith("'")))) {
  $value = $value.Substring(1, $value.Length - 2)
}
$env:DATABASE_URL = $value
Remove-Variable line, value
```

**第 4 步：运行**（清单路径用 Windows 绝对路径）：

```powershell
node .\packages\core-backend\dist\scripts\bootstrap-yida-initialization-owner.js --input 'C:\<目录>\yida-owner.json' --apply
```

- 参数必须恰好是 `--input <绝对路径> --apply` 三项，多一个少一个、或路径不是绝对路径，都会报 `input`。
- 运行完立即执行 `Remove-Item Env:DATABASE_URL`，然后关闭这个窗口。

**数据库权限**：命令使用的数据库账号需要对 `users`、`user_roles`、`role_permissions`、`user_permissions`、`user_orgs`、`user_namespace_admissions` 六张表有 SELECT 和 UPDATE 权限（用于行锁），还需要能读写锚点表。app.env 里的账号（后端运行账号）是否满足、是否与迁移账号相同，待确认（第 8 章）。

**第 5 步：判读结果**。输出是一行 JSON，例如 `{"ok":true,"status":"provisioned"}`，输出里不含任何 ID。

> **判读规则：以屏幕上打印出来的那一行 JSON 为准，不以退出码为准。** 只有打印出 `{"ok":true,"status":"provisioned"}` 才算成功。**如果什么都没打印（即使退出码是 0），不算成功**，说明命令没有真正执行，联系开发。

| 打印的 status | 退出码 | 含义 | 怎么办 |
|---|---|---|---|
| `provisioned` | 0 | 锚点已写入；或之前已用**同一份**清单写入过（重跑是幂等的，不会写第二条） | 完成。接着做第 3.3 节冒烟检查 |
| `input` | 1 | 参数或清单文件不合格（路径不是绝对路径、文件读不到、键多了或少了、空值、首尾空白、超长等）；数据库未被触碰 | 修正参数/文件后重跑 |
| `denied` | 1 | 该用户不存在、未启用、未通过激活检查、在该租户下没有有效成员关系，或不是实时集成管理员；没有写入任何行 | 先在 MetaSheet 里补齐角色/成员关系，再重跑 |
| `conflict` | 1 | 锚点已经指向**另一个** owner 或租户；锚点保持不变（仍是第一次登记的 owner） | 锚点永久不可改。停止操作，联系开发；不要改库 |
| `unconfirmed` | 1 | 结果未确认。可能原因：没设 `DATABASE_URL`、连不上库、提交时连接中断；**以及重跑也修不好的**：迁移 096 未执行、数据库账号权限不足、命令所需模块加载失败（部署包不完整） | 不要假设“什么都没发生”。先排除重跑修不好的三类（用 `--confirm` 核实 096、核对账号权限、核对部署包完整），再用**同一份**清单原样重跑一次：若锚点已写入，会返回 `provisioned` |

**重跑行为**：命令总是**先**检查该用户此刻是否仍是实时集成管理员，**再**读锚点。所以：

- 同一 owner + 同一租户重跑：通常返回 `provisioned`；但如果这期间该用户失去了管理员权限或成员关系，会返回 `denied`（锚点不受影响）。
- 换成另一位合格的管理员重跑：返回 `conflict`，锚点仍指向第一位 owner。
- 换成不合格的用户：返回 `denied`。
- 数据库不可用：返回 `unconfirmed`。

### 3.3 登记后的冒烟检查（宜搭 owner，只读）

目的：证明锚点、owner 登录会话里的租户、实时权限三者一致（第 0.2 节条件 9）。**这一步通过之前，不要做本地初始化。**

1. owner 用自己的账号登录（站点应已是 HTTPS，或在服务器本机用 localhost 访问）。
2. 打开「备料」工作台的项目备料页，打开任意一个项目号，点「宜搭静态预演（不发送）」。
3. 「预演合同」选「表单字段目录与协议 v2（仅本地）」。可以用自己的真实配置；如果还没有，可以点「填入七项身份合成样例 A」**仅用于冒烟**。点「只在本地预演」。
4. 点「打开本地初始化（不发送）」，再点「手动 GET 本地初始化状态」。
5. **期望结果**：显示「初始化命令：…」和「已确认本地空槽；仍须填写材料并人工确认，才能手动初始化。」把日期和这句结果文字记入内部记录（不记 ID）。
6. **不要填任何材料、不要勾选确认框**。看到结果后，立即再点一次「宜搭静态预演（不发送）」关闭面板。（样例里的目标是假的；一旦用它初始化，唯一目标槽位会永久绑定在假表单上。）

| 冒烟时看到 | 说明 | 怎么办 |
|---|---|---|
| 「已确认本地空槽…」 | 通过 | 继续第 4.2 节 |
| `YIDA_OWNER_HTTP_DENIED` | 会话里没有租户：该用户的有效组织成员关系不是恰好一条，或登录时带上了该用户不属于的组织 | 把成员关系调整为恰好一条后重新登录；或让该用户登录后选择组织（系统会按所选组织重新签发会话，`POST /api/auth/session-org`）；或清除浏览器里记住的组织后重新登录 |
| `YIDA_INITIALIZATION_DENIED` | 登录账号不是锚点里的 owner、会话租户与锚点不符，或不是实时集成管理员 | 停止；核对第 3.2 节的清单与账号，联系开发 |
| `YIDA_INITIALIZATION_UNAVAILABLE` | 锚点未建立，或数据库/权限异常 | 确认第 3.2 节确实打印了 `provisioned`；仍如此联系开发 |
| 显示「本地配置已初始化…」 | 已经被初始化过（不应发生） | 停止，联系开发 |
| 其他提示码（如 `YIDA_INITIALIZATION_RESPONSE_INVALID`、`…_INACTIVE`、`UNAUTHORIZED`） | 见第 5 章 | 停止，按第 5 章处理，不要继续第 4 章 |

### 3.4 发送开关 `INTEGRATION_YIDA_OWNER_SEND_ENABLED`（打开需要批准 ④）

- 后端进程最终看到的值**恰好**是小写的 `true` 才算打开。`TRUE`、`1`、`yes`、未设置，统统算关闭。
- **注意 app.env 的读法**：Windows 部署脚本（`multitable-onprem-apply-package.ps1`、`attendance-onprem-start-pm2.ps1`）读取 app.env 时，会先去掉值的首尾空格和一层引号。所以若客户主机经这两个脚本读 app.env，app.env 里写 ` true `、`"true"` 或 `'true'`，进程看到的都是 `true`，**等于打开**。其他加载方式（例如 pm2-runtime）是否同样处理，待确认（第 8 章）。
- **怎样才算关闭**：在 app.env 里**明确写成** `INTEGRATION_YIDA_OWNER_SEND_ENABLED=false`，按客户主机规定的方式重启后端，再做下面的只读确认。**不要用「删掉这一行」来关闭**：部署脚本只设置文件里出现的变量，不会清除文件里没有的变量；若同一运维窗口或进程管理器此前已带着 `true`，删行后重启，后端仍可能继承 `true`。
- **只读确认服务器报告的开关状态**：由 owner 做一次有效的 v2 创建预演 →「打开本地初始化（不发送）」→「手动 GET 本地初始化状态」。GET **成功**后，面板下方出现「打开单行 CREATE 确认（服务器已开通）」= 服务器报告开关打开；**没有**出现 = 服务器报告关闭。GET 失败（显示错误码）时不能据此判断，先按第 5 章处理再重做。改动开关后的每次重启都要做这一步，并把日期和结论记入内部记录。
- 它是后端进程的环境变量。代码在每个请求时读取它；但运行中的进程无法从外部改环境变量，所以**打开或关闭都要修改部署配置并重启后端进程**。客户主机如何加载环境变量、如何重启，待确认（第 8 章）。
- **关闭时**：保存草稿、读取预览、申请授权、提交都会被拒绝（`YIDA_OWNER_RUNTIME_DISABLED`）。查看已有授权的记录、撤销授权仍可用。本地初始化不受开关影响。
- **打开时**：开关只是前提，不是授权。每个动作仍要检查：是不是登记的 owner、是不是实时集成管理员、单次授权是否有效、是否已用过。
- **关掉开关（重启）对正在进行的发送**：重启时进行中的操作会被中止；**已经发出的请求收不回来**。账本可能停在 `prepared`、`dispatching` 或 `outcome_unknown`。结果未知的永远不会自动重发。请在业务空闲时操作，事后按第 4.6 节逐条核对。

## 4. owner 界面操作

### 4.1 谁能看到入口

- 入口在「备料」工作台的**项目备料页**：先打开一个项目号，在页面的动作区。
- 浏览器只对“平台管理员”显示宜搭入口（拥有 `admin` 角色，或持有 `role:admin`，或持有 `integration:admin`）。其他人看到的是灰色的「推送宜搭(暂未接入)」。
- 浏览器的判断**比服务器宽**：能看到入口不代表能操作。锚点建立后，不是登记 owner 的管理员点「手动 GET 本地初始化状态」会得到 `YIDA_INITIALIZATION_DENIED`；锚点建立**之前**，任何实时集成管理员点 GET 得到的都是 `YIDA_INITIALIZATION_UNAVAILABLE`。初始化面板不会自动请求，这些码只在点「手动 GET」或提交时出现。
- 两个入口按钮：「打开宜搭准备（不发送）」和「宜搭静态预演（不发送）」。两者打开的是同一个面板；第二个按钮再点一次可关闭面板。
- 切换项目号、租户或工作区，或离开项目备料页签，面板会被关闭，面板里的内容全部丢失，进行中的请求会被中止。

### 4.2 本地静态预演（只在浏览器里算，不发送）

面板标题「宜搭静态预演（不发送）」。这里的一切计算只在本页浏览器里进行，不访问服务器，也不访问宜搭。**此面板里不要填凭据。**

1. 如果之前已经归档过规则草稿：粘贴到「粘贴规则草稿 JSON」，点「加载粘贴的规则草稿 JSON」（加载会清空 appType、formUuid、数据和项目列表，需要重新填写）。
2. 「预演合同」选「表单字段目录与协议 v2（仅本地）」。只有 v2 才能走后面的初始化和发送；v1「字段映射 v1（默认）」只能看预演。
3. 填「appType（本地未核验）」和「formUuid（本地未核验）」。前后空格会被去掉，但 128 字符的上限按去空格**之前**的原文计算。
4. 「意图」选「计划创建」。（「计划更新」只能预演，不能初始化或发送。）
5. 在「本地表单字段目录」里，用「添加目录字段」逐个登记表单字段：「字段 ID」、「控件」（文本 / 数字 / 单选 / 单选按钮）、「目录必填」。单选和单选按钮还要在「选项表示」里选「逐行文本（一行一项）」或「JSON 字符串数组（保留选项内换行）」，再在「选项（精确匹配；切换表示后请核对格式）」里填写。逐行模式下**末尾不要留空行**：空行会变成一个空选项，配置不合格。
6. 在「字段映射」里，用「添加映射行」把本地数据字段（source）对应到表单字段（target），选 type（数字控件选 `number`，其他选 `string`；`boolean` 在 v2 里不合格）、勾「必填」、勾「业务键」；需要时勾「允许空键（仅可选字符串业务键）」。**业务键一经初始化就永久固定**（第 4.3 节检查清单第 H 项）。
7. 「项目数量分配（本地候选）」的「模式」：默认「原已整理逐表单（默认）」，表示每行数据就是一条表单。另有「整数精确均分」和「小数精确均分（最多 6 位，不舍入）」，会把一行按「明确项目列表（一行一个完整项目号）」拆成多行。使用均分时：
   - 项目列表 1–20 个，不能有空行、重复或制表符；
   - 「源项目字段」必须是业务键之一，且映射类型为 `string`；业务键至少要有 2 个；
   - 「源数量字段」的映射类型必须是 `number`，且不能与源项目字段相同；
   - 展开后总行数不能超过 100。
8. **先导出，再预演**：点「生成规则草稿 JSON」，把生成的文本连同 appType、formUuid 一起离线归档（保存在 owner 指定的内部位置，不发群、不进 issue/PR）。注意：点这个按钮会清空预演结果、关闭下方已打开的初始化/发送面板；面板被锁住时这个按钮也不可用。所以顺序是先导出、再预演。
9. 在「本地 rows JSON（最大 128 KiB / 100 行）」粘贴数据。每一行的**每一个键**都要符合第 2.2 节的标识符规则（包括没有映射的多余列），否则整份数据被拒绝。
10. 点「只在本地预演」，看结果：「共 N 行；计划创建 N；计划更新 0；无效 0；本地重复键 0。」每行会显示「计划创建」或「无效」及原因。

**只有当**：合同是 v2、意图是创建、每一行都是「计划创建」、没有无效行、没有重复业务键、并且（使用均分时）分配分析没有任何问题时，面板下方才会出现「打开本地初始化（不发送）」。

**千万注意**：面板上有「填入合成样例 A（创建）」「填入合成样例 B（另一布局）」「填入七项身份合成样例 A」「填入七项身份合成样例 B（另一布局）」按钮，它们填入的是假目标。**不要**用样例数据去做初始化——初始化是永久的，会把唯一目标槽位永远绑在假表单上。

「复用本地规则草稿」区导出的规则草稿不含目标、项目清单、数据。导出的文本可能含业务配置，请妥善保存。

任何编辑都会清空预演结果，并关闭下面已打开的初始化/发送面板。

#### 4.2.1 v2 配置结构（界面会替你生成；导入规则草稿或排查时参考）

| 字段 | 规则 |
|---|---|
| `version` | 固定 `2` |
| `kind` | 固定 `"yida-form-protocol-static"` |
| `target` | `{ "appType": …, "formUuid": … }`，各为非空、最长 128 字符（按去空格前的原文计）、无控制字符（前后空格会被去掉） |
| `intent` | `"create"`（初始化与发送只接受 create） |
| `businessKey` | 1–8 个不重复的 source 字段名，每个都必须出现在 `fieldMap` 的 source 里 |
| `emptyKeyFields` | 0–8 个；**即使为空也必须写成 `[]`**；必须是业务键之一，且对应映射为非必填的 string、对应目录字段也非必填。含义：该业务键缺失、null、空字符串视为同一身份 |
| `fieldCatalog` | 1–32 项，每项 `{ "id", "control", "required" }`，`control` 为 `text` / `number` / `select` / `radio`；`select`、`radio` 必须再有 `options`（1–64 个不重复、非空白、最长 128 字符的字符串），其他控件不能有 `options`；`id` 不能重复 |
| `fieldMap` | 1–32 项，每项 `{ "source", "target", "type", "required" }`；source 不重复，target 不重复且必须在目录里；`number` 控件对应 `type: "number"`，其他控件对应 `type: "string"`；目录里必填的字段，必须有一条“必填”的映射 |
| `instanceIdField` | 只用于 update；create 时不能出现 |

数据（rows JSON）：一个数组，最多 100 行、总共不超过 128 KiB；每行最多 64 个键；值只能是 null、布尔、有限数字、或最长 4096 字符的字符串。以下任何一种情况都会让**整份数据**被拒绝（不只是那一行）：某个键不符合标识符规则、同一行里有重复键、某行超过 64 个键、某个字符串超过 4096 字符、数字是 -0、整数超出安全范围。缺失或空白的“必填”字段会让该行无效；非必填字段为空时直接不发送该字段（不会把远端清空）。

最小的假示例（所有值都是虚构的占位）：

```json
{
  "version": 2,
  "kind": "yida-form-protocol-static",
  "target": { "appType": "FAKE_APP_TYPE", "formUuid": "FAKE_FORM_UUID" },
  "intent": "create",
  "businessKey": ["projectNo", "partCode"],
  "emptyKeyFields": [],
  "fieldCatalog": [
    { "id": "field_project", "control": "text", "required": true },
    { "id": "field_part", "control": "text", "required": true },
    { "id": "field_qty", "control": "number", "required": true },
    { "id": "field_priority", "control": "select", "required": false, "options": ["normal", "rush"] }
  ],
  "fieldMap": [
    { "source": "projectNo", "target": "field_project", "type": "string", "required": true },
    { "source": "partCode", "target": "field_part", "type": "string", "required": true },
    { "source": "qty", "target": "field_qty", "type": "number", "required": true },
    { "source": "priority", "target": "field_priority", "type": "string", "required": false }
  ]
}
```

对应的数据：

```json
[{ "projectNo": "DEMO-P1", "partCode": "DEMO-PART-A", "qty": 2, "priority": "normal" }]
```

规则草稿 JSON 的外壳是：`{ "formatVersion": 1, "kind": "stock-preparation-yida-rule-template", "status": "local-unverified", "rules": { …上面的配置去掉 target… }, "allocation": { "mode": "original" } }`。分配模式非 original 时，`allocation` 为 `{ "mode", "projectField", "quantityField" }`（不含项目清单）。

### 4.4 本地初始化（录入真实凭据，不发送；需要批准 ③）

在 HTTPS 站点上，或在服务器本机通过 localhost 操作（第 4.3 节 C 项）。操作期间不要切换项目号、租户/工作区，也不要离开项目备料页签。

1. 点「打开本地初始化（不发送）」，出现面板「宜搭本地初始化（不发送）」。
2. 点「手动 GET 本地初始化状态」。正常会显示「初始化命令：…」和「已确认本地空槽；仍须填写材料并人工确认，才能手动初始化。」看到其他内容就停止，按第 5 章处理。
3. 在「临时材料（不进入预演或导出）」中填 `appKey`、`appSecret`、`systemToken`、`userId`（输入框以密码形式显示）。
   - **粘贴会保留剪贴板里的完整原字符串，不去空格、不截断**；输入框可能看不出换行。服务器只检查“去掉空白后不为空”和长度，同样不去空格。多出来的空格或换行会**永久**保存，以后无法更换：
     - `appKey` / `appSecret` 带空白：换取令牌时很可能失败，该行停在 `prepared`，业务键被永久占用；
     - `systemToken` 带空白：请求会发到宜搭，很可能被拒，记为 `outcome_unknown`。
4. 填「人工审核编号」和「人工确认 organizationId」：各 1–128 字符，不能有首尾空白或控制字符。
5. 勾选「我已人工审核目标与执行身份，确认永久单槽仅归服务器指定 owner；此操作不发送。」
6. 点「仅初始化本地材料、草稿和人工目标」。点下后，材料输入框立即清空。

**成功时**显示：「本地配置已初始化；canSend=false，tokenIssued=false，externalWriteAttempted=false。没有 grant 或发送许可。」以及「本地草稿：…；目标：…；N 行（仍未核验远端）。」还有一个「受权草稿行」下拉框——在这里选择行**不会**请求、预演、批准或发送任何东西。注意：成功后界面只显示目标引用和草稿编号，**不再显示 appType、formUuid**，所以第 4.3 节 G 项的归档是必须的。

**如果显示**「状态未确认，禁止重做或换命令；仅可手动 GET 确认真实提交或回滚结果。」：不要重填重交。只点「手动 GET 本地初始化状态」查看真实结果：

- 若显示已初始化：就是成功了。
- 若仍显示「已确认本地空槽」：说明这次没有写入。常见原因是浏览器端检查不合格（错误码 `YIDA_INITIALIZATION_INPUT_INVALID`，例如人工审核编号或 organizationId 带了首尾空格）。此时材料输入框已被清空，改正后**重新录入全部四项材料**再提交。

初始化成功后，再次提交初始化会得到 `YIDA_INITIALIZATION_CONFLICT`，这是正常的。

### 4.5 单行创建（需要批准 ④ 开关已打开、批准 ⑤ 第一次真实发送）

- 只有在服务器开关为 `true` 时，点「手动 GET 本地初始化状态」后，面板下方才会出现「打开单行 CREATE 确认（服务器已开通）」。开关关闭时这个按钮不出现。
- 请先完成初始化再进行这一步；未初始化时保存草稿会被拒绝（`YIDA_SEND_APPROVAL_NOT_FOUND`）。
- 取得批准 ⑥ 后，以后每次要发送时，路径都是：在预演面板**先**粘贴并加载归档的规则草稿（加载会清空 appType、formUuid、数据和项目列表），**再**按归档原样填回 appType、formUuid，然后粘贴本次数据（使用均分时还要重新填写项目列表），做一次有效的 v2 创建预演 →「打开本地初始化（不发送）」→「手动 GET 本地初始化状态」（会显示已初始化）→「打开单行 CREATE 确认（服务器已开通）」。appType、formUuid 和业务键定义（业务键对应的表单字段、类型、「允许空键」勾选）必须与初始化时**完全相同**，否则保存草稿会报 `YIDA_SEND_APPROVAL_UNAVAILABLE`。
- **一个面板只处理一行**：一次保存草稿、一行授权、一次提交。点了「确认并申请单次授权」之后，上方的预演编辑区和初始化入口都会被锁住。要发下一行，先把本页状态记录下来，再关闭预演面板（授权显示会丢失），从头开始。结果未知（第 4.6 节）时不要关闭面板，先按该节处理。

打开后是「宜搭 Owner 单次创建确认」面板：

1. 点「保存服务端草稿（不发送）」。服务器重新编译你的数据，返回服务器端的行清单（与以前相同的数据会显示「（复用既有草稿）」）。
2. 在「选择服务端行」里选一行，点「读取所选行服务端预览」。
3. 核对「确认此服务端目标与此行内容」：目标引用、确认依据、组织、appType、formUuid，以及要发送的字段内容。
4. 勾选「我已核对目标与此行内容，知悉只尝试一次及结果未知不可重试的风险。」
5. 点「确认并申请单次授权（尚未发送）」。服务器生成授权：只能尝试 1 次，有效期 15 分钟（这是上限，界面固定申请 15 分钟）。显示「授权 …；状态 approved；到期 …」「授权记录的剩余尝试数为 1」。
   - 第一次点击后，按钮文字就会变成「恢复同一确认结果（不新增授权）」（不论网络是否正常）；再点只会取回同一个授权，不会新增。
   - 注意：授权成功**不代表**这一行能发。业务键是否已被占用、授权是否过期，只在提交时才检查。
6. 授权后**尽快**点「提交此授权一次」；剩余时间不足 2 分钟时不要提交，改为关闭面板、重新申请授权。原因：服务器在准入之后、真正发送之前还会再检查一次是否到期——若恰好在这之间到期，这一行会停在 `prepared`（什么都没发出，但业务键已永久占用），或在领取后记为 `outcome_unknown`（同样可能什么都没发出）。
   - **提交后不要关闭面板、不要刷新页面、不要切换登录账号、不要切换项目号或租户/工作区、不要离开项目备料页签**，等结果返回（浏览器最多等 15 秒）。这些操作都会关闭面板并中断请求，可能让这一行停在不确定状态（这正是第 0.2 节条件 1 尚未解决的问题）。
   - 页面提交过一次后就会冻结：「此页面已经提交过一次命令，已冻结再次创建。」
7. 用「手动刷新持久记录（只读）」查看账本状态，按第 4.6 节处理。需要时可「撤销此授权」；撤销只阻止尚未准入的提交，**不能**撤回已经发出的请求。

**重要**：授权编号只保存在当前页面里。刷新页面、关闭面板、或会话变化后，界面上**找不到**这个授权了，也就无法再查看它的状态（第 0.2 节条件 2）。请在提交前后把页面上的状态如实记录在内部记录里（不要截屏发群）。

### 4.6 结果状态及处理

页面显示「持久记录状态：…」。

| 状态 | 含义 | owner 要做什么 |
|---|---|---|
| `acknowledged` | 宜搭返回了 2xx 应答，并且应答里带回了一个格式合格的记录标识。界面提示「仅收到协议应答，尚未核验业务创建成功」。代码不看应答里的其他内容（例如是否声明了业务失败）。 | 到宜搭测试表单里人工核对这条记录（第 4.7 节） |
| `outcome_unknown` | 已开始发送，但结果不确定：网络超时或中断、**宜搭返回 4xx/5xx**、2xx 但应答不合格、写库失败、或领取后被中止（含领取后授权到期；这种情况下请求可能根本没有发出）。 | **绝不重发。**到宜搭里人工查是否已有这条记录，把结论记录下来，联系开发 |
| `dispatching` | 已领取发送权，正在发送；若长时间停留，说明进程在发送中途被中断。 | 不重发；稍后刷新；若一直不变，按 `outcome_unknown` 处理 |
| `prepared` | 已准入，但还没领取发送（例如换取令牌失败、`appKey`/`appSecret` 错误或带空白、提交前被取消、**准入后授权恰好到期（临近到期才提交）**）。授权已用掉。 | 当前**没有**界面内的处理方式；该业务键已被永久占用。联系开发，**不要手工改库** |
| `state_unconfirmed` | 连“结果未知”都没能写进数据库 | 按 `outcome_unknown` 处理，联系开发 |
| `not_started` | 当前界面路径下不会出现 | 若看到，截图状态文字（不含 ID）并联系开发 |
| `not_sent` | 数据库允许此状态，但当前版本没有任何代码路径会产生它 | 若出现，联系开发 |
| 刷新**失败**（页面显示错误码），或提交时没有收到明确结果，之后仍没有「持久记录状态」这一行 | **结果未知**：提交可能已被准入、请求可能已经发出，只是页面没拿到结果 | 按 `outcome_unknown` 处理：**不要关闭预演面板**（授权编号只在本页显示，关闭即丢失），先把页面上的授权编号、状态和到期时间记入内部记录（不贴进聊天）；**不要重新提交，也不要为这一行申请新授权**；稍后再点「手动刷新持久记录（只读）」；仍无法确认时到宜搭人工核对（4.7）并联系开发 |
| 刷新**成功**（没有错误码，页面已更新授权状态），且提交时服务器明确返回了拒绝码，仍没有「持久记录状态」这一行 | 这次提交没有被准入。常见原因：授权已过期或已撤销、该行业务键早已被占用、凭据已被撤销 | 记录页面状态后，可以关闭预演面板、重新预演并申请新授权。若第二次仍没有记录行，停止，联系开发（多半是业务键已被占用）。只要对「刷新是否成功」有任何疑问，就按上一行（结果未知）处理 |

### 4.7 在宜搭里核对

`acknowledged` 只代表“协议层收到了应答”，不代表业务一定写对了；填错字段 ID 等错误，若宜搭仍返回 2xx，也会显示为 `acknowledged`。MetaSheet 当前**不会**自动回读宜搭核对。请宜搭管理员和 owner 在测试表单里人工核对：记录是否存在、各字段值是否与预览一致、是否只有一条。界面不显示宜搭返回的实例 ID（是否允许 DBA 只读查询协助核对，见第 8 章）。

## 5. 异常处理

### 5.1 服务器返回的错误码

| 错误码（原文） | HTTP | 含义 | 怎么办 |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | 没登录或登录已失效 | 重新登录后重开面板 |
| `YIDA_OWNER_HTTP_DENIED` | 403 | 当前登录会话里没有租户。规则：登录时没有显式选择组织的，只有当该用户**恰好一条**有效组织成员关系时，会话才带租户；否则所有宜搭请求都是这个码 | 调整成员关系（第 4.3 节 D 项）后重新登录；仍如此联系开发（第 0.2 节条件 9） |
| `YIDA_OWNER_HTTP_INPUT` | 400 / 413 / 415 | 请求格式不对：URL 带了查询参数、请求带了租户/用户类请求头（如 `x-tenant-id`、`x-user-id`）、不是 JSON、请求体过大、**初始化请求体的格式或字段不合格**（这类问题多数显示为这个码，而不是 `YIDA_INITIALIZATION_INPUT`） | 不要通过代理或插件给这条路径加作用域请求头；检查反向代理配置；初始化时检查材料与审核信息 |
| `YIDA_OWNER_HTTP_UNAVAILABLE` | 503 | 服务不可用或返回数据异常 | 稍后重试只读操作；持续出现联系开发 |
| `YIDA_OWNER_RUNTIME_DISABLED` | 403 | 发送开关关闭 | 正常现象；面板显示「服务端发送开关关闭…」。只能查看或撤销已有授权 |
| `YIDA_OWNER_RUNTIME_INACTIVE` / `YIDA_INITIALIZATION_INACTIVE` | 503 | 集成插件未激活，或后端正在停止 | 等待后端完全启动；持续出现联系运维 |
| `YIDA_OWNER_RUNTIME_UNAVAILABLE` | 503 | 在「提交此授权一次」上，**几乎所有拒绝都显示成这个码**：授权已过期、授权已撤销、不是登记 owner 或不是实时集成管理员、同一授权用另一个提交号再提交、该行业务键已被占用、凭据已被撤销或轮换、换取令牌失败。其他操作上的服务端执行失败也是这个码 | 若发生在提交之后：**不要再提交**，先「手动刷新持久记录（只读）」，按第 4.6 节处理（包括“没有记录行”的情况） |
| `YIDA_OWNER_RUNTIME_CANCELLED` / `YIDA_SEND_APPROVAL_CANCELLED` | 409 | 请求在服务端被中止（例如连接断开） | 不重发；刷新持久记录 |
| `YIDA_OWNER_RUNTIME_INPUT` / `YIDA_SEND_APPROVAL_INPUT` | 400 | 请求内容不合格 | 关闭面板重新开始；持续出现联系开发 |
| `YIDA_SEND_APPROVAL_NOT_FOUND` | 404 | 保存草稿、预览、申请授权、刷新、撤销时：尚未初始化；或你不是登记的 owner（或租户不符）；或授权不存在。**在「提交」上，同样的情况显示为 `YIDA_OWNER_RUNTIME_UNAVAILABLE`** | 先完成初始化；确认用 owner 账号登录 |
| `YIDA_SEND_APPROVAL_CONFLICT` | 409 | 只在两种少见情况下出现：同一确认号参数不同（界面不会这样做）；刷新记录时账本与授权对不上（通常只有数据库被手改过才会）。“同一授权另一个提交号”“业务键已占用”在提交时显示为 `YIDA_OWNER_RUNTIME_UNAVAILABLE` | **不要换个方式再发**。记录状态，联系开发 |
| `YIDA_SEND_APPROVAL_UNAVAILABLE` | 503 | 服务端不可用。注意：**很多不同原因都会显示成这个码**，包括：你不是实时集成管理员、新草稿的目标或业务键定义与初始化时不一致、草稿内容不合格等 | 先核对账号权限，以及 appType、formUuid、业务键定义是否与归档一致；仍不明联系开发 |
| `YIDA_SEND_APPROVAL_EXPIRED` / `YIDA_SEND_APPROVAL_REVOKED` | 409 | 服务器的错误码表里有，但在当前界面的操作路径上，服务器**不会**返回：过期、撤销只在提交时检查，显示为 `YIDA_OWNER_RUNTIME_UNAVAILABLE`；重复点撤销返回成功。浏览器自己产生的 `YIDA_SEND_APPROVAL_EXPIRED` 见第 5.2 节 | — |
| `YIDA_INITIALIZATION_DENIED` | 403 | 你不是实时集成管理员；或锚点已建立且你不是登记的 owner、会话租户与锚点不符。只在点「手动 GET」或提交初始化时出现 | 用登记的 owner 账号；检查其角色/成员关系；初始化面板会被清空并停用，需重新预演后再打开（或关闭预演面板后重开） |
| `YIDA_INITIALIZATION_UNAVAILABLE` | 503 | 运维还没登记 owner 锚点（最常见；此时任何实时集成管理员都得到这个码，而不是 DENIED）；或数据库/锁/权限异常；或初始化内容在服务器端未通过校验；或凭据被手工撤销/轮换过（永久，无法恢复） | 先确认第 3.2 节已打印 `provisioned`；成功 GET 一次或关闭预演面板即可解锁；仍如此联系开发 |
| `YIDA_INITIALIZATION_CONFLICT` | 409 | 已经初始化过；或初始化命令号与服务器的不一致 | 已初始化时属正常，点「手动 GET 本地初始化状态」查看 |
| `YIDA_INITIALIZATION_INPUT` | 400 | 初始化请求内容不合格（少见，多数格式问题显示为 `YIDA_OWNER_HTTP_INPUT`） | 检查材料与审核信息；先 GET 确认，再重新录入 |
| `YIDA_INITIALIZATION_CANCELLED` | 409 | 请求被中止。浏览器自己等满 15 秒超时也显示这个码 | 只点「手动 GET 本地初始化状态」确认真实结果 |
| `NOT_FOUND` | 404 | 路径不存在 | 联系开发 |

### 5.2 浏览器端产生的提示码

| 提示码 | 含义 | 怎么办 |
|---|---|---|
| `YIDA_INITIALIZATION_SESSION_CHANGED` / `YIDA_OWNER_SESSION_CHANGED` | 登录状态、租户或工作区在别的标签页变化了，面板已自动清空（含已填材料、授权显示） | 确认用 owner 账号登录，重新预演后再打开面板（或关闭预演面板后重开）。若之前已提交过发送，**不要重发** |
| `YIDA_INITIALIZATION_STATE_UNCONFIRMED` | 上一次请求结果还没确认 | 只点「手动 GET 本地初始化状态」 |
| `YIDA_INITIALIZATION_RESPONSE_INVALID` / `YIDA_OWNER_RESPONSE_INVALID` | 服务器应答格式异常。**也包括账号被要求先改密码的情况**（服务器返回 `PASSWORD_CHANGE_REQUIRED`，浏览器不认识这个码，显示为此码） | 不要重提交；先确认账号无需改密码；刷新/回读确认；联系开发 |
| `YIDA_INITIALIZATION_INPUT_INVALID` / `YIDA_OWNER_INPUT_INVALID` | 浏览器端检查发现输入不合格（例如人工审核编号或 organizationId 带首尾空白、超过 128 字符） | 初始化时：材料已被清空、面板显示“状态未确认”。先点「手动 GET 本地初始化状态」，改正后重新录入全部四项材料（第 4.4 节） |

| `YIDA_OWNER_CANCELLED` | 浏览器等待超过 15 秒或请求被中断 | 若发生在提交后：**不重发**，刷新持久记录 |
| `YIDA_OWNER_UNAVAILABLE` / `YIDA_INITIALIZATION_UNAVAILABLE`（网络层） | 浏览器连不上服务器 | 检查网络；提交后出现时按“结果未知”处理 |

### 5.3 几种特别情况

- **结果未知（`outcome_unknown`）**：永远不要重发同一行，也不要改业务键“换个名字再发”——那可能在宜搭里造出重复记录。到宜搭里人工核对，记录结论，联系开发。
- **业务键被永久占用**：一行一旦被准入（无论最后是成功、未知还是卡在 `prepared`），同一目标上的同一业务键就**再也不能**通过本功能创建。当前界面里没有释放办法。请联系开发。
- **不要手工改数据库**：部分手工改动会被触发器拒绝；另一些是数据库允许的，但一旦做了就**不可逆**：
  - 推进账本状态（例如把 `prepared` 改成 `not_sent`）：不会释放业务键占用，还会破坏审计；
  - 轮换或撤销凭据表里的材料：之后初始化状态的读取永远返回 `YIDA_INITIALIZATION_UNAVAILABLE`，本功能永久不可用。
- **凭据填错或钉钉密钥被重置**：当前没有界面内的更换或重新登记途径（第 0.2 节条件 3）。
  - `appKey` / `appSecret` 错误：提交时在换取令牌一步失败，提交显示 `YIDA_OWNER_RUNTIME_UNAVAILABLE`，留下 `prepared` 记录；
  - `systemToken`、`userId`、appType、formUuid 或字段 ID 错误：请求会发到宜搭。宜搭返回非 2xx 时记为 `outcome_unknown`；若宜搭仍返回 2xx，会记为 `acknowledged`，但业务上可能不对（第 4.7 节）。
  - 以上都请联系开发。
- **关闭发送开关**：见第 3.4 节。已发出的请求收不回；重启后逐条核对。

## 6. 安全须知

1. **凭据**：`appKey`、`appSecret`、`systemToken` 只在初始化面板里录入；不进聊天、邮件、工单、PR、截图、日志。界面不把材料存进浏览器，服务器端加密保存，任何接口都不会回显材料。
2. **明文 HTTP 风险**：如果客户内网是按 IP 访问的普通 HTTP，录入的材料会以明文经过网络。录入前请确认站点已启用 HTTPS；否则请在服务器本机通过 localhost，或通过远程桌面在服务器上操作（第 0.2 节条件 5）。
3. **`NODE_ENV` 与 `ENCRYPTION_KEY` / `ENCRYPTION_SALT`**：宜搭材料、草稿、目标和授权快照都用平台密钥加密，而且这些记录不可修改。
   - 平台**只有在 `NODE_ENV=production` 时**才会拒绝未配置或默认的密钥；其他情况下，它会**只在日志里警告一次、不阻止启动地**使用公开仓库里的默认密钥，等于没有加密。
   - 如果先初始化、后来才配置真实密钥或更换密钥，已存的密文将**永远无法解密**，界面里也无法重新加密或重新登记。
   - 所以初始化前必须确认 `NODE_ENV=production` 且两项密钥为最终值（第 4.3 节 B 项）；没有经过评审的轮换方案前，不要更换（第 0.2 节条件 7）。
4. **K3 永久禁止写回**：本功能只向宜搭测试表单创建记录，与 K3 无关；K3 的保存、提交、审核写回在任何情况下都不允许。
5. **最小权限**：只给登记 owner 本人集成管理员权限；不要为了“方便”给更多人；不要为绕过错误去改角色、改 SQL 或打开开关。

## 7. 已知限制

- 一个部署只有**一个** owner、**一个**目标表单、**一套**业务键定义、**一份**凭据，全部永久；界面不能转移、更换或清空。
- 只支持**手动、单行、创建**。没有更新、批量、定时、自动化触发，也没有自动重试。一个面板只能授权并提交一行。
- 每个授权只能尝试一次，最长 15 分钟。
- `acknowledged` 只是协议应答，不是业务核验；没有自动回读对账。
- 没有凭据更换、重新登记的界面途径；材料前后的空白无法事后去掉。
- `prepared` / 结果未知的记录没有界面内处理途径；被占用的业务键无法释放。
- 刷新页面后找不回授权和发送状态（没有列表页）。
- 初始化后界面不再显示 appType、formUuid；每次发送都要按归档原样重新填写。
- 很多不同原因会显示成同一个 `…_UNAVAILABLE` 错误码（提交时尤其如此）。
- 宜搭入口对所有平台管理员可见，比服务器的实际许可宽。
- 字段只支持文本、数字、单选、单选按钮；值只能是文本或数字；字段 ID 含某些片段时无法映射。
- 数据需要手工粘贴 JSON，不会自动从备料看板取数；一次草稿最多 100 行。
- 发送开关的开关都需要重启后端。
- 后端出网不经代理。
