# 安装包升级时保留旧前端资源

本补丁用于 Windows 本地安装包发布：常规 `attendance-onprem-publish-web-dist.ps1` 和多维表原地升级。共享安装包中的 Bash 发布器采用相同保留规则。它不改变权限判断，也不打开 `DELEGATED_SCOPE_EXACT_DEPARTMENT_ENABLED`。

## 发布行为

旧标签页已经加载的 JavaScript 会继续引用旧版本的哈希资源。替换整份 dist 会让尚未加载的页面失效，因此发布时将旧 `assets/` 中的普通文件保留到新 dist。新的 `index.html`、`build-info.json` 及其他根目录文件始终来自新安装包。

同一相对资源路径如果内容不同，发布应失败，不能静默覆盖。路径重叠、符号链接或目录联接也应在替换现有目录前拒绝。正常发布不修改原安装包；原地升级只在解包后的暂存目录中合并资源，随后沿用原有备份、替换记录和失败恢复流程。

发布脚本需要可用的 Node.js。请使用带有 `scripts/ops/web-dist-retain-assets.mjs` 的完整安装包，不要只复制一个更新后的 PowerShell 文件。

## 保留与回滚

资源没有自动清理期限。连续升级会累积旧资源；仅凭文件年龄或保留最近两个版本，无法判断是否还有标签页在使用它们。清理需要另行安排维护窗口，确认客户端已重新加载，并保留必要的回滚包。

保留旧 JavaScript 不会延长服务端授权有效期，也不能保证新旧 API 永远兼容。后端权限验收和数据库迁移仍按原发布流程执行。

现有目录替换和原地升级维护窗口仍然存在，本补丁不提供零停机承诺。新的原地升级器会拒绝不包含 helper 的旧包，并沿用“尚未替换运行目录”的恢复分支。常规发布器可保留资源并发布旧版本 dist；既有整目录备份恢复操作和旧发布脚本不能保证保留当前标签页的资源。

## 验收边界

回归覆盖新装、连续升级、回滚复用、当前入口文件不变、二进制资源字节一致，以及冲突和不安全路径在现有目录变更前失败。正式旧/新前端构建还需经过实际发布脚本和 HTTP 服务验证：旧标签页在发布后首次请求懒加载资源成功，新会话获得新入口。

直接在 nginx 正在服务的 dist 中运行 `vite build` 会在发布器执行前删除旧文件，不属于这里的安装包发布流程。Docker 镜像替换也不在本补丁范围内。
