# 独立委派启停

状态按成员和命名空间保存。平台管理员仍能保存未启用成员的部门和成员组，范围为空时启用接口返回 409。停用只收回委派管理权。既有角色、插件准入以及角色授予的业务权限仍由各自的入口计算。没有状态行的既有管理员沿用角色与范围所决定的行为。

- 管理范围页从服务端读取状态和版本。启停写入校验当前操作者、目标账户、持有的命名空间角色和请求版本。启用需要有效部门或已选成员组。成员组的实际成员由授权判断实时求值。
- 配置、启停和角色任命共享目标成员的准入锁。停用成员不能用旧 JWT 操作通用委派、授权命令或备料成员管理。授权命令的预览会绑定状态版本，回执查询和重试会检查当前委派权限。
- 撤掉命名空间的最后一个管理员角色会清除该命名空间的范围，已使用启停的成员会进入新的停用状态。重授后重新保存范围，再明确启用。保留其他命名空间、其他同命名空间角色以及未改变的授权来源。
- 启停及审计在同一个事务。范围写入和模板不会隐式启用委派。提交结果不可核实时，页面保留只读重读入口。

## 升级与恢复

`DELEGATED_SCOPE_ACTIVATION_ENABLED` 默认关闭。只允许在旧权限读写进程全部退出后启用。部署时使用维护窗口完成正式迁移和进程切换。授权操作依赖封闭的目录指纹，迁移后旧程序的授权操作接口会拒绝未知结构。已停用状态即使在开关关闭后仍由新版读写入口执行。旧进程不认识这项状态，保存过启停数据后，数据库迁移会拒绝有损回退。

`DELEGATED_SCOPE_EXACT_DEPARTMENT_ENABLED` 是独立的范围开关，继续关闭。原有 Windows 安装包保留已有验收，新增迁移和功能需要使用新候选做独立验收。
