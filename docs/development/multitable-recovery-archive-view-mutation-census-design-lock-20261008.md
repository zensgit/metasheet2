# Bounded view mutation companion

This source-only guard complements D2e/D-H1 and the field-retype ADR §3.11 holder census. It starts from mutation candidates, independently of fence discovery. Its declared input is every non-test TypeScript source returned by `loadCensusSources` under core-backend/src. Its target is meta_views row INSERT/UPDATE/DELETE, including the finite applyConfigRevert table selector and Kysely row builders. Schema DDL and physical attachment deletion remain outside this bounded target.

The collector reports call-site candidates, not a proof of query API identity or runtime admission. It accepts literal SQL (including CTE mutations and multiple statements, masking SQL values/comments while retaining quoted identifiers), literal templates with value interpolation, lexical constant SQL, query-config text, quoted/case-insensitive/public/ONLY table forms, and finite literal conditional table selectors. Known console/logger calls and unattached strings/comments do not become SQL calls. An otherwise ambiguous call carrying covered SQL remains a candidate requiring an explicit ambiguous disposition. Unsupported dollar-body function effects, SQL passed beyond first argument, tagged raw SQL, namespace/re-export/destructured aliases, mutable or computed SQL, reflection, runtime-generated tables and plugin code outside the input tree remain open; this is not a general SQL or call-graph verifier.

Every exact call expression (receiver and argument expressions included) and occurrence count needs a curated disposition: direct caller admission, inherited admission at each enumerated caller edge, new-sheet creation, migration, or unresolved query identity. Named mutator calls (relative named imports/lexically scoped local aliases and ambiguous property-name candidates) and named callback handoffs are enumerated recursively to leaf calls; literal .transaction callbacks seed their named enclosing helper, while anonymous route registration handlers stop propagation; ambiguous property identity is explicitly retained. A new caller, new candidate, repeated same candidate, removed site, or stale ledger must fail. Dispositions are source-review evidence, not an automated proof that a fence precedes a write on the same transaction/sheet. The existing holder guard remains unchanged and independently required.

Success requires the whole companion spec, the field-schema neighbor, actual matching omission/admission mutations failing and restored bytes passing, and verified default Vitest whole-file collection in the existing backend CI test command. Root verifies CI collection; actual new-SHA CI remains unexecuted. Production writer-set/owner/deployed-state closure, other archived projections, SQL function effects, native entry-family blocked/unblocked races and physical deleters remain OPEN. No runtime code, routes, flags, schema, admission policy or activation changes belong to this slice.

At the fresh-main baseline the curated inventory is 13 mutation shapes / 14 occurrences and 20 caller or callback-handoff sites. The two identical form-share/token-regeneration statements retain an exact count of two. Admission wording in ledger reasons is a source-review disposition; the collector neither certifies query APIs nor verifies dominance, aliasing of transaction/sheet identities, or current runtime flags.

The source baseline for this companion is fresh main `afd32b704c6ff4c82dbfe90b94066fcaf3fc0074`. Collection is checked against that tree; this does not claim Node 20 CI execution or complete D-H1 writer closure.
