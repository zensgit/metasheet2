# 云课堂（学习中心）启用手册 — 无视频试点版（适用于 onprem-r65 在线包）

> 状态（2026-10-12）：草案，**未获 owner 批准执行**。在演示机上开开关、安装 / 启用应用、分配角色，每次都由 owner 决定。本手册对应的演练记录：[elearning-no-video-rehearsal-report-20261012.md](elearning-no-video-rehearsal-report-20261012.md)。

本手册来自 2026-10-12 在本地用同一 commit（`6d4e9fc38`）按生产模式做的完整演练。
文中不写任何主机地址、口令或路径值，只写「在哪里改」和「改成什么」。

## 0. 先读两条

- 本版本**不开视频**，所以学员**参加不了正式考试**。能用的只有图文/外链课程、指派与自学、刷题练习、人工积分和证书。演示前先跟客户对齐这一点。
- 只有 owner 批准后才执行。每一步都可以回退，回退方法见第 7 节。

## 1. 只读预检（不改任何东西）

1. 确认后端当前版本是 r65 包，`/health` 返回 200。
2. 用平台管理员登录，打开顶部「插件」页（/admin/plugins），找到 `plugin-elearning`。
   - 开关还没开时它显示 `inactive`，这是正常的，**不要点任何按钮**。在开关关闭时点「启用」，接口会返回成功，但插件仍是 inactive，页面不提示（已知怪癖）。
   - 记下当前状态。如果以前有人点过「停用」，这个状态会跨重启保留，开开关后插件也不会生效。处理办法见第 4 步。
3. 打开「用户管理」，确认要参加试点的教师和学员账号**都有组织归属**（新建用户时「所属组织」选了 default）。没有组织的账号用云课堂时会一律收到 `ORG_CONTEXT_REQUIRED`，而且本版本没有事后补组织的界面。新建试点账号时务必选「所属组织」。

## 2. 在 app.env 里加开关

在部署目录的 `docker/app.env` **末尾**加下面 7 行。值必须是小写 `true`，原样照抄：

```
ELEARNING_ENABLED=true
ELEARNING_CONTENT_ENABLED=true
ELEARNING_ASSIGNMENT_ENABLED=true
ELEARNING_ASSESSMENT_ENABLED=true
ELEARNING_ENROLLMENT_ENABLED=true
ELEARNING_ANALYTICS_ENABLED=true
ELEARNING_INCENTIVE_ENABLED=true
```

**不要加**以下三项，见第 8 节：`ELEARNING_MEDIA_ENABLED`、`ELEARNING_WATCH_CHALLENGE_ENABLED`、`ELEARNING_NOTIFICATIONS_ENABLED`。不需要配置任何对象存储或钉钉参数。

## 3. 重启后端

按现有方式重启后端（演示机由 pm2-runtime 托管，沿用平时的重启命令，并让它重新读取 app.env）。本地演练从重启到开始监听用了 3–6 秒。

查看后端日志，**应该看到**：

```
Plugin loaded: plugin-elearning v0.1.0
Plugin route registered: plugin-elearning GET /api/elearning/capabilities
Loaded 15 event types            （开关关闭时这里是 0）
```

没有专门的「云课堂已启用」日志行，以第二行为准。日志里**不应该**出现存储探针或 S3 相关内容，进程也不应反复重启。`/health` 返回 200。

## 4. 平台管理员安装并启用应用

1. 刷新「插件」页，`plugin-elearning` 应显示 `active`。
   - 如果显示 `inactive`，而第 3 步的第二行日志也没出现，说明之前有人点过「停用」。这时点一次「启用」，状态应变为 `active`。本地演练里，这样操作后立即恢复，不用再重启。
2. 顶部「应用」→ 卡片「学习中心」→「Open shell」。
3. 页面里有一个英文区块「Cloud classroom installation」：
   - 点 `Install`，状态变为 `inactive`（正常现象，安装后默认是停用的）。
   - 点 `Enable`，状态变为 `active`。
   - **不要勾选** `Opt in to learning notifications`。
4. 到这一步为止，只有管理员能看到「学习中心」卡片。学员要等第 5 步做完才看得到。

## 5. 给人员分配角色（每个人两步，缺一步都不生效）

在「用户管理」里选中要操作的用户：

| 用途 | 角色 | 能做什么 |
| --- | --- | --- |
| 学员 | `plugin_elearning_viewer` | 学习、报名、练习、查看积分和证书 |
| 建课教师 | `plugin_elearning_admin` | 建课、建题库、指派、积分规则、证书、分析。**注意**：这个角色同时也能在 /apps/elearning 停用整个应用，本版本没有「只建课」的角色 |
| 助教 | `plugin_elearning_operator` | 能指派课程、设置可见范围、查看统计，**不能建课** |

1. 在「角色」里选择上表中的角色，点分配。
2. **必须再做这一步**：在「插件使用」区块找到 `elearning`，点「开通插件使用」，直到三个标签都是绿色（已分配角色 / 插件使用已开通 / 当前实际可用）。
   只分配角色而不开通，用户拿不到任何云课堂权限。
3. 让用户重新登录（或刷新页面）。学员的「我的应用」里应出现「学习中心」。

## 6. 5 分钟冒烟测试

1. 教师打开「应用 → 学习中心 → 云课堂管理」（/admin/elearning）。页面最上面的视频表单不用管，它的按钮是灰的，属于正常现象。
2. 往下找到「文章与链接课程」：填课程标题 → 添加文章（文章 HTML 直接填 `<p>测试</p>`）→ 在「指派对象」里填一名学员的**用户 ID**（在用户管理里查）→ 点「发布内容课程」，应提示成功。
3. 学员登录 →「我的应用 → 学习中心」→ 看到这门课 → 点「打开并记录完成」→ 课程状态变为「已完成」，「学习档案」里已完成数加 1。
4. （可选）教师在「题库与考试」里导入 xlsx 题库并组卷，再到「刷题练习」区用这份试卷建练习集。学员在「刷题练习」里**先在下拉框选中练习集**（默认是空的）→ 开始练习 → 提交答案，页面显示「回答正确。」或「回答错误」。
5. 找一个没有角色的普通账号登录：「我的应用」里没有学习中心；直接打开 /learn 会被送回首页。

以上都符合时，启用完成。

## 7. 回退

1. 从 `docker/app.env` 删掉第 2 节加的 7 行。
2. 按现有方式重启后端。
3. 预期结果：学习中心卡片消失，`/api/elearning-app/installation` 返回 404 `feature_disabled`，插件页显示 `inactive`。
4. **数据库里的内容全部保留**：课程、学习记录、积分、证书、题库、安装状态（仍记为 active）、角色和插件准入都不变。本地演练中，关掉前和关掉后逐表行数一致。
5. 以后再开：把 7 行加回去并重启即可，**不用重新安装或启用**，学员数据直接回来。
6. 回退期间**不要**在插件页点「启用」或「停用」。

## 8. 不要设置的开关和原因

| 开关 | 原因 |
| --- | --- |
| `ELEARNING_MEDIA_ENABLED` | 开启后需要可用的视频对象存储。存储探针失败可能导致后端起不来。本次试点不带视频 |
| `ELEARNING_WATCH_CHALLENGE_ENABLED` | 依赖视频，没有视频就没有意义 |
| `ELEARNING_NOTIFICATIONS_ENABLED` | 会对外发送学习通知（钉钉）。对外发送需要 owner 单独批准 |

## 9. 已知限制（演示时主动说明）

- 学员参加不了正式考试，只能做刷题练习。
- 「完成课程」「登录」等积分规则能发布，但在本版本里不会自动加分。加分只能用「人工调整」。
- 分析数据按部门统计：不足 5 人的部门显示为已抑制；只统计到前一天；生产模式下没有导出存储：含 F9 修复的版本起「创建导出」按钮置灰并显示「当前部署未配置导出存储，分析导出不可用」的说明（更早的版本点了会失败，STORAGE_UNAVAILABLE）；是否配置对象存储由 owner 决定。
- 自学报名要先给课程设置可见范围，而这一步本版本没有界面。演示时请改用「指派」。
- 安装区块是英文，学员页副标题提到「视频」，截止日期显示为原始时间格式。这些都是文案问题，不影响使用。
