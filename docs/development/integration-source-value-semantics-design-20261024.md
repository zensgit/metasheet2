## 配置合同

配置放在既有 readPlan JSON 中，复用保存版本、目录校验、样本确认、批准、激活流程。请求参数不能覆盖已批准配置；不改全局默认。新增两个可选顶层字段：

```json
{
  "sourceProjectComparison": "case-insensitive",
  "bomActiveState": {
    "activeValues": [1, "启用"],
    "inactiveValues": [0, "停用"]
  }
}
```

1. `sourceProjectComparison` 仅允许 `case-sensitive` / `case-insensitive`。缺省保留现有精确文本比较，并且规范化不补默认键，避免改变旧配置摘要。显式模式接受非空文本和安全整数幅度内的有限数值，不将布尔或对象推断为项目编号；未配置继续使用既有 `toKey` 路径。沿用项目号既有首尾空白处理；不将 `0010` 与 `10` 视为相同项目。大小写模式使用同一明确的文本大小写折叠函数，不声称模拟 SQL Server 全部排序规则：重音、宽度、语言特例等不在此配置承诺内；客户应按来源字段语义选择并通过样本确认。
2. 状态物理列沿用 `bomHead.activeField`，默认示例为 `bom_able`，并非固定客户列名。
3. `bomActiveState` 的两个集合各含 1–32 个 JSON 标量：布尔、有限且绝对值不超过安全整数范围的数字、非空且无控制字符的字符串（最多 128 字符）、或显式 `null`。类型严格匹配，数字 `1` 与字符串 `"1"` 不等；字符串不隐式去空白或折叠大小写。集合内重复、跨集合重叠、额外键、嵌套结构或缺少状态列均拒绝。
4. 启用映射后的未知、缺失或大小写重复列一律拒绝；`null` 只有显式列入一个集合才有含义。未配置映射时保持既有默认解释，包括历史显式 NULL 行为；不借本轮变更改全局默认。

值集合不能进入 `ROLES` 的列名列表。目录校验只验证物理列，真实样本展开和每次执行验证实际遇到的状态值；样本通过不代表全库值域已普查。新增字段均参与完整配置摘要、版本和执行身份，改配置必须重新校验/批准，不得沿用旧预览 token。

## 项目身份与歧义边界

配置控制的是来源 `pathExAttr.matchField` 与 MetaSheet 已登记项目号的比较。例如登记 `Abc`，可匹配来源 `ABC`。内部参数、目标、审批、token、写锁和行幂等键继续使用服务端登记的 `Abc`；不自动将 HTTP 请求 `abc` 路由到 `Abc`，不改登记主键，不迁移或合并旧项目。

在启用不区分大小写的执行路径，来源读取和发放预览 token 之前，必须确认可信租户及精确登记目标；读取含归档行的租户登记清单并检查其完整性，当前项目等价组必须仅有精确命中这一条。清单不可用、截断、不一致或存在大小写冲突时具名拒绝，不自动选第一条。仅有当前 sheet 的 foreign-row 检查或 sheet 写锁不能证明跨 sheet 唯一。每次执行重新检查，不缓存该结论；该检查不宣称替代登记创建的事务约束。

选择此模式但没有可验证登记目标时拒绝，不通过旧环境目标推断项目唯一性。源码级纯展开函数可用合成来源单测；实际 HTTP 消费路径须验证上述门已接线。

## 第四轮补正：登记前原子拒绝大小写变体（本地）

基线 `d3930865ea79e05550d1203fbde43dc0495be20a`。Owner 要求优先修复登记漏洞，并允许在拒绝变体与自动路由之间选择；本轮选择拒绝变体，保留原登记拼写，与既有不自动改路由的合同一致。上轮普通追加推送及 CI 已获得直接授权并执行；此次新修复仅本地实施和验证，不沿用上轮发布授权推送新补丁，#6337 保持封存。

登记的有效模式来自服务端当前有效的读取计划（含已激活在线版本），不能只看部署配置，更不能接受请求体自报。没有配置的旧行为保留；有效计划解析失败不得降级放行。新建路径在既有租户 advisory transaction 内重新取模式、扫描含归档行的完整登记、检查冲突，然后才允许 provision、安装字段包和登记插入；不能先建表再在 insert 前拒绝，也不能外层持锁后调用另开事务的 create 而自锁。重放须保留精确原拼写及归档门。

模式为 case-insensitive 时，只差大小写的已登记项目（含归档）使新登记返回具名 409，拒绝前不得发生建表、安装字段包或授予角色写权限。相同精确拼写重放保持既有幂等行为；未配置及 case-sensitive 不扩大限制；租户间相互独立。验证必须走真实路由、有效计划解析和真实 store，并检查并发争抢下的登记数量及宿主写次数，另做逐条变异。

本轮对抗复核补充：带有效模式解析/宿主回调的事务复用 `pinLockProtocolIsolation`，首条 SQL 固定 READ COMMITTED，再通过同一租户 key 的 `tryAdvisoryXactLock` 取锁，只有布尔 true 可继续。争抢失败返回 `STOCK_PREPARATION_PROJECT_TARGET_BUSY` 409，解析器和宿主回调均不运行；待首个请求完成后，变体再次登记返回 `STOCK_PREPARATION_PROJECT_IDENTITY_CONFLICT` 409。这样避免这些新建/重放等待者阻塞持连接，并防止继承 REPEATABLE READ 的陈旧扫描。既有 archive/restore 等阻塞参与者未在本轮扩大改造，不能声称整个租户锁协议的连接池饥饿均已消除。

本补丁不自动修复历史重复行，不迁移登记，不改变项目以外的标识比较，不在 222 打开开关，也不增加状态未知值按停用的选项。状态字段与显式启用/停用值仍可配置，未知值拒绝，未配置保留既有默认。计划激活使用另一把锁，本补丁不声称登记与并发激活整体原子化；启用比较模式前仍须单独盘点冲突、核对租户声明和项目表前提。

回滚同时覆盖在线计划与部署 readPlan JSON：必须先停用依赖新字段的消费路径、恢复经确认的旧配置再退代码，不能让旧版本静默忽略新字段后继续执行。客户数据盘点与实际部署不在本轮范围。

## 第六轮补正：登记与激活串行化（Claude 实现，本地，2026-10-26）

第五轮补丁关闭了 P2-A / P2-B，但留下其自述的残余：登记前一次性解析模式，默认/CS 登记在锁内不再复查；激活不看登记表、也不与登记共用锁。并发时可能混入一对大小写变体，在线计划一旦生效两者都被执行侧拒绝；“启用前盘点”在在线路径上也只靠人工。本节在不改两条登记路径结构的前提下补上串行化。

- 激活侧：激活一份 `sourceProjectComparison: 'case-insensitive'` 的版本时，读计划存储在自己的激活事务里，固定 READ COMMITTED 之后、锁任何来源/版本/指针行之前，先取登记表的同一把租户锁（阻塞），再扫描该租户全部登记行（含归档），存在大小写折叠后相同的项目组即 409 `READ_PLAN_ACTIVATION_PROJECT_IDENTITY_CONFLICT`，扫描不可信即 503 `READ_PLAN_ACTIVATION_PROJECT_IDENTITY_UNAVAILABLE`；不写指针、不返回任何项目号。区分大小写或未设置的版本不取该锁。锁与扫描由登记表模块导出的 `lockRegistryAndCountCaseFoldedProjectGroups` 提供，不在读计划模块复写锁键。
- 登记侧：默认/CS 路径仍在锁外建表，但把同一模式解析器传入 `create`；`create` 在“有解析器、无 prepareTarget”时固定 READ COMMITTED 后取**阻塞**锁，锁内重新解析模式，若已变为 CI 则先扫描再插入。这取代第五轮“默认/CS 登记不传解析器”的写法；默认/CS 重放仍不传。仍不会出现 BUSY。
- 锁顺序：两侧都先取登记表锁；登记持锁期间的模式解析只做不加行锁的自动提交读取（`getActivation`、`listForAction`、`getForRuntime` 均为普通 SELECT），其余只读写登记表本身，不碰激活要锁的来源/版本/指针行，因此不会互相等待成环。
- 连接池占用（备料线评审 2026-10-26 已接受）：默认/CS 登记持阻塞锁期间，模式解析在连接池的另一条连接上读取。这在**新建**这一腿上是新增的；main 上的重放腿与合同选项修复路由早已有同类持锁占连接的情形。备料线用真实形态连接池实测：同租户同时 ≥20 个默认路径登记时整个后端约停滞 9–10 秒，持锁者得到 503 且未改动任何数据，多出的请求得到无类型 500，随后自行恢复；19 个并发 65 毫秒内完成。可选后续（owner 决定）：把事务句柄传给模式解析，`getActivation` / `getForRuntime` / `listForAction` 增加可选 `{ executor }`（#6514 已用同一形态），实测 20/40 并发 55–79 毫秒全部成功、无停滞；不建议仅加锁等待上限（仍停滞约 4 秒，19/20 无类型失败）。
- 已知残余：在“预读为 CS、激活恰在建表期间提交”的极少见竞态里，默认路径已在锁外建好的表不会被登记，仍按派生 objectId 由同一拼写的重试复用（与原“建表后失败可重试”属同一类）。部署 JSON 开启 CI 需重启，运行期无竞态；历史重复仍由执行侧拒绝，启用前盘点仍是前提。
- 前端：管理面板新增两条固定文案，不提示重试；诊断码白名单新增两码。

实施与证据见 [验证记录 §15](integration-sa01-sa02-local-resume-verification-20261024.md#15-登记与激活串行化claude-实现2026-10-26)。提交前仍需备料线会话复核共享登记 store；本节同样只在本地，不推送/CI/合并/部署。
