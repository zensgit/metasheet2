# Managed auth writer interlock — design and verification (2026-10-18)

This slice serializes managed browser completion and normal Meta identity transitions using one origin-wide exclusive Web Lock, `metasheet-auth-identity-v1`. It reuses existing session, source binding and revocation engines. The native provider, backend auth policy and migrations are unchanged. Base is `aec9458c8137a883bcc9fd1a13b96c58bf950d6f`; native runtime verification uses `991d8a62849df9576af164e935785bcdd15774c0`. Draft only; no merge, deployment or production enablement.

## Identity transitions

Every external transition queues on the browser lock. The mutation guard exists only during a synchronous callback, resets before any await and rejects async callbacks. It is not a global async reentry shortcut. Bare token setters, explicit-org setters and storage clears refuse when coordination is required. Existing ordinary standalone behavior remains available without Web Locks when no managed residue exists; managed start/complete/logout refuse unsupported coordination before posting.

Password/container/invite/forced-password/DingTalk login, dev-token publication, org switch, App/session-center logout and API/bootstrap401 cleanup use awaited transitions. Org-switch alias/barrier rollback remains synchronous. Ordinary publication first revokes any managed cookie or pending completion residue; failed revocation leaves identity/markers intact and prevents navigation. Complete holds the lock through response-body validation and identity recheck. A persisted pending marker is required before the POST. Network failure retains it; pending state blocks a no-bearer managed snapshot probe until recovery. Known409 refusal preserves the pre-existing managed session. A successful but stale/unreadable body compensates with the existing managed logout.

Request stamps include the actual stored token, principal signature and epoch. Stale401 cleanup rechecks its stamp inside the lock before revocation, mutation, failure-cache adoption or redirect. Late dev-token publication checks the initiating signature. Login/forced-password failure wipes clear only the session their request owns. Intentional user logout remains unstamped. Forced-password logout captures and explicitly sends its original ordinary bearer after managed-cookie revocation/local cleanup, so it still revokes the server session.

## Scope and remaining acceptance

The guarantee covers cooperating normal application writers within one browser profile implementing Web Locks. It is not an XSS boundary, does not coordinate other profiles and cannot make localStorage aliases or browser cookie installation transactional with PostgreSQL. A killed document may leave a cookie already stored; persisted pending state forces normal recovery to revoke before identity publication or managed snapshot adoption. The browser still applies Set-Cookie before script reads a body.

AcceptInvite has no mounted component spec and SessionCenter's existing component spec does not click its private redirect helper; their changed call sites were independently read and typechecked, while shared transition behavior is exercised directly. Exact-source remote CI, installed package/backup/restore/disable acceptance and the complete master goal remain pending. No full engineering-goal completion is claimed.
