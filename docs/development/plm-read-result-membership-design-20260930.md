## 1. 已复现问题与裁决

真实 `expandPlmProjectBom` 的纯内存探针确认：其余读取正常时，单次混入错误父件的 BOM 头、错误版本的 BOM 头或错误 BOM 的明细，仍可能返回 `valid:true/status:expanded`。显式订单版本保护也不能挡住外来明细。Bridge 合同允许返回未在源端过滤的完整记录集，`filtersApplied` 只是元数据，不是归属证明。

修前代码位置（相对 `plugins/plugin-integration-core/`）：`lib/adapters/bridge-agent-readonly-adapter.cjs:428` 接收记录、`:457` 转交过滤元数据；`lib/stock-preparation-bom-expansion.cjs:702` 仅记元数据，`:1870` 的普通 BOM 头只核 active，`:1906` 明细未复核父 BOM；订单头和明细同类读取在 `:2133`、`:2141`。这些行号仅锁定上述修前字节，修改后以验证报告为准。

本片选择在业务消费者沿用已有 `readField`/`matchesByField` 复核，不改变 Bridge、SQL adapter 或 `readAll` 的通用合同，不因 `filtersApplied:false` 一概拒绝合法宽结果。无新端点、权限、capability 消费者、DDL、flag、外部发送或真实客户访问；属于既有客户 BOM 正确性修补，不是新平台建设。

## 2. 精确行为

| 返回集 | 必须满足的归属 |
| --- | --- |
| 订单头 | 声明的 path 字段等于当前已确认的路径 ID |
| 订单明细 | 声明的 order 字段等于当前订单 ID；在版本、数量和根选择前过滤 |
| BOM 头 | 声明的 parent 字段等于当前部件；显式订单版本继续用已有 `comparableBomVersion`，普通/递归路径仅复核实际发出的版本条件 |
| BOM 明细 | 声明的 parent 字段等于当前 BOM ID；在数量、循环、子件读取和去重前过滤 |

所有复核无条件执行，不以 metadata 为开关。普通 ID/版本沿用既有 key 比较与字段大小写兼容；不新创数值、排序、trim 或版本兼容政策。显式订单版本仍保留无活动匹配、缺 BOM ID、多 BOM ID 的固定错误；递归子件仍用自身版本，不能继承根订单版本。未发送版本条件时不凭空添加。

过滤后的行为沿用既有合同：无匹配普通 BOM 头可成为叶子；有匹配头但无匹配明细报 `missing_child_bom`；外来头不能触发假深度溢出，外来明细不能触发假循环。有效匹配数据的数量相乘、同父去重、跨父出现、根选择和限制不改。读取统计仍计原始回包和真实请求次数，不掩盖宽结果成本；分页/完整性预算仍先完成源读取后判定。

2. 五个归属谓词分别有正交负例，其他关系合法；metadata 为 false/true/缺省都不能成为旁路。
3. 订单版本与物料版本分离、递归、subtree 共用路径、改名/大小写字段、数值 ID、分页的有效匹配保持正确。
4. 真实 table-actions → expander → planner → 本地内存 apply 断言外来行不进入预览/计划/写入，不以替身 planner 或 expander 自证。
5. 补同父、同要求版本的禁用头用例；原用例先被版本过滤，不足以单独证明 active 守卫。
6. 每个独立守卫的内存降级必须触发行为断言；冗余守卫若单删存活应明确记录，不伪称全部检出。
