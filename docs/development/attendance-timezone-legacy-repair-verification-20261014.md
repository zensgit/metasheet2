## 问题与修复

多时区关闭也会遇到历史日期缺冻结上下文、组织缺默认规则的写入阻塞。本次保留严格时区语义，用独立运维工具补齐有证据的上下文，不在迁移或普通读取中自动补数据。

- 完整旧 V2 快照继续走既有严格复用路径。
- 普通旧记录必须提供经人工审阅的历史规则、日历、无获胜排班事实、尾窗和无批准加班事实。当前规则、空 meta、存储时区本身均不能替代历史证据。源文件摘要只绑定批准字节，不证明历史真实性。
- 预览使用只读事务；执行必须同时提供源文件与计划 SHA-256，重新校验原记录完整行摘要、管理员及员工组织关系、持久计算状态。只追加 companion，不改原记录或事件。相同批准计划可精确重放。
- 执行按 rollout → 时区组织/成员/排班 → 记录的既有锁序，并使用 READ COMMITTED；记录变化拒绝，不覆盖并发写入。
- 旧记录上下班、补卡和请假沿用修复后的上下文。旧待审批请求可从对应 repaired parent 取上下文；补卡不再被后改排班重新解释。闭合跨夜旧班次的尾窗不能抢走次日上班卡。
- 缺默认规则的组织可由管理员明确输入合法时区后受控恢复；保留未结束记录、附近排班、轮班、计算组及有效已批准出差的保护。无法证明旧边界时仍拒绝。
- 界面显示固定错误解释，区分配置缺失与历史升级问题，不再笼统让用户刷新。

## 首版边界

工具仅支持 `legacy_untracked`、无计算指针的普通旧记录。活跃弹性规则、旧排班归属、已批准加班窗口、DST 重叠/缺失墙上时间及非 legacy 持久计算状态均明确拒绝；不得伪造 V2 issued context。修复后若组织进入非 legacy 状态，运行时也会拒绝使用该 rule-only repair。

缺默认恢复采用 UTC 当前日期前两天至后一天的保守排班检查；未开始但落在该区间的排班也可能要求冻结证明。有效未来出差、计算组来源无法证明时不自动恢复。这是可用性限制，不是声明所有旧组织均可直接恢复。

组织预检逐页扫描，最多 100000 条记录/申请、每条 SQL 10 秒、总扫描预算 30 秒。所有待审批关联单据、未严格运行时验证的 V2 和非 repair companion 都是 `REVIEW_REQUIRED`；无依据或损坏记录是 `BLOCKED`。未扫完绝不 `READY`。`READY` 仅描述这一只读快照的历史上下文检查，不替代完整业务验收或部署许可。

## 运维入口

在隔离验证或另行批准的环境中，由已有数据库运维身份执行。数据库连接只从环境读取。`--actor` 是需核对的组织管理员身份，不是一个新的远程认证机制。私有档案必须受控保管，不提交到仓库、Issue 或日志。

```sh
pnpm --filter @metasheet/core-backend exec tsx scripts/attendance-timezone-legacy-repair.ts \
  --preflight --org=<组织标识> --actor=<管理员标识>

pnpm --filter @metasheet/core-backend exec tsx scripts/attendance-timezone-legacy-repair.ts \
  --source=<私有历史档案.json> --actor=<管理员标识> --confirm-archive-source

# 仅在批准这份源文件和预览计划后；不是本轮目标环境执行授权
pnpm --filter @metasheet/core-backend exec tsx scripts/attendance-timezone-legacy-repair.ts \
  --source=<同一私有历史档案.json> --actor=<同一管理员标识> --confirm-archive-source \
  --apply --approved-source-sha256=<预览源摘要> --approved-plan-sha256=<预览计划摘要>
```

原记录摘要必须从固定 UTC 会话的 `to_jsonb(record)` 计算。完整档案字段及校验约束见 CLI 顶部示例。预检退出 0=READY、2=BLOCKED/REVIEW_REQUIRED、3=未扫完、1=固定错误；普通预览/执行失败退出 1。输出只有固定码、计数及摘要。

## 回滚与发布前检查

本次无新数据库迁移、无自动回填和新开关。目标环境部署前应另批只读普查、历史档案审阅、备份及恢复演练；存在未解决旧记录或未验证单据时禁止放行。

代码回滚应使用经确认兼容的先前包，先停止受影响写入并记录当前版本。不能通过删除 immutable companion、重新计算已结算记录或临时改时区实现回滚。若经批准的实际回填有错误，应停写、保留审计证据，按预先验证的备份恢复方案处理；本轮没有对任何实际环境执行这一流程。

组织锁粒度和大规模历史性能 P2 不在本次修复完成声明内。
