## 5. 方法学产出(本会话真正的价值密度)

每个子代理都被要求「**先证伪再动手**」。命中多次,每次都拦下一个错误:

1. **一个自称守卫的 fixture**(公式对齐守卫无 import 边)→ 可复用判据:**读守卫的 import 列表;与被守护对象无活引用 = fixture,不必运行即可判定**。已固化为记忆里 wire-vs-fixture 失明的第 8/9 形态。
2. **一条「不可能实现真守卫」的辩护**(跨包 import 会拉起连接池)= 属实但无害(构造连接池不开套接字)→ 守卫本该长在 backend 侧。
3. **非网格视图**:画廊是假阳性(有翻页器);「静默截断」其实更糟(同屏两个互相反驳的数字);层级视图会把已载入内存的行永不渲染。
4. **分组小计**:值是对的,骨架(存在/计数/顺序/边界)才错——审计过度声称被收窄。
5. **队列门禁的两个 catch**(§4):一个假安全声明、一个信任边界 P1——在 ratify 前拦下。

一个我自己核实并**纠正了自己此前过度声称**的发现(G5,分页元数据在权限过滤前成形)已经独立渠道交付 owner,不在本文展开。
