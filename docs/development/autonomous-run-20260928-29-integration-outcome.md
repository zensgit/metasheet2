owner 问：对标 n8n、数环通、飞书连接器这类产品，这块功能做到什么程度。做法是五个读者按能力域读代码，按固定的 13 项清单打分，每一项都有一名只读反驳者复核（两项的反驳者在成批重启里没交回，事后另起补做）。全程只读，未运行任何测试。**全文和逐项的 `path:line` 锚点只在开发机的临时目录里**；入库时每条缺口应附一到两个锚点。

**13 项清单与结论**：连接器目录、通用连接器与扩展、触发器、流程编排、数据映射与转换、执行可靠性、可观测性、凭据与安全、可视化构建器、模板与复用、内网触达、写回与双向同步、流程上的权限与协作 —— **每一项都是「部分具备」**，没有一项完整达到，也没有一项完全空白。

评估认为最实际的三个缺口（只读结论）：

1. 多维表自动化规则和数据工厂里一源对一目标的管道互不相通（另有一套默认关闭的 BPMN 设计器）；读代码没找到自动化启动管道、或管道写入后发事件的路径。
2. 没找到管道在产品内的定时、排队、自动重试和失败告警；现在的定时拉取靠操作系统计划任务。
3. 非管理员基本用不了：三类权限码没有入库；摸底的反驳者另指出只补种子打不开这条路（§5.1）。09-30 演示机上两个非管理员账号访问数据源都得 403，「数据工厂」页被前端路由守卫弹回首页。

连接器广度、OAuth2、画布、代码步骤的延后是记录在案的，出处：`docs/research/integration-capability-benchmark-vs-dingtalk-feishu-yida-20260703.md:9`、`:71`，`docs/development/dev-plan-gap-audit-20260916.md:187-188`。

反驳者纠正的两处细节：

- **数据映射**：来源记录缺字段时，真实运行写入空值，更新时会清掉目标原值，只有勾了必填才拦下。预览里显示为缺失，预览与运行不一致。这个转换（`plugins/plugin-integration-core/lib/transform-engine.cjs:213`）在 main 上只有四个调用点（`pipeline-runner.cjs:786`、`external-write-dry-run.cjs:784`、`http-routes.cjs:3564`、`:3590`），备料拉取不在其中；客户只用备料拉取就不经过它，客户有没有配通用管道没查。
- **内网读取的截断**：一次读取上限 500 行（`lib/adapters/bridge-agent-readonly-adapter.cjs:47`），无翻页。被截断的一页有三种不一致的处理：备料来源拉取明确报错拒收；通用管道记为成功且无截断标记；BOM 展开当作完整数据接受。BOM 展开在不在客户当前路径上没查。
