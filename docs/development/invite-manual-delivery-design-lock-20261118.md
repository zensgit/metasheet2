# 待接受邀请改为手动交付

基线 57a53c2c29。独立于 B2 和普通创建工作树。无新用户、无邮件、无登录标识更改，不更正邀请，不自动重试，不操作环境。

1. 已有平台管理员认证。待处理邀请面板逐条确认目标姓名/登录标识与后果。POST /api/admin/invites/:inviteId/manual-delivery，仅当前邀请，无自选密码或目标覆盖。仅成功提交后回实际登录邮箱和一次性显示的系统临时密码，Cache-Control: no-store；关闭/卸载清空，迟到响应不回填。失败不显示凭据，不确定结果先刷新，不重发。
2. READ COMMITTED 事务内先按邀请定位目标，再沿现有接受流程的顺序锁原 users 行，后锁该用户的邀请。首版仅允许恰有一条邀请，且 pending、未消费；有效签名和期限、token 的 userId/email 与邀请及当前账号一致，和接受入口一样拒绝已失效的用户版本。账号 active、activated、本地密码已可用、未删除/清除。拒绝目标为操作者本人。检查 last_login_at、任何历史 session（包括已撤销）、已接受邀请；有任一证据或读取未知即不转换。
3. 同事务：邀请改为不可重发的新终态 manual_delivery，记录实际管理员和时间（复用适当字段或专列，不伪造接受）；换密码哈希、强制首次改密、推进 access_generation。记录不含凭据的操作审计。失败两边都不写；不改组织、绑定、角色、准入和撤权证据。枚举、重发的读及条件 UPDATE 都拒绝新终态，旧 pending/expired/revoked 行为不变。生产 recordInvite 当前仅对应新建用户；多个历史邀请拒绝处理。
4. 防首次登录竞态：密码核验和会话登记不是一条事务；以验证密码时读到的 access_generation 调用现有加共享锁的登记方法，登记失败不得发 token。交付持用户排他锁后以新语句读 session；先登记则拒交付，先交付则旧密码读出的代际无效。网页和容器外部登录已有代际校验；SSO 激活必须从激活写事务取得当时代际，传给真实回调登记，不得改用提交后重读值。门禁包括激活提交后暂停登记、管理员改成有本地密码、交付导致原登记失败。不把 dev-token 当生产登录，不放宽任何现有认证条件。
5. 手动和接受、重发、重复交付同一行只存在可串行解释的结果。旧链接不可预览/接受，已交付不可重发；更新任何一步失败回滚。凭据不写日志、审计、存储。普通邀请列表不暴露新的秘密。用户首次用新密码登录必须改密，旧密码不能登录。无其他凭据恢复动作。
6. 门禁：独审设计后才动产品；后端验证拒绝路径及旧行为，前端验证显式二次确认、关闭清除、竞态及未知结果，迁移后独立合成库验证成功、原账号/权限不变、旧链接与旧密码失效、首次改密、重复/接受/登录竞争和故障回滚。没有执行的检查单列。不提交、不推送、不部署。
7. 锁内按当前密码登录模式只读确认邮箱唯一解析到本用户（别名模式含 readiness）；不可证明拒绝，不修复别名。交付无凭据审计用同一事务持久化 actor、时间、原邀请关联，失败回滚，不依赖 best-effort auditLog。重发先写则使用并校验锁后最新 token；交付先写则已预读的重发条件写也须失败。两种顺序均测；所有列表只对 pending/expired/revoked 提供重发。
## 使用边界

实现独审补充：此端点的全局及路由认证不得顺带补写角色。事务等待原账号锁后必须确认操作人仍有持久化的平台管理员资格，并与实际撤权操作串行；证据不明不交付。发送期间不能无提示关闭唯一一次密码展示；无法得到成功回执时不能把同一凭据再次显示或自动重发。

手动交付改变的是原账号领取凭据的方式，不是「新增普通用户」：原有角色既不增加也不降级。管理员须先核对收件人；姓名或登录标识填错时不要交付，本功能不更正邀请。

将来若上线，应先升级全部可接受或重发邀请、签发会话的实例，再开始交付。旧版重发逻辑不认识新终态，不能在已产生手动交付记录后直接回退到旧版。这不是部署授权。
