## §2 Causal order — ONE `seq` domain across revisions AND markers
The chain walk must interleave content revisions and markers in true causal order; `created_at` (=txn-start, same-ms collisions), `version` (resets per generation), and UUID ids cannot do this — and today the marker join orders by exactly those.
- **Migration:** one PG sequence `meta_record_chain_seq`; add `seq BIGINT DEFAULT nextval('meta_record_chain_seq')` to **both** `meta_record_revisions` and `meta_record_version_markers`; NOT NULL after backfill; indexes `(sheet_id, record_id, seq)`. Backfill legacy rows best-effort by `(created_at, version, id)` — legacy pre-checkpoint records are fail-closed anyway (§6), so the backfill is ordering-for-display, not trust.
- **Generation** = count of `action='create'` revisions at-or-before, **ordered by seq**. **Contiguity** judged per `(sheet_id, record_id, generation)` in seq order; the version chain must be +1-dense within the generation, markers occupying their consumed versions; the terminal `delete`'s version-duplicate is expected; `v3-delete → v1-create` = generation boundary, never a regression.
- **Marker uniqueness** (replaces the dropped constraint): *within a generation* exactly one chain event may occupy a version; a duplicate ⇒ fail-closed `chain_corrupt`. Cross-generation repeats are legal by construction. The marker INSERT drops `ON CONFLICT DO NOTHING` — any conflict fails the enclosing lock/unlock txn loudly (no silent swallow, no divergence between the version bump and its marker).
- **C2 (contiguity leg, fail-closed):** within a generation, `seq` order and `version` order must agree; disagreement ⇒ `nonmonotonic_history` refuse. **This is only the CHAIN-WALK leg of C2** — it does NOT fix reconstruction (see §2b).
- **Exact comparison (v3.6 Medium):** `seq` is `BIGINT`; every comparison/sort in the precheck AND the reconstructor MUST use an **exact bigint/string comparator**, never `Number(seq)` + subtraction (values collapse past 2^53; a float64 tiebreak swallow already bit this line). §8 adds a production-magnitude (`> 2^53`) seq value test.
- **Causal caveat (v3.6 Medium):** a PG sequence is *allocation* order, not *commit* order — `seq` is a trustworthy causal order ONLY under the L4 fence (allocation + write serialized) + L5 checkpoint (excludes prior un-fenced events). The backfill is display-only, not trust. "Prospectively causal on landing" is withdrawn.

## §2b Reconstruction linearization — the C2 REAL close (v3.6 High-1)
`seq` orders the *chain events*, but recovery/PIT reconstruction (`record-reconstructor.ts:25`) selects each record's state by **`created_at ≤ T`**, and `created_at DEFAULT now()` is **transaction-START** time. A write that started early but acquired the sheet fence late commits later yet carries an *earlier* `created_at`; its `seq`/`version` increment normally, so the strict contiguity check passes — but a query at a `T` between that write's `created_at` and its actual effect reconstructs a state that **had not happened**. Reconstruction must not keep trusting txn-start time.
- **`effective_at timestamptz`** — a linearized time taken with **`clock_timestamp()` while holding the L4 sheet fence** (so, because the fence serializes writers, `effective_at` is monotonic with `seq`/commit order for that sheet). Stored on each chain event alongside `seq`.
- **Reconstruction selects by a T→seq boundary:** for wall-clock `T`, the boundary is `max(seq)` among the record's post-checkpoint chain with `effective_at ≤ T`; reconstruct the record's state at that `seq`. `created_at` is retained for display only, never for selection.
- **C6 truncation:** the checkpoint (§6) defines the post-checkpoint `effective_at`/seq origin; pre-checkpoint (pre-fence) events have no trustworthy `effective_at` ⇒ any `T` below the checkpoint fail-closes (already the §6 posture).
- **Hard dependency:** `effective_at` is only monotonic because the **L4 all-writer fence** serializes writers — so §2b's linearization, and thus C2's real close, **cannot land before L4** (see §10). Golden (§8): a constructed early-start/late-fence write ⇒ a `T` in the window resolves to the pre-write state (not the un-happened write); mutation to `created_at ≤ T` selection reds it.

## §3 All-writer shared sheet fence — with the SAME-TRANSACTION / SAME-CONNECTION contract (v3.1 owner P1 fix)
`pg_advisory_xact_lock` acquired in an **autocommit** statement is released the instant that statement ends — it fences nothing. "Outermost first statement" is therefore insufficient by itself; the binding contract per writer entry is:
1. **Explicit transaction** — the entry opens (or provably inherits) a real transaction before the fence; no autocommit acquisition, ever.
2. **One client** — fence acquisition, `seq` allocation, revision/marker writes, and the `meta_records` mutation all execute on the **same client/connection** (the transaction's query fn); passing `pool.query` where the txn's `query` is required is a contract violation.
3. **All-or-nothing** — any step failing (including the marker INSERT, §2) rolls back the whole transaction.
4. **Entry matrix (impl + gate deliverable):** a table of *entry → transaction owner → fence acquisition point → mutation site* for every writer family — patchRecord (`record-service` txn), bulk patch (`record-write-service.ts:768` `pool.transaction`), deleteRecord, plugin patch/create/delete (caller txn via SDK), automation create/update/delete/lock/unlock (`automation-service.transaction` / button `txq`), form-submit (route txn — already compliant), trash restore, PIT resurrect (revert txn), attachment-delete (route txn), lossy-retype revert, lock/unlock routes. The create family (`record-service:518`, `records:587`, form `14485`, auto-number `:82`) is compliant today; each remaining family must be shown fenced **inside its real production transaction**, not a test-only wrapper ([[feedback_verify_follow_the_delegation]]).
5. **Per-family production-wiring mutation proof:** for each family, neuter its fence (or acquire it on the wrong client) ⇒ that family's constructed race golden reds. A family without a red-capable golden is not verified.
Single serialization point per sheet ⇒ no deadlock; reset/revert destructive txns hold it ⇒ nothing can write after the in-txn re-check. Reset keeps the landed in-txn re-check + per-affectedId FOR UPDATE; **revert's resurrect txn gets the same in-txn re-check**; revert's per-record field-revert loop remains deferred behind the #4261 gate (unchanged honest boundary).

## §4 Deleted/trash chain enumeration + asOf-generation check (C3 — v3.6 High-2 corrected)
Strict mode enumerates live rows **AND** records that existed at T but are now deleted (from the revision chain + `meta_records_trash`): Revert resurrects them, so their generations must pass per-generation contiguity or the operation refuses.
- **Not terminal-only (the v3.6 High-2 fix).** L3 (#4309) checked only the *terminal* generation's contiguity — but a user can pick `T` inside an **older** generation (before the last delete), and reconstruction to that `T` would then use an old generation that has a hole while the precheck passes. **The precheck must validate the TARGET asOf generation** — the generation that `T` falls in (per §2b's `effective_at`→seq boundary) — for every record in scope. Conservative alternative: check **all** generations that are reconstructable after the selected checkpoint (i.e. every generation with `effective_at ≥ trusted_from_at`). Either way, a hole in the generation `T` resolves to ⇒ `HISTORY_INCOMPLETE`, never a silent pass.
- Golden (§8): a record with a **clean terminal generation but a hole in an older generation**, queried at a `T` inside the old generation ⇒ 409 (mutation: revert to terminal-only check ⇒ this reds); plus the deleted-record mid-generation-gap resurrect golden.

## §6 Trust checkpoint = per-record BASELINE table + sheet watermark, TIME-anchored, executable state machine (C6 — v3.3 owner P1 fix)
A sheet-level watermark alone cannot establish a real trust origin; the checkpoint is a **baseline event**. v3.3 fixes the v3.2 cutover that was **unexecutable** (insert-active-before-flip trips its own partial-unique) and the **contradiction** between "retention keeps only the active checkpoint" and "superseded baselines serve old `T`". **Mechanism (decided v3.2): a SEPARATE baseline table** — synthetic `action='checkpoint'` in-chain revisions are rejected (they'd pollute History, retention, the `action` CHECK).

1. **Schema:**
   - `meta_history_trust_checkpoints (id, sheet_id, trusted_since_seq, trusted_from_at timestamptz, state 'building'|'active'|'superseded'|'retired', superseded_by uuid NULL, created_at)` — **partial unique** on `(sheet_id) WHERE state='active'` (at most one *active* per sheet). `'building'` and `'superseded'`/`'retired'` are outside the partial index, so a new checkpoint can exist alongside the current active one during cutover.
   - `meta_history_baselines (id, checkpoint_id, sheet_id, record_id, generation, version, kind 'live'|'trash', data_snapshot jsonb, tombstone_ref jsonb NULL, seq bigint)` — one row per in-scope record per checkpoint; FK to the checkpoint. **NOT** in `meta_record_revisions` (History / before-hydration / restore-by-version / `action` CHECK untouched by construction).
2. **Cutover state machine — ORDERING FENCE-FIRST, ANCHOR-UNDER-FENCE (owner v3.4 P1: the time anchor must not predate the fence).** All in ONE transaction on ONE connection. **The order is load-bearing:** the fence must be held *before* the anchor is taken, and the anchor must use `clock_timestamp()` (real wall-clock at that statement), **NOT `now()`/`transaction_timestamp()`** (which return transaction-start time — stale if the fence made the txn wait; an old writer committing during the fence-wait would then be baselined at a state LATER than the txn-start anchor, and a `T` in the wait window would reconstruct a state that did not exist at that `T`).
   1. `BEGIN` (READ COMMITTED, one connection).
   2. **Acquire the §3 sheet writer fence** (`acquireAutoNumberSheetWriteLock(query, sheetId)`) — blocks until every concurrent writer of this sheet has committed/aborted. Nothing can advance the sheet's state past this point.
   3. **`anchor := clock_timestamp()`** — the real wall-clock instant *after* the fence is held, so the anchor is ≥ the commit time of every write already reflected and < every future write (all future writes are fenced out). No writer can commit between the anchor and the baseline.
   4. INSERT the new checkpoint `state='building', trusted_from_at = anchor` (partial-unique on active does not fire — `building` is excluded).
   5. INSERT all baselines FK'd to it (the now-frozen state) — **live rows** = `{generation, version, full data_snapshot}`; **recoverable deleted/trash set** = `{generation, version, FULL inlined recovery payload, tombstone_ref}` (see §6.6).
   6. UPDATE the prior `state='active'` checkpoint → `state='superseded', superseded_by = new.id` (now zero active rows).
   7. UPDATE the new checkpoint `state='building'` → `state='active'` (partial-unique now satisfied — exactly one active).
   8. `COMMIT`. The partial-unique is never violated at any step. **Correction (v3.4, owner non-blocking):** because this is ONE transaction, a crash before COMMIT **rolls the whole cutover back** (the `building` INSERT included) — there is **no** orphan `building` row (the earlier "harmless orphan" claim was wrong: an uncommitted txn leaves nothing).
3. **Selection by T (fully total-ordered — owner v3.4):** reconstruction/precheck take a wall-clock `T` and select the **latest RETAINED checkpoint with `trusted_from_at ≤ T`** under a **total order** `ORDER BY trusted_from_at DESC, trusted_since_seq DESC, id DESC LIMIT 1` (states `active`+`superseded` not yet `retired`) — the seq+id tiebreak makes selection deterministic even if two checkpoints share a `clock_timestamp()`. Trust holds iff such a checkpoint exists; else fail-closed.
4. **Trust semantics:** for a `T` resolving to checkpoint C, every C-baselined record is trustworthy from its baseline forward (baseline + dense chain to `T`); a `T` older than every retained checkpoint's `trusted_from_at` is fail-closed.
5. **Retention floor + retire contract (owner v3.4 P2 — protect the FLOOR-SELECTED checkpoint, not "checkpoints whose time is within the horizon").** The earlier rule was wrong: for a retention floor instant `F`, the checkpoint that a `T = F` would select is the **latest checkpoint with `trusted_from_at ≤ F`** — and that checkpoint's own `trusted_from_at` is typically *older* than `F` (e.g. `C1.time < F < C2.time` ⇒ `T=F` selects `C1`, even though `C1` predates the horizon). So the floor must protect: **the checkpoint selected by the floor instant `F`, PLUS every checkpoint newer than it.** A checkpoint `Cᵢ` may `superseded → retired` (baselines + floored events prunable) **only when** its successor `Cᵢ₊₁.trusted_from_at ≤ F` (so `Cᵢ₊₁` already covers the floor instant and everything `≥ F`) **AND** no live preview/restore-operation references `Cᵢ`. Retention advances; every legal in-window `T` still resolves soundly; nothing is pinned forever.
6. **`tombstone_ref` contract (owner P1):** a trash baseline must be **self-sufficient for resurrect** — it stores the **complete inlined recovery payload** (`data_snapshot` = the full record data at delete, plus inbound/outbound edge set) so a resurrect rebuilds the record and its links from the baseline alone. `tombstone_ref` is an *additional* pointer to the live `meta_link_tombstones` rows; **iff** the design chooses to rely on those rows instead of fully inlining the edges, then those referenced tombstone rows **enter the retention floor** (cannot be pruned while the baseline is retained). Default (**recommended**): fully inline, so the baseline is independent of tombstone retention.
7. Cutover runs **after** the all-writer fence + loud-marker emission reach all instances (two-phase rollout); idempotent per sheet (re-run makes a new `building`→`active`, supersedes the prior; never two active).

## §8 Golden matrix (delta over #4269's landed suite; real-DB, mutation-proven, two-point wired)
- **generation-2 lock survives** (the P1-1 regression test): create→delete→restore→lock at a version the first generation also marked ⇒ marker INSERT succeeds (no swallow), strict precheck **passes**. Mutation: restore `ON CONFLICT DO NOTHING` ⇒ this reds.
- **within-generation duplicate ⇒ fail-closed** `chain_corrupt`.
- **unfenced-writer race closed** (the P1-2 constructed race): concurrent `patchRecord` attempted during reset's fenced txn blocks until commit (pg_blocking_pids harness) — final state == T. Mutation: remove the fence from patchRecord ⇒ race golden reds.
- **C2 fail-closed**: seq/version disagreement within a generation ⇒ 409. **C3 deleted-gap** ⇒ 409. **spoof golden** (§7). Plus #4269's landed goldens stay green (healed-gap, delete→restore→delete passes, formula, flag-off parity).
- **baseline redemption** (the §6 P1 regression test): a record with a **pre-existing pre-checkpoint gap** ⇒ after cutover, `T ≥ trusted_from_at` **passes** (baseline anchors it) while `T < trusted_from_at` refuses. Mutation: drop the baseline write from cutover ⇒ the pass-leg reds.
- **cutover executability** (v3.3): the full `building→(baselines)→supersede-old→activate-new` sequence **commits** in one txn without violating the partial-unique (mutation: v3.2's insert-active-first order ⇒ reds with a unique-violation).
- **anchor-not-before-fence** (v3.5 P1, CONSTRUCTED RACE — assertion direction corrected per owner round-8). Setup: the cutover txn `BEGIN`s at `t0`, then **blocks on the sheet fence** held by an old writer; that writer commits a new version at `tw` (`tw > t0`) and releases; the cutover acquires the fence and takes `clock_timestamp() = tc ≈ tw`. The baseline therefore holds the **post-write** state (it read after the fence). Consider a query `T ∈ (t0, tw)` — at that instant the `tw`-write had **not** committed, so the **correct** reconstructed state is **pre-write**.
  - **Correct (fix, `trusted_from_at = tc ≥ tw > T`):** `T < trusted_from_at` ⇒ this checkpoint is **not selected**; `T` resolves to the prior checkpoint (the pre-write era) or fail-closed — it does **not** return the post-write baseline. ✔
  - **Bug (`trusted_from_at = now() = t0 ≤ T`):** the checkpoint **is** selected and returns its **post-write** baseline — WRONG, because the correct state at `T` is pre-write.
  - **Golden:** build the real race (checkpoint blocked on the advisory lock via `pg_blocking_pids`; old writer commits at `tw`; fence releases). Assert that a query at `T ∈ (t0, tw)` does **NOT** resolve to the post-write baseline (it returns the pre-write prior-checkpoint state or fail-closes). **Mutation: set the anchor to `now()`/`transaction_timestamp()` (= `t0`) ⇒ the query now selects this checkpoint and returns the post-write baseline ⇒ the assertion reds.** Also assert selection is total-ordered (two same-`clock_timestamp()` checkpoints ⇒ deterministic pick by `trusted_since_seq, id`).
- **select-by-T**: an old `T` resolves to the **superseded** checkpoint that governed its era (`trusted_from_at ≤ T`, latest retained), not fail-closed (mutation: select active-only ⇒ old-`T` wrongly refuses). **time-anchor**: trust by wall-clock `T`, never a raw seq. **retention floor = floor-selected checkpoint** (v3.4 P2): for floor instant `F`, the checkpoint selected by `T=F` (latest `trusted_from_at ≤ F`) is protected even though its own time is older than `F`; a checkpoint retires only when its successor `trusted_from_at ≤ F` AND nothing references it. Mutation: retire by "own time within horizon" ⇒ the `C1.time < F < C2.time` case retires `C1` while `T=F` still selects it ⇒ old-`T`-soundness reds. **trash self-sufficiency**: resurrect from a trash baseline rebuilds full data + edges from the **inlined** payload (mutation: store only terminal version ⇒ resurrect-fidelity reds; if edges rely on `tombstone_ref`, prune those tombstones ⇒ resurrect reds unless they're floored).
- **autocommit-fence trap** (the §3 P1 regression test): acquire the fence via a bare `pool.query` (no txn) ⇒ the constructed race golden reds (lock released at statement end, concurrent write lands); acquire inside the real txn ⇒ greens.
