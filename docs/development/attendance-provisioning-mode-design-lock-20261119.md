# 考勤首次开通与历史角色兼容

基线：私有本地手动交付工作树，57a53c2 加未提交的同秒登录修复；不属于 B2。

| 入口 | 平台模式（含缺省） | 考勤专用模式（含 attendance-focused） |
|---|---|---|
| AuthService.register | 创建普通账号，不种考勤角色、直接权限或旧 JSON 权限 | 保留原子创建与恢复锁重试 |
| 管理员创建及邀请 | 管理员显式选角色、权限与准入；接受邀请或手动交付本身不授予考勤 | 保留现有明确拒绝记录，不拿专用模式覆盖它 |
| 成功密码登录、verifyToken、refreshToken | 不创建角色。保留 RBAC 已生效权限。现有 attendance_employee 若因缺准入被过滤，仅按旧逻辑返回原来的两个自助权限，但须读到现存角色且无撤销。仅有准入而无角色/权限不等于授权 | 沿用原来的锁内二次判断与补齐；错误密码、无有效会话的密码登录不补齐 |
| 只读权限检查 | 不写；只有现存角色需要旧兼容投影时保留原来的不确定判定，无授权的普通人不标不确定 | 保留原有语义 |

PLM 不启用。平台兼容读取必须同时看见准入与现存角色的同一快照；拒绝或 role_unassigned 优先，错误不生成权限。不得按身份、邀请来源或账户年龄猜测历史授权。不新增迁移、开关或批量修数据，不改变角色管理与准入过滤本身。历史显式 grant 继续走原授权读取。

验收：独立合成库验证注册的三处存储、密码和会话及刷新、历史角色有无撤销、普通用户只有准入、已有显式授权；复验原手动交付与同秒登录；专用模式保留撤销及并发/恢复重试见证。更新旧测试中断言旧默认值的部分，不删除原场景。不得提交、推送、部署、访问 staging。

## 独审补充边界

- 管理员单建/批建显式角色与准入不变。目录自动/手工签发的无预设邀请不是授权；接受写入先提交，再以真实密码自动登录。无准入、无员工角色：平台仍无考勤，专用模式成功登录可补齐；明确禁用则两者都不补。验证普通邀请、显式预设、明确拒绝、目录式无预设，以及自动登录失败不反转邀请消费。手动交付只换凭证。
- 平台兼容只在权威读取成功、确证**没有**准入行且持有员工角色时投影。准入开启但无有效权限不补授；撤员工而保留审批角色时，只保留审批角色实际有效的权限。读取出错或缺表不从旧 JSON 合成考勤权限；密码/会话与 routes/auth.ts 的认证资料回退均要检查。专用模式禁止错误读取触发新角色。
- 验签应在账号、撤销及已有 sid 检查后才补齐；刷新在会话登记成功后才允许补齐。无 sid 的合法旧令牌仍须过账号与撤销检查。非生产信任声明不属于本次兼容、更不作为验收；测试强制 trust 与 bypass 均关闭。
- 本授权限制的是自动授予、自动恢复，并非清理历史直接权限或改写考勤插件所有端点的授权规则。插件 `withAnyPermission` 有自己的授权读取；核对获准与撤销后的真实授权效果时，区别员工角色写入、认证资料、插件鉴权三者。若已有直接权限在禁准入时仍被插件接受，单列既有边界，不能报“所有考勤端点均已封禁”，不擅自收走历史权限。
