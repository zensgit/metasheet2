# 备料项目交付清理设计锁

依据 [#6991](https://github.com/zensgit/metasheet2/issues/6991) 和业主在该 issue 的两条补充。首版基线为 `6babc578ec`，本轮修订已对齐 `e33d447552`。R-38 的日常归档与恢复继续适用。交付清理是单独入口，由本租户的平台管理员选择一个项目执行。

| 门槛 | 验收约定 |
|---|---|
| G1 项目和影响预览 | 拉取建表、平台登记、二者兼备均可发现。显示租户、项目、受影响表和分类数量。归属不明、忙碌或预览后数据变更时拒绝删除。 |
| G2 身份和确认 | 后端复核平台管理员与当前租户；短时随机验证码一次性使用，绑定操作者、租户、项目和预览。并发确认最多成功一次。 |
| G3 事务 | 物理清理专表、托管及项目表登记，共享表仅清归属明确的行。成功审计使用同事务 appendWithin 和 project_delete，计数及标识可查。中途失败和审计失败均回滚。 |
| G4 操作验收 | 工作台提示同号试填和正式数据均删除。合成目标与两个对照验证目录、总览、侧栏、原表链接、同租户其他项目、另一租户同号和通用表删除保护。 |
| G5 调度和重建 | 清理不发起拉取。已有调度在预检得到 STOCK_PREPARATION_PROJECT_ABSENT 时跳过，手工以同号重建空表。 |
| G6 名额和租户设置 | 200 个登记含归档时创建受限，清理后释放名额。数据源绑定和批次默认配置逐项保留。 |

禁止对外部系统写入。本次开发与验证使用合成数据。验证报告按实际运行结果逐项记录。

## PR #7004 复审验收

| 原门槛 | 必须覆盖的场景 |
|---|---|
| G1、G3 归属与恢复 | 共享恢复检查点包含两个项目时应保全完整历史。已认领的旧沙箱须验证登记、托管关系和行归属，保留共享表及对照项目。 |
| G2、G3 并发 | 已升级的两个副本使用不同开关时，已开始的拉取及会写阅读凭据的请求须与删除互斥。活动跟踪不得耗尽普通业务查询的连接。 |
| G3、G4 跨租户与协同 | 一个租户的清理预览可与另一租户的普通编辑同时完成。目标记录清理后，已打开的协同文档不得在断开时写回，另一项目的协同数据须原样保留。 |
| G4、G5 重建 | 专表同号重建后必须重新审批相同冲突。共享表的审批继续有效。侧栏验证须先确认目标表和同租户对照表处于同一库，再验证删除前可见、删除后消失及同号重建。 |
