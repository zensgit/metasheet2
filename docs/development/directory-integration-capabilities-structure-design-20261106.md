# 目录集成能力状态：存储结构与只读展示设计说明 — 2026-11-06

基线：`origin/main` @ `7363f2d57`。本次只建立存储与只读观察面，不接任何消费者，不新增写路径。

## 1. 不变量

- 没有行 = 目录、登录、通知三项能力全部为关；迁移不回填、不推导。
- 能力状态不进入 `directory_integrations` 的列或 config JSON。
- 每项能力各带一组作用域锚点（租户、应用）：启用时必须存在且形状合法，未启用时必须为空；各能力的锚点互不相关。
- 生产注册表只含钉钉，三项能力都留在既有的开关与配置路径上（`legacy`）；没有任何项为 `gated`，没有任何实现可用，因此生产中两张表不会出现行。
- 开关 `DIRECTORY_INTEGRATION_CAPABILITIES_ENABLED` 默认关、只认精确字符串 `true`；它不是授权输入。
- 展示路径的判定与读取不权威：两条读语句可能来自不同快照，且不加锁；任何决定"是否允许某事"的路径不得调用它们。

## 2. 结构

| 对象 | 内容 |
|---|---|
| `directory_integration_capabilities` | 主键即集成 id；复合外键 `(id, provider)`、`(id, org_id)`，`RESTRICT`；三条锚点 CHECK（显式 `IS NOT NULL`）；形状 CHECK；修订号 CHECK；登录部分唯一索引（折叠大小写的租户与应用） |
| `directory_integration_capability_history` | 追加式；无外键；更新与删除由触发器拒绝 |
| 更新守卫触发器 | 修订号必须恰好加一；集成 id、provider、组织、创建人、创建时间不可变 |
| 迁移 | 先检查父表与两个唯一约束存在；无 `CONCURRENTLY`；锁等待 `5s`、语句时长 `5min`，结束时恢复；`down()` 在任一表有行时拒绝 |

## 3. 读取

`GET /api/admin/directory/integration-capabilities/:integrationId`

顺序：管理员鉴权 → 开关（关则 404）→ 路径 uuid（400）→ 两表是否存在（503，`to_regclass` 探测，不依赖捕获 42P01）→ 集成是否存在（404）。

响应逐字段构造，不含企业标识、应用 key、环境值、配置值或锚点值。`effective` 仅对 `gated` 项给出，其余为 `null`（本状态不治理该能力，不等于已关闭）。所有 500 为固定句，日志只记错误类名与五位 SQLSTATE。

## 4. 守卫

- 导入边界：能力模块只允许名单内的文件导入；旧登录、旧同步入口不得导入。
- 表名普查：两张表名只出现在迁移、迁移帮助文本与判定模块。
- 开关读点普查：开关只在纯谓词模块里读取。
- 真实库测试文件加入 no-DB 排除清单与 approval-db 运行清单；文件顶层的哨兵在要求数据库而无 `DATABASE_URL` 时直接失败。

## 5. 不包含

消费者解析函数、PATCH 写路径、启用前置条件的执行、历史与审计写入、前端。
