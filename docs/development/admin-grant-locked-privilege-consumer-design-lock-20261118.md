# B2 receiving actor privilege expectation

Independent design review accepts this leaf extension of the existing receiving reader. It produces a real actor-and-target prepared read on a genuine authorization root. It does not authenticate the actor, write a proof/grant or complete the broader writer graph. K-02 and all production prerequisites/purposes retain their current state.

## Input and preparation

Add required `actorPrivilege` to `AdminGrantReceivingContext`, with exactly `userId`, `orgId`, `privilegeWitness` string data properties. Accept only ordinary/null-prototype records; reject accessors, symbols, missing/extra/inherited-only properties and reflection failures without invoking getters or returning causes. Copy descriptors into a new frozen owned record; do not freeze or retain caller containers. Witness is exactly 64 lowercase hex characters with a true end assertion. Preserve existing string representability, opaque identifiers and intent normalization rules.

Preserve existing intent/phase error order. Validate the new actor record before IO. Malformed input gives `actor_privilege_expectation_invalid`; copied unrepresentable strings retain `unrepresentable_string`; valid-shaped user/org unequal to normalized intent give `actor_privilege_subject_mismatch`. All messages remain the fixed values-free receiving refusal. Capture client, exact registered privilege plan reference and copied actor expectation before the first await; never reread context properties as authority afterward.

Keep the existing sequence: genuine open token/client, actual exact-singleton `requireIdentityRead([connectionId])`, awaited registered complete-role-plan revalidation, exact actor-plus-all-target subject equality. Then assess the actor once through the actual `assessSecurityActionPrivilege` on this same tx, before R6 receiving SQL. Full witness mismatch gives `actor_privilege_witness_mismatch`; read/parse failures use `read_failed`. User/org must be explicitly bound because the privilege hash does not contain them. No class-only, token, cache, subset plan, late acquisition, MAINTENANCE or alternate executor substitute.

Both standard and high actors may yield a prepared result; neither establishes S0 or scope authority. Preserve unchanged complete target checks, including standard-only targets, high reasons, exact full witness, account/member/evidence/scope/revision gates and all-or-nothing result. Keep existing R6 SQL and target output fields unchanged.

Add only a frozen actor output `{ userId, orgId, privilegeClass, privilegeWitness, authorizes:false }` to the frozen prepared snapshot. Privilege class/witness are the fresh matched assessment. Do not add role/permission values, credentials, session data or reasons. Extend the existing private brand with the captured exact plan and copied actor expectation, without another registry or factory.

## Synchronous consume assertion

Normalize intent and shape-copy actor expectation; then preserve existing real token/client, snapshot identity, phase, token and intent/connection checks. Require captured plan identity equal to the branded plan and `tx.plan === brandedPlan.lockPlan`; otherwise existing brand mismatch with reason `role_plan_mismatch`. Check identity before dereferencing a replacement plan. Require the three actor values equal the branded copy, otherwise reason `actor_expectation_mismatch`. A valid changed actor/org under the unchanged intent is this brand mismatch, not resolver subject mismatch. Malformed input remains actor-invalid.

Snapshot and plan identities must be exact. New actor/context containers with equal values and the same genuine client/plan are accepted. Copied/JSON snapshots, structurally copied plans, another/closed root and issue snapshots refuse. The assertion is synchronous, reads no DB and creates no new authority. Same-root owners must not mutate checked classifier/identity inputs afterward.

Future issue uses phase issue without the consume assertion. Future consume performs a fresh consume-phase read and asserts it immediately before proof/grant/receipt/audit writes, keeping the same root through commit. T3 owns authenticated actor/session/browser/provenance/policy/S0/scope/access-generation and immutable proof storage. Its actor expectation must survive password comparison unchanged and be bound separately in the stored proof; recapturing it after drift is not verification. No takeover/nesting of an owned comparison transaction is authorized by this leaf.
