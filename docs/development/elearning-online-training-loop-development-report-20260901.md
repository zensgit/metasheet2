## 1. 收尾范围

按“只做最简单需求”收敛为一条线上培训闭环：

1. 管理员上传并发布视频课程与客观题考试；
2. 员工在可见课程中在线报名，或由管理员指派；
3. 服务端累计有效观看进度；
4. 播放过程中由服务端下发随机位置验证，正确响应后才继续累计；
5. 视频达到完成策略后才能开始考试；
6. 服务端自动判分，员工可查看成绩与通过状态；
7. 管理员可把经过聚合和小样本抑制的部门统计投影到系统多维表。

第 7 项是运营增强，不是员工完成课程的前置条件。线下培训、学习地图、问卷、混培、直播、AI 问答继续保持需求门控，不为“功能齐全”而扩建。

## 2. 已合入 main 的产品能力

- 视频上传、MIME/魔数校验、配额、探测及受保护播放票据；
- 发布版本、可见范围、直接/批量指派和在线报名；
- 服务端 watch session、heartbeat、完成证据及考试前置条件；
- `raster-position-v2` 观看挑战：服务端生成 `360×260` PNG，候选位置每次随机；公开 DTO 和 DOM 不暴露目标文本到答案 ID 的结构化映射；
- 客观题考试快照、答卷提交、服务端自动判分和成绩复盘；
- 管理端及员工端 Web 页面、OpenAPI、后端/Web/真实数据库 selectors；
- 聚合部门统计到系统多维表的单向只读投影、失败对账及 reconcile。

观看挑战只提高固定坐标脚本和简单 DOM 自动化的绕过成本；不宣称抵抗 OCR、视觉模型或所有 AI 自动化，也不采集人脸、摄像头、麦克风或生物特征。

## 3. 在线报名语义

报名是当前用户对可见自学课程的不可变审计意图，不等于指派：

- 不产生必修义务、截止时间、催学或容量占用；
- 不创建 assignment member；
- 可见范围收缩后不会凭报名恢复访问；
- 相同 requestId 与相同载荷重放原结果，异载荷返回 values-free 冲突；
- org、user 与时间由服务端权威上下文产生。

## 4. 多维表统计边界

云课堂专用表仍是学习数据的 SoR，多维表只承载受治理的读模型：

- 仅投影部门级聚合统计，不写入个人答案、原始观看轨迹或个人成绩；
- 分组人数少于系统阈值 5 时只写 `suppressed`，不写被抑制数值，也不伪造 0；
- 系统 base/sheet 由稳定保留 ID 管理，用户不能创建同 ID 对象或修改、删除、恢复、改名；
- 全局 `elearning:admin` 或平台管理员可读，并可使用视图、图表和导出；投影内容不能回写云课堂 SoR；
- 投影失败不回滚学习主事务，reconcile 按 `updated_at` 公平轮转失败行，避免单个毒行长期阻塞批次。
