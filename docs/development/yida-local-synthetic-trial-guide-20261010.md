# 宜搭连接器：本地合成试用指南

这是完整开发工作区中的合成操作窗口，不是客户部署包或真实宜搭发送授权。入口仅支持 Linux 非 root 用户；Windows 用户须在已准备好的 Linux/WSL 开发工作区执行，不能把 Windows 的 node_modules 复制过去。本指南于 2026-10-12 对照候选 `9a9ca90e05c99eff2bb142d4c16fbbc3e534a05d` 核实；该候选已携带 main `906840c74`，但尚未合并、部署，完整 CI 仍待终态。它是待验收的开发候选，不是已发布的客户安装包。阶段证据与限制见[目标文件 §194](integration-self-service-adaptation-goals-20260930.md#194-叠层对齐完成完整ci前置失败修复与新head验收)。

## 可以试什么

- 用临时合成账号登录实际 MetaSheet 生产构建页面，打开合成备料项目看板。
- 查看宜搭初始化状态，用私有交接文件中的**假材料**配置目标及本地草稿，手动回读和刷新查看状态。
- 查看现有字段映射与不发送的预演；不输入客户数据或真实凭据，不点击或申请真实发送。

这不是 PLM/K3 客户接入验收，也不证明宜搭远端字段、token 或业务记录已验证。合成项目中的记录刻意为 inactive；不把演示记录报成真实拉取业务数据。

## 启动前

使用完整候选开发工作区，安装其原 PNPM 工作区依赖，并确认本机已有受信任的 PostgreSQL 二进制目录。脚本会自行创建临时数据库、随机登录材料和合成账号；不接收现有数据库 URL、旧数据目录、env 文件、真实材料或外部目标。

Windows 使用者须在 WSL 内另行安装 Linux 版 Node、PNPM 和 PostgreSQL，并在独立 Linux 开发副本安装依赖；不要复用 Windows 的二进制或 node_modules。此文档所在的文档分支不含全部运行代码，实际执行须使用上面的完整代码候选。

可在 WSL 中用 `pg_config --bindir` 查询已安装 PostgreSQL 的二进制目录；若存在多个版本，要核对目录中 `initdb`、`pg_ctl`、`postgres` 来自同一版本。传入 `realpath` 解析后的实际绝对目录，不能传 Windows 路径或符号链接别名。当前合成验收使用 PostgreSQL 14；其它版本不借用该结果背书。

命令必须在 Linux 非 root 用户下执行。将下方占位符替换为实际的本地 PostgreSQL 二进制**绝对目录**，不把占位符原样运行；TTL 为 READY 后的整数秒数，限 60–900。

入口要求工作区 `tmp/` 已存在且不是符号链接。新副本可先在仓库根目录执行 `mkdir -m 700 -p tmp`；如果已有该路径，先确认它确属此工作区，不覆盖链接或借用其它目录。

```sh
node scripts/ops/run-stock-preparation-yida-synthetic-trial.mjs --help
node scripts/ops/run-stock-preparation-yida-synthetic-trial.mjs --pg-bin=<ABSOLUTE_LOCAL_PG_BIN_DIR> --ttl-seconds=600
```

初次会真实构建前后端并执行完整迁移，READY 前还不能登录。不要复用 `.env`、打开发送开关或为方便登录扩大公开绑定。该命令不是线上 `migrate`，只迁移自己新建且核对身份的临时库。

## READY 后操作

1. READY 只报告私有交接文件的位置，不打印密码、token 或材料。仅在本机查看该次文件；不要复制到聊天、PR、报告、共享日志或云同步位置。
2. 用文件的 `loginUrl` 打开一个独立浏览器页，输入其合成 `identifier` 和 `password`。忽略未配置的钉钉登录提示，使用密码登录；不要保存密码或输入任何真实账号。
3. 打开文件指向的合成看板，确认项目、初始化 ready 及发送关闭状态。假材料只取自该次私有文件的 `material`，不要替换为真实应用凭据。
4. 按页面初始化操作保存本地草稿，手动刷新/回读核对同一草稿。若返回结果未知，只用页面的手动状态回读；不要自动重做或创建第二个操作来“试试”。
5. 字段映射/静态预演不应触发宜搭 token 交换或发送。出现权限、目标或版本错误时保留固定诊断状态，不通过改角色、SQL 或发送开关绕过。

初始化写的是该次临时 MetaSheet 库，不是宜搭记录。普通浏览器的后台连接、扩展、缓存、下载和堆内容未获得自动验收浏览器的内核隔离保证；因此只允许假材料和合成业务输入，不把 Node 子进程禁止连接计数当成全机零出网。

## 正常停止与失败

先关闭本次创建的浏览器页，再在启动终端输入 `stop` 并回车，或用 Ctrl+C 请求停止。READY 后达到 TTL 也会请求停止。等待启动进程的真实终态，不只看一行状态；正常结束须有 STOPPED 且 exit 0。引导期间取消、守卫或清理失败应为非零失败，不能冒称试用成功。

正常停止会关闭应用、删除该次合成登录/材料交接文件，核对并移除脚本自有的临时数据库数据；这些临时内容不可恢复。诊断文件、构建回执与 values-free 身份侧录保留在该次私有 tmp 目录，不能直接公开原始日志。后续启动使用新的合成账号、密钥及临时库，不承诺旧草稿跨次保存。

每次试用的诊断目录位于工作区 `tmp/stock-preparation-plm-full-app-<nonce>/`。只有确认原启动进程及其自有子进程已经终止、数据库已正常停止后，才可以清理**这一次**诊断目录；若仍需排障，先私下保留日志和构建回执，不上传原文。不要把 `tmp/` 或工作区根目录作为清理目标。

异常退出可能留下该次目录中的 `trial.private.json`，其中含合成登录密码和假材料。先核实原进程的真实终态及文件确属该次运行、是目录内的普通文件且非链接，再删除这个精确文件；身份不明或仍有进程使用时先停止清理。删除交接文件不能替代数据库停止/清理，也不能把 FAILED 改称 STOPPED；不要按旧 PID 直接杀进程。

工具只针对本次创建并核对过的对象收尾；不得手工递归删除工作区、借用数据库目录或按保存 PID 杀其他进程。工具超时或观察失败不等于进程已经停止：先确认原句柄的终态；不要仅凭超时立即再启动另一份。

可信本地 PostgreSQL 引导父进程不在子进程 CJS guard 覆盖内；隐藏 worker 也不是抵御同一恶意本地文件系统 owner 的独立边界。正常启停与一次引导取消不代表已证明完整强杀、断电、内核撤销或无人值守恢复。

## 从合成试用到真实宜搭首试

下一步另行明确批准独立宜搭测试应用/表单、受管凭据输入、token 交换及 **1 条合成记录的一次发送**；由 owner 在远端人工核对记录。协议 ACK 不等于业务正确，结果未知不重试 CREATE。初始化批准不包含真实发送、生产账号/表单、客户读取、合并、发布或部署；K3 永久禁止写回。
