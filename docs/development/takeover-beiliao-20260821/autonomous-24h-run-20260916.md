## 1. 模型选择依据

- **opus + 完整对抗流水线**：凡是触及授权、租户、写路径或会让客户规则静默停火的改动（A1、A2、C1、C2、F1、F2）。流水线固定为"实现 → 两个不同视角的只读反驳者 → 修复轮 → 安全裁判"，C1 因是 RBAC 写路径额外加了一个只读测绘阶段。
- **opus 单代理**：逻辑有坑但不涉及边界的（E1：需要避开 401 分支、处理刷新风暴）。
- **sonnet 单代理**：文案与机械改动（B、裁判追加的补测试）。
- **主会话**：量测、判定不做、文档更正、合并与上机、裁判只要求改注释时的小修。

## 2. 每项设计要点

（窗口结束前补全；每项含：问题、做法、刻意不做的、对抗核验的主要发现）

### A1 自动化执行日志/统计路由补授权（#5791）
- **问题**：两条路由注册时零中间件，handler 不读 `req.user`、不读路径里的 `sheetId`，服务层只按 `rule_id` 过滤，响应还带 `ruleSnapshot`（含 webhook 地址、收件人）。
- **做法**：照抄同路径形状、已经正确的两个兄弟路由——能力门 → 表存活 → 规则归属校验（与"不存在"同体 404，不作归属 oracle）→ 响应脱敏；拒绝响应体收敛到新的 `multitable/sheet-refusals.ts`。
- **没修干净、如实写明的**：`canManageAutomation` 是全局能力位，只有该表存在授权行时才收窄——与表毫无关系的 `workflow:*` 持有者仍能读，而只读授权者反而 403。两半都被测试钉住，能力模型交 owner（#5792）。222 上无人持 `workflow:*`，现场无实际面。
- **原测试的毛病**：把能力解析 mock 成恒真后断言无认证头返回 200，等于把"没有守卫"钉死了。新套件不 mock。

### C1 角色权限写入（#5802）
- **派单时的问题**：角色管理页编辑已有角色时，`PUT` 只改名、静默丢弃 `permissions`，owner 在界面上授不了权。
- **反驳者多挖出来的**：`POST /api/roles` 传已存在的 id，会跳过改名但照常执行权限插入且**无门**——任何 `roles:write` 持有者可以给任意角色塞 `*:*`。这是 main 上既有的提权路径，本 PR 把 POST/PUT/DELETE 三个入口的提权门做成对称，一并关掉。
- **运维必读**：失效只作用于处理请求的那个进程，多实例部署下其它实例最长 60 秒**收权失败开放**；勾选框全清是真指令、无确认。

### E1 焦点刷新权限快照（#5799）
- **副产品（比原任务更重要）**：**授权即时、收权不即时**。前端快照与 JWT 声明取并集，token 里烤进了 `role`，所以降级/收权刷新页面也看不见，要等重登或 token 过期。只影响界面门控，服务端仍按库判定。已写入授权方案文档 §7f2。

### F1 审批桥续跑存活性（#5804）
- **请 owner 裁决的恢复空洞**：删表 → 审批完成 → 恢复表，那次结果永久丢失且难以人工补救（已创建审批的运行拒绝整次重试）。本 PR 保证有落账，补救需改删表/恢复路由。

## 4. 过程发现与教训

- **一条上机标记坏了六个版本**。上机核对脚本第 129 行（#5754 数据库标记）自 r48 起被反斜杠折叠打坏，Windows 路径里夹进了 0x0F、0x08、0x07 三个不可见控制字符。r48–r53 每次上机都报 6 条 PowerShell 错误并打出空值，我每次都报"标记与上一版逐行一致"——字面属实，因为两版一起坏；实质是把"一起坏"当成了"都通过"。没因此漏掉真问题，只因为同样的数据库事实另外用直连 SQL 核过。
  - 隐形的两层原因：按字面串 grep 找不到（实际字节中间夹着响铃符，终端显示时被吞掉）；自己挑的上机日志关键行没把 PowerShell 报错捞出来。
  - 处置：用 Python 按字节修复，写回前断言除 TAB/LF/CR 外零控制字符；§3.2 直连补核。以后上机日志先单独数一遍 `FullyQualifiedErrorId`，非零即停；说"与上一版一致"前先确认上一版是好的。
- **时间闸类任务要到点主动触发。** 上机窗口 18:00 开，我在等流水线通知时没看时钟，迟了 47 分钟。等待其他事件的时候，不能指望它们顺带把自己叫醒。
- **不要为了"有东西在跑"而空等。** 所有代码 PR 合完后，我一度说"等 18:00 上机、期间无阻塞"，被用户提醒后才续派 F1/F2。上机是时间闸，开发不是。
- **"一瞬全绿"会骗合并。** 监控报 `CLEAN` 的那一刻发起合并，随即有检查重跑，GitHub 拒绝。之后改成合并前先当场复核 `mergeStateStatus` 与在跑数，并把监控的完成条件收紧为"CLEAN 且零在跑"。没有用 `--admin` 绕过必跑门。
- **自己交付的文档也会错。** 授权方案文档里写了"授权后必须退出重登"，是照搬审计代理的结论；追代码后发现刷新就够，当窗口内更正（#5798）。
- **代理常常找到比派单更重的东西**：C1 派的是"界面授不了权"，关掉的是一个提权洞；E1 派的是"焦点刷新"，带回了"收权不即时"的不对称；C2 的裁判点名了第三条会往软删表写记录的车道（后成 F1）。派单时写清"只读你能证明的"，这些发现才可信。
- **反斜杠折叠在同一天里又咬了一次**：修那条坏标记时，我先在 bash heredoc 里写 Python，heredoc 本身又把反斜杠吃了。改用 Write 落文件才修成。记忆里早有这一条，仍然踩了。
