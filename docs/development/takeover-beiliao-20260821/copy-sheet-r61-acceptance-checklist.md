## 2. 复制一张备料托管表（带数据）

以平台管理员或有权限的操作员身份，选定「55 列备料主表」（首列冻结）执行复制。

### 2.1 预检（dry-run，零写）
依据：ADR §3「预检」；PR #6112 body `Summary` 结构；PR #6116「Probe rule」。

- [ ] 弹窗预检显示：源表只读展示、默认新表名、「包含数据（共 N 行）」勾选、权限固定「与源表相同」（灰显）。
- [ ] 预检披露至少包含：行数、列数；自动编号将变化的编号处数（若该表有自动编号列）；附件列 / 自链接列 / 镜像列 / 按钮列的披露（`ATTACHMENT_BLANKED` / `SELF_LINK_BLANKED` / `MIRROR_NOT_BUILT` / `BUTTON_DISABLED` / `PROPERTY_HIDDEN_BLANKED` 中命中的项，按列名展示，不显示字段 id）。
- [ ] 不复制项清单（自动化、评论、订阅、表单分享、记录锁、修订历史等）随预检展示。

### 2.2 执行复制并核对结果
依据：ADR CS-4/CS-7/CS-11~CS-14、§3、§4.3、§5、§7.3、§7.2 第 5 步；PR #6112 A2/FE-1、B7/DATA-7、B5/SEC-1 修复项；PR #6116「Success」「Badges」。

- [ ] 新表名 = 「<源表名> 副本」。
- [ ] 新表徽标含「快照副本」；源为托管表 ⇒ 追加「不随 PLM 刷新」。
- [ ] 默认网格视图：**冻结列**（首列）、**列宽**、**汇总行**（若源表配了聚合）与源表一致（PR #6112 A2/FE-1：`frozenLeftColumnIds` / `columnWidths` / `aggregations` remap 修复；R6b/E14/真库 G3）。
- [ ] 其余视图数量、筛选、排序与源表一致（视图未建列上的筛选叶子会被去掉并计入 `VIEW_FILTER_LEAF_DROPPED`，这是预期的 UX 降级，不是权限泄漏，ADR §5.2 r3-nit）。
- [ ] 用一个**受限账号**（例如只对部分列有 `field_permissions` 可见性、或只对部分行有 `record_permissions`）分别登录源表与新表，确认可见列集合、可见行集合一致（ADR §4.3「拒绝集等价断言」、§9「行级 deny 相等」测试口径）。
- [ ] `created_by`（创建人）与源表逐行一致；找一个在源表有 write-own（仅能改自己创建的行）权限的账号，确认其在新表里**只能编辑同样那批行**（ADR CS-13/§4.4；§9 write-own 测试）。
- [ ] 自动编号列已重新编号为 1..N（不是源表原值）；预检里报过的「N 处编号将变化」与实际变化处数一致（ADR CS-12）。
- [ ] 附件列存在但值为空，且有对应披露（ADR CS-11/§5.1）。
- [ ] 公式列 / lookup / rollup 列有值（不是恒为 0 或空）——这是 PR #6112 B7/DATA-7 修的坑（复制后台重算不水合 lookup/rollup 会导致「公式套 lookup」恒 0）；抽查至少一个此类列。
- [ ] 新表默认列表行序与源表一致（按创建先后，ADR §1.16「默认列表全部 `ORDER BY created_at ASC, id ASC`」、CS-13 序数时间戳保证顺序）。

## 3. 不该发生的

依据：ADR CS-19、§6、§7.4；PR #6112「Plugin scope」「Suppressed events」。

- [ ] 复制期间/复制后，**没有**为新表触发任何自动化（若能看执行记录：新表 0 条 `record.created`/相关自动化运行记录）。
- [ ] **没有**任何 webhook 出网记录归属新表（若有 webhook 投递日志可查：新表 0 行）。
- [ ] PLM 定时/手动刷新**不会**碰这张新表（它不是托管表，`plugin_multitable_object_registry` 无它的登记行；ADR §6「非托管快照」）；在「数据来源与体检」或备料托管表清单里**不应**出现这张新表。
- [ ] 若能验证插件侧读取：以插件身份（非本插件）经备料线接口尝试读新表 ⇒ 应被拒绝（ADR §6「插件作用域 hook」；PR #6112「copied-sheet-plugin-scope」）。
- [ ] **对刚才复制出来的这张新表再复制一次**（二代复制），确认二代副本同样带「不随 PLM 刷新」徽标（不会被「洗白」成普通用户表——PR #6112 B5/SEC-1 修复项，真库 G6「second generation」）。

## 4. 失败面

依据：ADR §8（失败模式表）；PR #6112 body「Errors」表；PR #6116「refusal copy」。

- [ ] **超过 2000 行的源表**：预检（勾选「包含数据」）显示超限提示行（`overLimit`），且预检本身仍是 200、仍展示结构披露；执行「包含数据」的复制会被拒绝（413，只报行数与上限，不报任何单元格值）；**取消勾选「包含数据」（结构only）复制应能成功**。默认上限 = 2000（env `MULTITABLE_COPY_SHEET_SYNC_MAX_ROWS`，未特别配置则用默认值）。（ADR CS-15/§7.5/§8；PR #6112 B8/FE-2）
- [ ] **对源表没有全表读权限的账号**：无论走 UI 还是直接打预检/复制接口，一律 403，且响应里**不带任何行数/列数或存在性提示**（`COPY_SOURCE_NOT_FULLY_READABLE`）。（ADR CS-5/§4.1/§8）
- [ ] **复制过程中改动源表**（例如另开一个窗口对源表做一次记录编辑）：复制应整体回滚，前端提示「复制期间源数据表被修改，已整体回滚，请重试」（409 `COPY_SOURCE_CHANGED`）。（ADR §7.2 第 6 步/§8；PR #6116 refusal copy）
- [ ] **快速连续点两次「复制」**：只产生**一张**新表，第二次响应带「已复制过/重放」提示（幂等重放，201 + `Idempotent-Replayed`）。（ADR CS-16/§8）

## 5. 并发与性能注意

依据：ADR §7.5、CS-15；PR #6112 终审评论第 4 条（TX-6）。

- [ ] 演示机上做复制演示时，**源表行数保持 ≤ 2000**（默认上限）。
- [ ] 复制事务执行期间，源表以及它所有正向关联（link）外表会被围栏锁住；这些表上如果同时有 PLM 刷新或插件写入，会**等待最长 30 秒**（`statement_timeout`）——**演示期间不要在复制同一张表或其关联表时手动触发 PLM 刷新**，避免相互卡顿。
- [ ] 挑一次「55 列主表」的完整复制（含数据），记录**墙钟耗时**（只写秒数/毫秒数，不写时间戳、不写主机名）。

## 6. 回滚

依据：ADR §6（非托管快照可删）；PR #6112「Flag manifest」（无布尔开关，只有数值上限常量）。

- [ ] **删除某一张复制出来的表**：直接在表操作里删除即可——它不是托管表（registry 无它的登记行），删除不受 #6089「托管表隐藏删除按钮」的限制，正常显示删除入口且可删。删除后确认没有残留的 provenance/权限/视图行（复制物是普通表，走既有的建表删除路径）。
- [ ] **该功能没有独立的开关型 env flag**（只有 `MULTITABLE_COPY_SHEET_SYNC_MAX_ROWS` 这个数值上限常量，不是 on/off 开关）。若要临时下线整个功能（隐藏入口①②、关闭路由），**唯一办法是回退到本次上线之前的代码包**（不需要回退迁移——两条迁移都只新增可空列/带默认值的列，回退代码后这些列继续存在但不再被读写，不影响旧代码运行）。

## 7. 回帖格式（发回 #6079）

只写计数 / 布尔 / 枚举 / 用时，不写主机、IP、凭据、单元格真实值、客户项目号等。建议逐项对齐本清单章节号：

- §0：迁移按名核对结果（2/2 或差几条）。
- §1：三身份 × 两入口 = 6 个布尔值；`stock-prep-operator` 是否命中「有编辑权但无 Base 写权限」的预期差异。
- §2：dry-run 披露是否完整（布尔）；新表名/徽标/冻结列/列宽/汇总行/视图筛选排序/权限一致性/write-own/自动编号/附件披露/公式-lookup 非零/行序，逐项通过或不通过（布尔）。
- §3：五项「不该发生的」检查结果（布尔）。
- §4：四类失败面命中的实际状态码/提示是否与预期一致（布尔 + 状态码）。
- §5：本次复制墙钟耗时（数字，秒）；是否观察到关联表写入等待（布尔）。
- §6：删除是否成功（布尔）。
- 任何不通过项：写清楚是哪一步、看到的状态码/错误码（如有），不要贴请求体/响应体原文，不要贴单元格内容。
