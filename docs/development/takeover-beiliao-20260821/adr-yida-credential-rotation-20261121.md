# ADR 宜搭凭据轮换

状态：设计成稿，待 Harold 裁定（R-102）。范围：222 备料的宜搭测试与正式目标。同一表单的宜搭凭据轮换是本 ADR 的对象，MetaSheet 的加密主密钥和盐重加密另立方案。

## 决策

采用**原目标下逐代重锚**。保留目标标识、槽位、应用与表单定位、租户、指定 owner、字段布局、创建防重和账本。初始化和登记继续保留第 1 代这一历史事实。为原目标追加新代际的 owner 确认凭证，当前有效绑定由统一服务端入口读取。凭证绑定原目标、凭据引用、新代际和批准记录，每目标每代只追加一次，历史轮换留痕仅保留审计元数据。新增目标或替换 owner 走各自裁定。

复用现有加密材料库与代际检查，实施时拆出共享事务能力。锁定目标及材料后校验预期代际，在同一事务更新封装材料到 `N+1`、记审计、追加重锚证据并切换有效绑定。重试按同一命令查已提交结果，同一预期代际只允许成功一次。已登记目标迁移后仍以原证据验证第 1 代，之后的所有执行路径统一验证当前绑定。发送、测试、目标读取和对账各入口需要覆盖，尤其是初始化 GET 与目标列表中用于判断是否可发送的状态。证据缺失、代际不符或解密失败时关闭出网。

原目标直接改写、给同一表单另建槽位、清库重跑 L4 都会损害已有证据或防重身份。正常轮换和故障恢复沿同一目标单调推进。已签发授权仍保留原代际和历史状态。旧代际未消费授权在恢复后失效，新代际须重预演、重新批准；已消费授权继续按持久记录查结果。清理各进程的旧代际 token 缓存、交换请求和执行句柄。每次出网以当前代际和持久维护状态为准，已发起的请求要排空或转恢复。

## 轮换窗口

1. **确认触发和范围。** 客户宜搭管理员报告计划重置、紧急撤销或执行身份变更，Harold 指定目标、执行人和窗口。一套上游凭据若被多个槽使用，全部纳入范围并逐个核对，整个受影响范围确认前保持关闭。旧系统来源已知或无法确认的凭据按暴露处理。
2. **暂停并核对在途。** 关闭发送开关并核对各实例生效，实施版还须持久禁止受影响目标的普通授权、准入、令牌交换、真实读取和表单写入。等旧进程的在途请求完结，或以进程退出和持久结果界定恢复项。页端超时只触发核对。按[准备态收尾](runbook-yida-prepared-ledger-cancel-20261104.md)和[派送恢复](runbook-yida-dispatching-recovery-20261106.md)手册分别处理 `prepared` 与进程已退出的 `dispatching`。结果不明的行转人工核对。账本和占位均保留。紧急泄露时由客户立即撤销，并行关停和记录可能已出网的范围。
3. **验证候选。** 客户在约定现场渠道录入新凭据，由锚点 owner 本人按下文的单次探针边界验证。换令牌成功仅验证钉钉应用凭据。宜搭令牌、执行身份和原表单权限由客户在宜搭侧核对。MetaSheet 侧如需真实读或试写，按各自批准另开窗口。
4. **提交并核对。** 按预期代际提交一次，事务结果查明后核对有效代际、目标一致及旧授权失效，在发送关闭状态完成多实例换代核对。计划窗口若上游允许新旧短时并存，由客户撤销旧密钥并确认旧 token 的失效机制或剩余有效期。若上游只允许直接重置，发送持续关闭，直至新代际准备完毕。备份及审计保留策略按既有受控流程执行。
5. **恢复发送。** 值班人员提交代际、状态、计数与审计位置。维护状态、受影响槽、在途核对、旧凭据撤销、当前候选验证均通过后，由 Harold 单独批准恢复。任何一项缺证据，保持关闭。发送和测试开关须分别审批。实施如需新增开关，登记到开关清单，默认关且只认精确字面值 `true`。

### 维护窗口内的候选探针

维护中的唯一出网例外是**为待轮换候选向固定钉钉 OAuth 换令牌端点提交一次申请**。轮换探针独立于初始化 L3 和发送入口，发送开关始终关闭。Harold 对一个正在维护的目标、预期当前代际、具实时集成管理员权限的锚点 owner、现场录入的本次候选和有明确截止时间的窗口批准一次。服务器锁定维护记录，原子消费单次探针批准。出网前再检查两个开关、窗口有效性、在途已核对、维护状态、代际与实时身份。任一检查失败、状态无法确认、候选变化、重复请求或窗口结束均拒绝出网。探针超时后记结果并保持维护，如需再次验证须另批。

探针只向上游提交候选应用凭据，并限定为固定的换令牌操作。服务端丢弃换得的令牌，只返回结果类别。探针不调用宜搭表单、不读取客户数据、不为正式发送缓存令牌、不更新当前有效绑定。成功证据以服务端生成的候选引用绑定完整候选、该目标、预期代际和轮换命令，并记录客户对同一目标和表单权限的核对结果。只有同一窗口内通过验证的同一候选可提交换代，换值、换代或窗口失效须重新验证。记录仅保留批准、验证状态及计数，候选值和令牌不进入日志、审计或回包。

合成验收要求发送开关关闭时，并发请求同一批准只产生 1 次候选令牌交换，表单请求和正式凭据令牌交换均为 0。错目标、错租户、陈旧代际、非锚点 owner、已撤权、改候选、已用批准及过期窗口均产生 0 次出网。注入探针超时和换代事务失败后，维护保持生效、普通发送拒绝、有效绑定保持原代际。验证成功也须等换代提交和 Harold 另批后才可恢复发送。

## 失败和回退

| 情况 | 处理 |
| --- | --- |
| 本地事务未提交，上游旧凭据仍受信且有效 | 原有效绑定仍在。保持关闭至核清事务与在途状态。如取消窗口，由 Harold 核对并另批恢复。 |
| 回包丢失或提交不确定 | 保持关闭，按命令查事务审计和实际有效绑定。以持久证据决定是否可重新提交，避免重复升代。 |
| 旧凭据已撤销、疑似泄露，或提交后第 `N+1` 代不可用 | 暂停发送，撤销不可用或不可信材料。使用新的安全凭据继续换代。已提交代际、历史授权、账本和防重占位保留，旧材料与旧 token 不恢复。 |
| 应用或数据库出现故障 | 关闭出网，用兼容当前代际的版本修复后恢复。旧版回退须先证明其在新代数据上能安全关闭。灾备恢复须先核对恢复点之后的轮换、外部创建与防重账本，再由 Harold 决定是否解封。 |

## 首发与正式入槽

11-26 测试应用交接时，继续依据[首发验证 §4.3](ipaas-yida-dev-and-verification-20261120.md)和现场清单（`first-send-20261119/window-1-2-checklist-zh.md`）处理 C-6、C-7。若测试应用凭据沿用旧系统或来源不明，由客户先轮换，再做 L4，按 O-1a 批准。若已封存第 1 代而上游随后重置，关闭发送并交 Harold 处置。正式表单入槽前，提请 Harold 确认本 ADR、批准实施，并核对轮换路径已在测试环境验收。

验收用合成材料和隔离测试目标覆盖第 1 代兼容、跨租户和非指定 owner 拒绝、并发重锚和事务失败、陈旧授权与旧 token、多进程在途、未知回执、防重占位和撤销后向前恢复。证据只记代际、状态类别、计数和审计位置。日志、审计、错误与问答都用无值证据。正式环境的任何读取、写入、开关与部署仍逐项批准，K3 写回永久禁止。

代码审阅（Codex）请复核维护门是否覆盖普通出网入口，单次候选换令牌是否只能由经批准的 owner 针对原目标与代际发起，以及换代事务、失败回退和发送恢复是否均落实该边界。
