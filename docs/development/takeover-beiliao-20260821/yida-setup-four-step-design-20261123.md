# 宜搭表单配置面板：四步改版 —— 设计（2026-11-23）

> **事项**：T-13「宜搭预演面板参数集中配置与步骤简化」。**裁定**：登记册 R-107（owner 2026-11-23）。**ADR**：`adr-yida-connection-test-20261028.md` §12（读表单字段）。
> **PR**：PR1 = 本设计第 1–5 项，分支 `feat/yida-panel-four-step-20261123`，叠在 #6812 上；第 6 项（多张表单）= PR2，另开。
> **values-free**：不含主机、地址、口令、appKey、appSecret、令牌或任何客户值。

## 1. 为什么改

11-23 非现场彩排时，备料页「宜搭静态预演（不发送）」面板有 8 步：选合同 v2 → 填样例或规则 → 只在本地预演 → 生成并存档规则草稿 JSON → 打开本地初始化 → 手动 GET 本地初始化状态 → 测试连接 → 本地初始化。参数分在两处：appType / formUuid 在预演区；appKey / appSecret / systemToken / userId / organizationId 要等预演通过、打开本地初始化后才出现，实施人员找不到。组件 ID 要手填，四项凭据其实都必填，页面却没标。

## 2. 改成什么：用户只看到四步

| 步 | 用户做什么 | 系统自动做什么 |
|---|---|---|
| 1 表单信息与测试连接 | 一处填齐七项（appType、formUuid、organizationId、appKey、appSecret、systemToken、userId），全部标 `*`；点「测试连接并读取表单字段」 | 打开面板即读服务器状态（不再有「手动 GET」）；测试连接通过后读该表单的字段列表 |
| 2 字段映射 | 左边下拉选备料字段，右边下拉选宜搭字段；单选类字段逐行填选项；勾「宜搭里是必填」 | 按字段名称自动配好能唯一对上的行；七项身份字段自动作为业务键，父组件图号自动作为允许空键 |
| 3 预演 | 默认用合成样例；可展开粘贴数据、选项目数量分配 | 合同版本固定为 v2（初始化只收 v2），用户不选 |
| 4 保存启用 | 填人工审核编号、勾确认、点「保存启用」 | 保存时自动存档规则草稿（下载一份 JSON，只含规则，不含目标、行数据和凭据） |

去掉的：合同选择（v1 / v3 不再出现在这块面板）、「生成规则草稿 JSON」与「粘贴规则草稿 JSON」两个按钮、「打开本地初始化」按钮、「手动 GET」按钮、意图选择（固定「计划创建」）。

## 3. 字段映射的规则（`apps/web/src/services/integration/yidaSetupMapping.ts`）

- **备料字段固定 9 个**：项目号、图号、名称、规格、材质、版本、父组件图号（七项身份，R-71 ⑤）、数量、优先级。列名与合成样例一致（`projectNo`、`componentCode`…）。
- **必须映射**：七项身份字段和数量。少一项就不能预演，页面用中文说缺哪个。
- **类型**：数量只能对数字字段；文本字段不能对数字字段。宜搭字段只提供单行文本、多行文本、数字、下拉单选、单选五类，且不在子表里；日期、成员、附件等不出现在下拉里。
- **自动配对**：宜搭字段名称与别名完全相同（例如「项目号 / 项目编号」「图号 / 物料编号 / 物料图号」），且只有一个候选、类型兼容，才自动填；两个同名字段留给人选。
- **业务键**：恒为七项身份字段，顺序固定。父组件图号在宜搭里不是必填时作为允许空键（顶层零件没有父图号）。这正是以后 v3 草稿必须一致的键定义。
- **选项与必填**：钉钉文档没写定义接口返回不返回选项和必填，本实现不依赖它们；单选类字段的选项、宜搭必填由操作人确认。

## 4. 接口

- **新增一项能力，不加新路径**：`POST /api/integration/yida-owner-send/initialization/connection-test` 在新开关开时可带 `form`，回复多一个 `formRead`；`GET /initialization` 在开关开时多一个显示位 `formFieldsReadEnabled`。细节、授权顺序、出网和失败分类见 ADR §12。
- **开关关时**：两个回复与此前逐键相同；页面提示「服务器未开启读取表单字段，第 2 步请手动填写宜搭组件 ID」，四步照样能走（右边换成组件 ID 输入框和控件选择）。
- **其余接口不动**：初始化 POST 的请求体、单次授权、发送开关、幂等台账全部沿用。

## 5. 护栏：没有削弱的地方

| 护栏 | 现在 |
|---|---|
| 凭据只在浏览器里 | 七项输入只在组件内存里；不进 localStorage、不进日志、不进导出；会话变化（换账号、换租户、令牌变化）立即清空 |
| 先预演后封存 | 凭据挪到了第 1 步，但服务器**封存**仍只在第 4 步，且请求必须带一份干净的 v2 创建预演（每行「计划创建」、0 无效、0 重复）。服务端这道门不变 |
| 一次 ready 读对应一次 POST | 客户端照旧：初始化前必须读到 ready，POST 消耗它；页面只是把「读」变成自动的 |
| 不重做未知结果 | 保存的回复丢了：不重发 POST，只自动重读状态（2 秒、5 秒、10 秒），确认前不能再保存；三次都没确认才给一个「重新读取状态」按钮 |
| 测试的那对凭据 = 封存的那对 | 测试通过后改了 appKey / appSecret，保存被挡住，除非重新测试或 owner 勾选明确覆盖（与旧面板同一规则） |
| 发送 | 不变：保存启用后，只有服务器报告发送开关开，才出现「打开单行 CREATE 确认」 |

页面层的两处变化，记在这里供审阅：① 旧面板「手动 GET」会清空已填凭据，新面板读状态不清空，只有服务器命令号变了才清空；② 旧面板预演一变就清空凭据（因为凭据是预演之后才填的），新面板凭据先填，改映射或预演不清空凭据。两处都只在浏览器内，服务端每个请求照旧重新授权。

## 6. 多张表单（PR2，另开）

- owner 11-23：现在没有任何单张表单在用，不必兼容旧单表单数据（R-107 ③）。
- 每张表单的映射已加密存在封存草稿里（`integration_yida_draft_operations.snapshot_encrypted`，`envelope.source` 含完整 config），PR2 只加一个按表单读回映射的只读接口，**不加迁移**，不受 R-105「新增迁移先不合」限制。
- 界面从一开始就是「表单列表」，第 1 张就是列表第一项；只有新增 / 查看 / 改映射，没有删除和替换（R-71 ①：槽永久，最多 6 张，第 2 张起多目标开关另批）。新增前先读字段、要人确认是哪张表，防止绑错白占一个槽。
- 工时约 1.5–2 天，在 #6812 合入后开工。
