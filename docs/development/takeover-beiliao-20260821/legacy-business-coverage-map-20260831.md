# legacy 备料全业务盘点与我方实现地图(2026-08-31)

> 三路并行代码盘点(控制器/页面/实体与集成),56 项业务逐一有 file:method 证据。values-free
> (legacy 源码中硬编码的钉钉/K3/SMB 凭证仅记"存在硬编码"这一事实,不复述其值,并建议客户轮换)。

## A. 已实现且真机验证(核心链)

| legacy 业务 | 我方实现 |
|---|---|
| PLM BOM 拉取/递归展开/数量累乘/批次刷新 | 只读同步 + 展开器 + **快照批次与差异**(封闭变化词表 added/removed/quantity_changed/version_changed) |
| 刷新时按 pliObjId 复用备料信息、保住人工填写 | 人工列墙(T-HUMAN-WALL)+ 幂等刷新 + **确认队列治理**(比 legacy 强:变化先裁决后落数) |
| 需求日期刷新(总图基准 − 提前周期) | 公式列(owner B 口径),真机验证 |
| 批次查看/层级展示 | 备料表 + 快照批次 tab |

## B. 多维表平台原生免费(legacy 自研且带缺陷,我方天然免疫)

| legacy(自研) | 我方(平台自带) |
|---|---|
| 双击编辑 + 服务端按角色控可编辑列 | 多维表编辑 + 字段权限 + manage-schema 拆分 |
| 乐观锁 version("被他人修改"弹窗) | Yjs 实时协同,冲突根本不发生 |
| 前后镜像 updateRecord 日志 | Time Machine 记录历史 |
| Excel 导出(**硬编码列下标,列一变即静默错位;falsy 0 判断缺陷**) | 原生 CSV/XLSX 导出 |
| Excel 导入(中文表头映射) | 多维表导入 |
| config_info 六类字典 + 颜色扩展列 | select 字段选项(pack 声明)+ 选项颜色 |
| 每用户列显示配置(tcc 表) | 个人视图 |
| 用户/角色/菜单/数据操作/列级权限五层自研 RBAC | 平台 RBAC + 角色视图 |
| **批量更新缺陷:未勾选字段被空串覆盖(采购/仓库同款)** | 无此形态,天然免疫 |

## C. 配置可解(实施期少量工作,无需开发)

1. **采购跟进 / 仓库跟进**:pack 角色视图 + 列权限(默认只开各自回填列:采购=回复日期/采购员/备注,仓库=报料/到料/发料确认/实际材料);
2. **通用件备料**(按任务单号 ZPxx 而非项目号):**第二个场景 pack**——正好是"通用化=配置即接入"设计的第一个真实验证;
3. 项目状态/类型维护:小表或选项字段。

## D. 待 owner/客户裁决的四项

| 项 | 盘点发现 | 建议 |
|---|---|---|
| **工艺信息管理** | 前端**死路由**(/craft、/section、/process 全被注释,59KB 页面无入口),后端完整 | **先问客户是否在用**;在用则一张受管表+种子建议值,不在用则不移植 |
| **钉钉待办协同**(生产/采购/仓库互发修改确认,7 天窗口,editIds 台账) | 真业务在用,legacy 核心协同机制 | 对接**自家审批流程**(B 机车道,出移交件);过渡期用多维表评论+通知 |
| **宜搭推送**(报工物料/项目号/发料确认三表单) | 在用;图纸链路已停用 | 已裁不移植;问客户报工系统的真实需求(导出可否替代) |

## E. 裁定不做——盘点**加固**了裁决

- **K3 写入全家**(物料/BOM/生产任务/投料变更 ECN/采购订单):G-4 永久禁写。盘点证据:全部是**硬编码测试数据的原型**;单据拼号**无流水号自增,连续生成必重号**;采购订单写入标注"todo 未完成",组装后从不发出。**legacy 的 K3 写入本来就没跑通,我们禁写不损失任何在用功能**;
- **MRP/采购建议**:legacy 只到"建议列表",从未闭环下单;两版口径还不一致(锁定量一减一不减),旧版 @Deprecated 仍可调;
- **定时任务**:全工程**零个**——所谓"自动同步"不存在,一切靠按钮。我方按需刷新模型与之等价且更可控;
- **死数据层**:工段领料(pick_info)、基础物料档案关联——legacy 规划后放弃,不移植。

## 提醒客户两件(实施时提)

1. legacy 源码硬编码了钉钉/K3/SMB 凭证(值不复述)——建议轮换;
2. 工艺/工段/工序三个页面是死路由——确认业务上是否已弃用。
