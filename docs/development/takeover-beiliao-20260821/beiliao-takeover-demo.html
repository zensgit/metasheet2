② 拉取新批次时,发生了什么

旧系统（今天）

  • 先插新批、后删旧批,采购/仓库值靠 BeanUtils 拷贝到新行
  • 无事务:中途失败会留下半新半旧数据
  • 借用件的历史填写靠 reuseStockInfoExistsInDb 取最近一次

MetaSheet（接管后）

  • 按 pliObjId 幂等重同步:同行原地保留,新键才插入
  • 单事务:要么全成、要么回滚,永不半批
  • 采购/仓库是同一行的列,天然不会丢——拷贝逻辑消失
  • 借用件沿用同一条"取最近填写"规则,行为一致

同一套业务规则,去掉旧代码里最大的正确性风险(无事务的插入-删除批次交换)。手工新增的行(无 pliObjId)也会被重新挂到父组件下保留。

接管第一天,顺手关闭的风险

  • ✕
    现系统 SecurityConfig /** permitAll + TokenFilter 被注释 → 所有接口匿名可达
  • ✕
    /erp/* 的 K3 写端点(Material/Save、BOM/Save、PD/Save…)全网匿名可写
  • ✕
    登录明文比对密码;数据库 / K3 / 钉钉 / SMB 凭据明文存配置
  • ✓
    接管后:统一鉴权 + 只读对接 + 加密凭据,以上入口当天关闭

迁移不丢功能:BOM 拉取、共享网格、批次复用、需求日期、钉钉待办、Excel 导入导出全部保留;被迫停用的 Excel 导入(因缺 pliObjId)也可重新启用。
