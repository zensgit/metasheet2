## 已确认事实

1. Issue #6395 维护者在评论 6161876950 确认，总览实际参数下的 `timezone-context/me`、`rules/me`、`effective-calendar` 全部返回 `422 / ATTENDANCE_TIMEZONE_DEFAULT_REQUIRED`。不是裸接口请求造成的 400。
2. `attendance-timezone-companion-store.cjs` 的 `readLegacyFrozenV2`（约 L36）只复用有完整 V2 计算及归属快照的旧记录。`assertTarget`（约 L119）与 `attendance-timezone-runtime.cjs` 的 `readTargetTimezoneContext`（约 L640）会对其他已存在记录返回 `409 / ATTENDANCE_TIMEZONE_FROZEN_CONTEXT_MIGRATION_REQUIRED`。此行为不受多时区 OFF 保护。准确范围是缺少可验证冻结上下文的旧日期，不是所有旧日期。
3. `attendance-timezone-runtime.cjs` 的 `prepareSourceChange`（约 L845）发现组织缺默认规则时，只要有有效排班、轮班、伴随快照或未结束出差安排，就返回 `503 / ATTENDANCE_TIMEZONE_DEFAULT_MISSING`。因此“通过 UI 保存默认规则即可恢复”只对空白组织等满足守卫的情况成立；仅未来排班也会阻塞。
4. `index.cjs` 的 `applyLivePunchProjectionLegacyV1`（约 L23200）保存旧归属标记；`attendance-work-date-resolver.cjs` 的 `buildFrozenWorkDateAttribution`（约 L311）仅存归属与证据引用，不保证有完整规则。普通记录可只有存储时区、日期、首末打卡和统计结果。不能从这些字段推导完整的旧迟到、扣假、舍入及计薪规则。

## 推荐决策：受控补齐，保留可验证的原始上下文

三种原始选项中推荐“受控回填”，但不允许猜测缺失历史：

- 完整 V2 快照：复用现有严格校验路径，不改写旧计算。
- 可从可信历史配置或备份证明原规则的旧记录：先输出只读计划，包含记录版本/摘要、来源证据、旧日期/时区和拟冻结窗口；授权后在事务内校验未变化，再追加上下文。保持原事件、日期、时区及已结算结果不变；幂等重放不重复写入。
- 证据不足的旧记录：列为人工确认项，不能拿当前规则冒充旧规则。尤其未下班的旧班次不能靠公告或“只读历史”忽略，须在升级前有已验证处理方案，否则阻止升级。
- 创建组织默认规则必须有明确管理员输入和组织权限；兼容已有排班，保留未结束班次及已冻结记录。不能把现有守卫整段删掉，也不能通过普通 GET 自动写默认值。
- 默认规则普查与历史上下文普查都应进入发布前检查。检查失败阻止发布；目标环境检查也需单独授权。

这不是“按保存的 timezone 直接拼一个当前班次”：时区可靠不代表历史计算规则完整。也不建议接受故障后公告，更不采用刷新、隐藏控件或静默 UTC 回退掩盖它。
