# 首次改密后同秒重新登录

独立于邀请业务与 B2。保留邀请真库 40 项的失败断言、现有撤销水位、严格会话检查和首次改密要求；不靠等待、未来 iat 或放松边界。

1. 在 user_session_revocations 上增加不复用的数据库修订 UUID。新增和每次更新均由数据库生成新值，包括冲突更新、身份修复及相同时间值；旧行具备初始值。仅迁移独立合成库。
2. 本地密码登录在验证哈希之前取得用户绑定的撤销修订（无行也是明确状态），一起绑定到这次密码验证；签名 session JWT 私有声明只由服务器生成，要求有 sid。绝不在验证旧密码之后重读新修订补发。对于读后并发改密，旧快照与当前修订/现有代际不同时拒绝。密码更新与撤销写入的实际顺序、会话登记和缺失模式必须核实。
3. 带新声明的凭据只有当前修订完全相同才可用，同时保留签名、用户、有效 session、禁用及代际等既有检查；无行状态不能匹配任一实际修订，畸形/未知/数据库不可用拒绝。旧 token、无 sid token、其他签发方式不获得新例外，按旧水位判定。刷新不得把旧验证升级到新修订，不得复活旧 sid。严格/普通/敏感证明相关校验需要逐个核对；证明创建后的独立撤销检查不取消。
4. 验收：固定时钟同一秒的真实改密前后 credential；旧 token、旧密码、旧 token refresh 均拒绝，新密码获得的 token 直接访问受保护入口，第二次撤销也立即失效。旧格式仍保守；相同时间连续更新、回滚、并发旧认证不得复活。保留原红灯证据、在独立合成库实际运行手动交付全部 40 项且零跳过。先设计独审，再改产品；不提交、不推送、不部署、不操作 staging。
5. 首次改密原先是两个独立写入，还会签发回执 token。改为同一事务锁用户，验证请求所依据的密码/会话状态仍有效，更新密码并推进撤销修订，失败全部回滚；回执只携带本事务返回的修订，不在提交后重取最新值。真实验证回执 token 及用新密码重新登录的 token。权限、其他用户和组织不变。
6. 默认和别名登录均在最终用户行的同一 SQL 快照读取用户 ID、密码哈希、代际和修订。无行不等于读取失败。刷新原样继承修订；无修订的旧凭据仍无修订，登记时须按输入的原始撤销证据作最终判断，并保证派生 token 不借刷新后的新 iat 跨过并发撤销。固定两种交错：已读旧哈希后改密，及旧格式 refresh 初检后、登记前撤销。相同时间不能靠放宽比较通过。
## 本地验收

原手动交付测试文件与封存副本字节一致，40 项全过。独立合成 PostgreSQL 另跑 3 项：固定同一 JWT 秒的首次改密和直接访问，以及旧密码、旧格式刷新在会话登记等待期间遇到撤销。两文件共 43 项，逐项通过，无跳过。原失败报告保留；未运行远端 CI、浏览器或 staging 验收。

此次包含数据库迁移；新签发与所有校验者必须按同一协议运行，不应以新旧实例混跑作为验收。以后若部署，须另行安排迁移和实例切换；有已签发凭据时不能把回退数据库列当作安全回滚方案。本次没有执行这些操作。
