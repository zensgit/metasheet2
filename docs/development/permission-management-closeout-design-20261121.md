# 权限管理收尾设计

基线为 `bac4883241b9ed27a0f33efb4ee5dac7d1d41972`。已合入的授权命令、权限来源、业务检查器及 Windows 升级路径见[权限管理 v1.1 实现记录](permission-management-v1-1-implementation-20261120.md)。

## 部门范围保存

成员部门范围和模板部门编辑的写入规则相同。

| 请求 | 已有范围 | 结果 |
| --- | --- | --- |
| 省略 `includeChildren` | 无 | 新范围包含下级，沿用旧客户端默认值 |
| 省略 `includeChildren` | 有 | 保留锁内读到的原值，精确部门开关关闭和开启时都适用 |
| 显式 `true` | 任意 | 包含下级 |
| 显式 `false` | 任意 | 只有精确部门开关的值为字面量 `true` 时才保存 |
| 非布尔值 | 任意 | 返回 400 |

旧客户端重复提交“添加部门”时，若该条目已经是仅本部门，省略字段会保留该设置。扩大范围必须明确发送 `true`。读取既有范围沿用数据库里的布尔值。

## 范围模板应用

模板详情返回 `scopeVersion`。版本由模板 ID、排序后的部门 ID 及其包含下级标记、排序后的成员组 ID 计算，覆盖实际应用的配置。成员组成员和部门层级仍由各自的读规则实时解析。

管理范围页将所查看的版本作为 `expectedScopeVersion` 提交。服务端锁住模板，并读取部门及成员组后做比较。版本过期返回 409，发生在范围替换、合并和委派状态初始化之前。页面清除过期详情，引导管理员重新读取并主动提交。页面没有可用版本时会禁用覆盖应用。

保留旧 API 调用方省略 `expectedScopeVersion` 的行为。带版本的请求要求 64 位小写十六进制字符串，格式错误返回 400。版本用于确认模板内容，操作者、目标成员和命名空间的授权检查继续按写入时的实际状态执行。

## 考勤角色模板

考勤的单人和批量授权入口都提供员工、审批人、导入员和管理员四种角色模板。正式接口继续接收模板 ID。旧版全局后备入口使用同一份权限清单，导入员包含读和导入，管理员包含读、写、审批、导入和管理。

兼容入口逐项处理直接权限，因此无法保存角色来源。仅在已有规则识别出全局接口缺失、且当前账号是平台管理员时使用。组织范围请求和业务错误不触发直接授权。

Grok 4.7 medium 实现前端下拉、权限清单及相应的页面用例。模板事务和授权边界由 Codex 实现及复核，使用真实数据库验证并发结果。

### 运维脚本

`attendance-provision-user.sh` 支持导入员。导入员是读加导入，管理员是读、写、审批、导入和管理。调用正式角色入口时验证角色 ID 和权限；仅在确认旧接口缺失时使用既有的直接授权兼容路径，随后独立回读完整权限清单。

## 角色目录与管理员能力复核

权限来源页面的能力读取使用数据库中的 `user_roles.admin`，历史撤权写入也要求有效的该角色。管理范围和成员管理保留已记录的原始管理员字段兼容规则。角色目录的权限码写入仍有自己的兼容判定。后续须核对该判定和服务器写入口，确定哪些通配符只是权限码，以及哪些平台动作要求当前数据库管理员身份。

保留插件权限的既有语义。业务权限检查以已注册的实际路由为准，通用预检和旧版兼容入口各自按其契约判断。

## 发布边界

上述改动不需要新数据库迁移。发布检查继续使用默认关闭的 `DELEGATED_SCOPE_EXACT_DEPARTMENT_ENABLED` 和 `DELEGATED_SCOPE_ACTIVATION_ENABLED`。开启任一开关前须确认旧权限进程全部退出，并按[独立委派启停](PERMISSION_DELEGATED_SCOPE_ACTIVATION_20261118.md)测试启停、权限缓存的刷新和恢复。
