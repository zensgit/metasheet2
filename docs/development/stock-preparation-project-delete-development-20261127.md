## 操作与影响

管理员在备料工作台打开要清理的项目，选择「删除项目（含全部备料数据）」。预览显示当前租户、项目号、实际涉及的表和分类数量。同一项目号的试填与正式数据都会进入预览。管理员逐字输入服务端签发的 8 位验证码后提交。成功后工作台刷新目录和侧栏；过期、验证码错误或数据变化需要重新预览。

| 数据 | 判定和处理 |
|---|---|
| 专属备料表 | 以租户、项目号、确定性对象 ID、项目表登记及托管登记相互核对。物理删除专表、手工行、回收站记录和关联登记，释放登记名额。 |
| 平台登记、共享备料表 | 从登记行的项目号向内关联批次、快照行、备料明细、异常和运行，再反查是否有其他项目引用同一批次或行。仅移除归属明确的行。已知旧版无登记的共享表还要验证服务端绑定和租户专属系统库。 |
| 待办、刷新和后台作业 | 处理确认记录、交接、刷新台账、项目拉取批次及可归属的终态后台作业。活动写入、无法归属的旧作业、跨项目引用会阻止整笔删除。旧写入计划的代次同时失效。 |
| 独立依赖 | 对受保护的恢复历史、仍受外部订阅或授权引用的专表、未清除的附件实体等返回冲突。管理员需先在所属功能内处理依赖。 |
| 保留数据 | 其他项目和租户、共享表本体、模板、历史审计、租户级数据源绑定和批次默认设置。整个请求只访问本地存储。 |

历史沙箱的项目登记可能指向一张被多个项目使用的表。清理时核对租户、登记、实际表及插件托管关系，只移除可证明归属的行和当前项目的登记。共享表及其托管关系保留。只要目标行属于恢复检查点，预览就拒绝清理，保留整张表在该检查点的原始状态。

专表的表级冲突审批纳入预览指纹，在确认事务中清除。同号重建后的相同冲突需要重新审批。共享表和其他项目的审批继续生效。

## 实现入口

| 接口或模块 | 职责 |
|---|---|
| `GET /api/integration/stock-preparation/project-delete/access` | 当前会话的可见性探测。 |
| `POST /api/integration/stock-preparation/projects/{projectNo}/delete/preview` | 提交空对象，返回租户、项目、影响清单、验证码和过期时间。 |
| `POST /api/integration/stock-preparation/projects/{projectNo}/delete/confirm` | 请求体只含 `challengeId`、`code`，成功返回数量和审计 ID。 |
| 插件 `stock-preparation-project-delete*.cjs` | 控制挑战、活动锁、表及其依赖、业务台账、后台作业的盘点和清理。 |
| 宿主 `stock-preparation-project-delete-authority.ts` | 要求登录凭据已证明当前租户，再在数据库事务内复核平台管理员和本租户有效成员身份。仅凭请求头选择租户会被拒绝，即便管理员是两个租户的成员。 |
| 宿主 `stock-preparation-metadata-cache.ts` | 读取确定性编号表的缓存前核对实际表版本，防止另一进程在同号重建后给出旧字段或视图。 |
| 前端 `StockPreparationProjectDelete.vue`、`projectDelete.ts` | 预览、输入、确认、租户切换处理和成功后的缓存失效。 |

同一预览绑定操作者、租户、项目、数据指纹。数据库时钟控制五分钟有效期。确认以原子方式领取验证码，重算盘点后在一个事务内删除数据并通过 `appendWithin` 写入 `project_delete`。审计保存操作者、时间、租户、项目和分类计数。已有调度从不可改写的成功审计与当前项目登记判断项目是否仍然缺失；关闭清理入口后，此判断继续生效。主动重建产生新的有效项目根记录。

## 启用与回退

开关为 `STOCK_PREPARATION_PROJECT_DELETE_ENABLED`，默认关闭，只接受小写精确值 `true`。先完成迁移，再升级处理拉取、写入、协同编辑及清理的全部进程。升级后的副本即使关闭删除入口，也会在拉取、后台持久化及会写阅读凭据的 GET 请求期间持有活动锁，此时可以分别开启各副本的删除入口。旧版本二进制缺少这些协议，升级完成前应保持入口关闭。入口关闭可停止签发和确认。项目清理成功后没有业务级撤销。

迁移 `zzzz20261127090000_stock_prep_project_delete.ts` 创建验证码表，扩充审计动作 CHECK。回滚会检查既有审计；存在成功删除证据时拒绝缩窄 CHECK，以保留审计链。在同一批次合并后续迁移的环境，按仓库迁移顺序处理。

备料写入通过独立的 PostgreSQL 连接池持有会话级活动锁。通常按租户和项目加锁，无法从请求证明项目号的任务使用租户级锁。每个副本按需建立最多四条活动连接，上限也受主池配置约束。业务查询继续使用主池。单条盘点语句的超时为 15 秒，删除事务的预算为 30 秒。

旧格式的后台试算记录可能缺少项目归属字段。已升级应用的启动和查询入口在持有活动锁时处理这些记录。直接向数据库写入这种旧格式时，触发器无法推断项目；现场工具应通过应用入口操作。盘点发现无法证明归属的遗留作业时会拒绝清理。

协同文档以记录的创建代次识别所属行。清理覆盖目标记录的 Yjs 快照和增量。打开的旧文档在写增量或断开保存时复核代次，即使重建后复用了同一个记录 ID，也会拒绝旧写入。普通回收站还原继续使用保存的协同内容。

预览在 PostgreSQL 的 `REPEATABLE READ` 快照中盘点，并保留对在途备料写入的检查。用户浏览预览期间可以继续编辑。确认在 `READ COMMITTED` 事务中锁住此次清理涉及的表标识、业务范围及目标记录，重新计算指纹。普通写入和删除同时触及受保护的范围时会立即报忙。其他租户可以继续修改自己的表。

复审新增的迁移按顺序为记录创建代次、通用表写入协调、备料台账写入协调和运行状态 KV 写入协调。回退应先关闭所有副本的删除入口并结束在途操作，更新应用到与目标 schema 匹配的版本，再按相反顺序回滚。先移除 KV 和备料台账触发器，再移除共用的协调函数。已有成功删除审计时，首次迁移的审计动作约束必须保留。
