# #6404 输入身份修复约束

用户已批准修复 #6404；本轮允许隔离开发、更新现有 PR、验证及 CI，不允许合并、部署或启用。基线 e264eb952210ae8591210314db45795ad70c1bfd / main 2fc0527bd6。

## 行为保持与修复

- UUID 保留当前规范化快路径。非 UUID 仅能解析成当前组织内明确活动的员工；用户和组织成员活动字段是必需授权 schema，缺失即拒绝。
- username/mobile 为可选别名字段，缺失只减少别名能力，不删除授权谓词。查询失败使用固定安全错误，warnings 不含邮箱、手机号或原输入值。
- 输入与候选用同一 JS trim/NFKC/lower 规则终判；SQL 必须提供该规则的候选超集，不依赖部署环境可选 ICU collation。跨不同字段多员工归属拒绝；同一员工多个字段命中只算一人。
- 一次线性建立索引，碰撞集合最多保留两个不同 owner；正常与碰撞密集数据均不得重复扫描全部员工。
- actor 能力检查保留；scope 角色授权与后续处理复用规范身份。内部 Map 不进入公开响应、payload、冻结计划 JSON 或持久任务。
- 上传 CSV 与手工 rows 同时存在时，以现有执行选择的 CSV 为准；授权、估算与执行统一来源。内部集成构造的 rows 入口不引入不可能的文件配置。
- 模板下载仍服务器 CSV 优先，故障时 guide 再 builtin；加入 UserId 与映射表头，保持 BOM、picker/prefs，并逐字节保持手改或非法 JSON payload。
