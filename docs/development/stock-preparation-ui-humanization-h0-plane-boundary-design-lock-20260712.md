# 备料 UI 人性化 — H0 平面边界设计锁(evidence-plane vs authorized data-plane)— 2026-07-12

> **状态:PROPOSED / owner-ratification-required。** 本文是 UI 人性化线(路线图 C 层)的**第一刀**,
> 锁死**两个数据平面的边界**,后续 H1-H4 全部在此边界内实现。**不请求编码;H1-H2 在证据面实现无需等本锁,
> 但 H3(值面读)必须等本锁 ratify + OD-W3-1 授权。**

## 0. 为什么先锁平面边界

备料线全程守住 `values-free`:证据/摘要只含**字段名 / 计数 / 状态 / 布尔 / 不透明 handle**,
不含图号 / 数量 / 单位 / 物料名等**业务值面**。这是安全资产,不能在"让 UI 更好用"的名义下悄悄放开。

但一个只显示计数和枚举的备料工作台,对操作员是**不够用**的——他需要知道"这个项目、这个阶段、
卡在哪、下一步做什么"。**H0 的任务:把"更好用"拆成两半——哪些能在证据面直接做(无需授权),
哪些是业务值面(必须 RBAC + 白名单 + 审计才给看)——并钉死后者的门。**

## 1. 两个平面(硬定义)

### 平面 A — 证据面(evidence-plane,values-free)
**内容**:计数 · 闭合枚举/状态 · 布尔 · 不透明 handle(projectId / snapshotBatchId / sha16)· 阶段 · 错误码/字段名。
**永不含**:图号 · 设计量/领用量 · 单位符号 · 物料编码/名称/规格 · ERP internal id · 凭据 · host · tenant · 原始行。
**授权(owner review 纠正:证据面≠"全站可见")**:平面 A 仍是**已认证 + tenant/workspace/project scoped +
**遵循各路由现有权限**——**不是**"read 门即可全站可见"。当前实际权限:
- **H1 项目概览**(`GET /projects`)= **read** 门(现状即 read)。
- **H2 六阶段明细**(snapshot-batches / material-mappings / unit-conversions / prep-lines / exceptions)
  = **`requireAccess('admin')`(现状)** → **H2 暂时保持 admin-only**;非 admin 只见 H1 概览。
**H1-H2 全部在证据面(values-free)**——用计数/枚举/handle/布尔表达,不需业务值——**但各自沿用其路由的现有权限,零放宽**。
**若日后要让普通 read 用户查看 H2**:必须**单开授权契约 / 聚合端点切片**(独立设计+审阅),**不得在 UI PR 里顺手放宽路由权限**。

### 平面 B — 授权数据面(authorized data-plane,业务值面,H3,gated)
**内容**:项目名 · 图号 · 物料编码/名称/规格 · 设计量/领用量 · 单位换算前后 · **经白名单的**异常业务字段 + 结构化原因(枚举/字段类别)。
**异常上下文明确排除(P2)**:上游异常 `message` 原文 · 原始响应 · payload —— 这些可能含 host / 单号 / 敏感串,**永不**经值面读暴露(即使对授权用户)。异常只给**白名单业务字段 + 结构化原因码**,不给原始报文。
**门(三重,缺一不可)**:
1. **RBAC**:仅特定角色/权限可读(不是 read 门,是单独的值面读权限)。
2. **字段白名单(server-side projection,P2 硬约束)**:逐字段声明哪些值面字段可暴露给该角色(不是"放开整行")。
   **RBAC + server-owned 白名单必须在服务端响应序列化*之前*执行** —— **禁止**返回完整行后由前端隐藏,
   **禁止**请求端提交任意字段列表(白名单是服务端拥有的,不接受客户端指定)。**值面结果不得进入日志 / telemetry / 共享缓存 / 错误消息。**
3. **审计**:每次值面读**写审计轨**(谁 / 何时 / 读了哪个项目的哪类值面);审计轨本身**仍 values-free**
   (记字段类别/计数,不记读到的具体值)。
**gate**:OD-W3-1 决策 = 允许 + owner 单独授权。**默认关闭。** 本锁不开它,只定义它的门。

> **⚠️ H3 的两把门当前都不存在(owner review P1)—— H3 前必须先做 H3-0 契约基础切片:**
> 现状:`requireAccess()` 只认 `read/write/admin`,**无独立值面读权限**;`integration_stock_prep_audit`
> 只有 8 种**决策写**动作(store + DB CHECK 都是闭词表),**无值面读取动作**。因此:
> - **H3-0(契约基础,新 runtime surface,非纯 UI)** 必须先落:① 定义**独立 value-read 权限**(不复用 `integration:read`);
>   ② 扩展审计 action + migration CHECK + store 注册集 + 漂移测试(纳入值面读动作);
>   ③ **审计写失败 → 不得返回值面结果**(fail-closed:先写审计成功,再出值)。
> - **H3 是新增 runtime surface,不能称"纯 UI H3"** —— 它引入新权限 + 新审计动作 + 新读投影,须走完整对抗审阅门 + 真库证据。
> - H3-0 未落地前:**H3 值面读一律不实现**。

## 2. 不变量(H1-H4 全程强制)

- **I1**:平面 B 的存在**不降低**平面 A 的 values-free。日志 / 审计 / smoke / issue 证据**永远 values-free**,
  即使 UI 给授权用户显示了业务值——**"给人看"和"记进证据"是两回事**(这是备料线一贯纪律)。
- **I2**:平面 B 是**逐字段、逐角色、带审计**的读,**不是** "把 values-free 关掉"。没有"全局值面开关"。
- **I3**:externalWrite 与本线**无关**——UI 人性化**只读+只写内部表**,永不触外部写(那是 D 层 / #4194)。
- **I4**:任何值面渲染路径必须**同时**满足 RBAC + 白名单 + 审计;缺任一 → fail-closed 回落证据面。

## 3. H1-H4 在边界内的落点(概览,细节各自设计锁/切片)

| 层 | 平面 | 内容 | gate |
|---|---|---|---|
| **H1 任务化入口** | A 证据面 | 进系统即见"当前项目 / 当前阶段 / 阻断数 / 推荐下一步";项目选择器(handle + 状态 + 计数) | read 门 |
| **H2 备料流程状态** | A 证据面 | 六阶段进度(provision→sync→map→unit→generate→exception)、每阶段计数/阻断、跨阶段导航 | **各路由现有权限;H2 明细现为 admin-only** |
| **H3-0 契约基础** | — | **前置**:独立 value-read 权限 + 审计 action/CHECK/store/漂移测 + 审计写-fail-closed(**新 runtime surface**) | owner + 对抗审阅门 + 真库 |
| **H3 授权值面读** | **B 数据面** | 白名单业务字段(项目名/图号/物料/数量/单位)+ 结构化异常原因;映射 PLM↔ERP 左右对照;单位换算前后;机器码折叠到专家详情。**排除上游 message/原始响应/payload** | **H3-0 落地 + RBAC + server 端白名单投影 + 审计 + OD-W3-1 授权** |
| **H4 响应式 + 可用性验收** | A(+B if H3 开) | 桌面/平板、键盘操作、错误重试、长表格;截图验收 | read 门(值面部分随 H3) |

## 4. 与既有面的关系

- 承接前端审计(2026-07-12):6 视图已 values-free 建成;H1-H2 是在其上加**人性化的证据面导航**,不改 values-free。
- H3 是 **OD-W3-1** 的产品化落点——**唯一**开放业务值面的路径,且必须走本锁定义的三重门。
- **值面读若要接真实外部数据**,还叠加 #4194(真实外部对接线)的 gate——两把锁**都**要过。
