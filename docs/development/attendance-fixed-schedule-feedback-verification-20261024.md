本报告对应客户反馈审阅中确认的两项 P1、两项 P2，范围为考勤组固定排班编辑器。客户安装版本未知；本轮证据来自 Mac mini 独立源码目录、合成数据和独立 PostgreSQL，不代表客户环境已修复。允许 Draft PR 和 CI；合并、真实回填、部署、启用仍须另批。

## 修复与验收

| 问题 | 修改 | 验收要求 |
| --- | --- | --- |
| P1：重新进入或切组后回到最新班次与当天日期 | 新增受权限约束的编辑器读取，恢复服务端已保存配置；无配置时不推断班次和日期 | A/B 组、未配置、列表外班次、跨组织和延迟回包 |
| P1：修改固定排班只能撞到配置冲突，缺少保存入口 | 显式保存配置；保留 PUT 并提供共享处理器的 POST update；新 UI 始终提交期望版本 | 首次保存、更新、零成员、无变化保存、过期版本和并发首次保存 |
| P2：多段能力关闭仍允许发起应用／重建 | 从服务端真实组织策略及持久班段读取资格，显示原因并限制操作；写端守卫保留 | 关闭与允许正反例、不可读依赖、不能用班次 DTO 代替组织策略 |
| P2：周矩阵把分段班次显示成连续时间 | 复用完整班段格式化 | 显示午休间隔、跨夜次日；不改变已正确的分钟计算 |

保存只更改期望配置，不生成排班、考勤事件或权益；应用／重建仍是显式动作。历史管理排班只能按用户选定的准确班次和日期窗口清除。目标消失后保持不可用，不自动改为清除新配置。缺少有限结束日期的历史集合不推断日期。

切组、组织、候选项和版本变化后，旧回包不能改写新界面；这不撤销已发出的合法服务器写入。保存后回读发现另一管理员更新时保留草稿并提示冲突。重建后的排班列表刷新同样有范围和请求序号保护。
