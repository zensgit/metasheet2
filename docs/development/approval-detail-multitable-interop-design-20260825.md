## 1. 判据:审批明细是「证据」,多维表行是「活数据」

审批实例提交后进服务端**不可变 `form_snapshot`**(FWB 锁 D4 明文依赖)。多维表行是持续演化的
协作状态。两条公理:

- **A1(冻结边界)**:任何互通设计必须保持「提交即冻结」;不存在审批单↔表的实时双向同步。
- **A2(三缝原则)**:关联记录(引用进)、FWB(批准后快照出)、automation 桥(表事件触发审批)。
  新能力必须落在三缝上,不开第四条。

三相成本分析(为何不做「表单内嵌可编辑网格」):提交前 1~20 行/单人/分钟级——嵌千行级协作网格
是阻抗错配;**审批中**要把按节点字段权限(#5143 已交付)投影到按人/角色的表权限——两个权限模型
的乘积,是嵌表方案的真实硬核成本;审批后「数据进表」已被 FWB 解决。宜搭「平铺方式」是表格在
移动端不成立的自供状——嵌网格同样要接这道题。

## 3. v1.1 原生补刀(轻明细,零架构变化)

范围:①复制行;②上/下移;③删除确认;④xlsx 批量导入到原生明细行(复用考勤 xlsx-guard;借鉴
宜搭边界:公开免登表单禁用导入);⑤序号列。

**行数边界合同(v3 扩为全路径统一,审阅 P2-2)**:
- 现状:`maxRows` 可不填,服务端仅校验非负整数,**无系统硬上限**;`minRows≥1` 时发起页初始
  仍播种空数组(不自动出首行)。
- 合同:引入**系统明细行上限**(数值待裁,建议 200),**单一定义常量,FE/BE 共用**;生效上限=
  `min(字段 maxRows, 系统上限)`,并在**全部六条路径统一强制**——①模板保存(明细配置校验)、
  ②发布(同)、③发起页 minRows 播种(播种数 ≤ 生效上限,且 `minRows>0` 时真实播种 minRows 行)、
  ④手工添加(按钮到限即禁)、⑤批量导入(超限**整批拒绝**并报明细,不静默截断)、⑥**提交**
  (服务端对实例行数终检——前五道全是 UX,这道才是合同)。只限导入即留五个旁路,不成立。

**行操作口径(v2 澄清,审阅第 6 条)**:v1.1 的行动作=复制/上下移/删除确认的**固定闭集**,系统
内置;「自定义操作列」(模板作者自配动作/绑定回调)仍**不做**(§6a)。两者不是一回事。

## 4. FWB v2:明细行展开投递(审批→表)

一单明细 N 行 → 目标表 N 行。

**幂等(v3 补全迁移合同,审阅 P2-1)**:不另立键。既有账本 `meta_fwb_action_applied` 业务键为
`(instance_id, rule_id, action_key, node_key, entry_epoch, application_mode)`(唯一索引
`uq_fwb_action_applied_business_claim`;哨兵约定已覆盖 FWB-1/2/3)。v2 延展一列 `row_index`,
**完整合同**(缺一不落锁):
- **列定义**:`row_index INTEGER NOT NULL DEFAULT -1`。哨兵 `-1` = 非展开动作(沿既有
  `node_key=''`/`entry_epoch=0` 哨兵风格);展开动作写冻结快照内行序(`>=0`,快照不可变故稳定)。
- **约束**:`CHECK (row_index >= -1)`;并与动作形态配对——非 v2 展开动作必须 `row_index = -1`,
  v2 展开动作必须 `row_index >= 0`(配对检查落在 application_mode/action 类型维度,防哨兵与
  真值混写拆分幂等域,同既有 node_epoch_paired 的设计动机)。
- **迁移**:单事务内——加列(带 DEFAULT,既有行自动回填 `-1`)→ 验证零 NULL → 删旧唯一索引 →
  建含 `row_index` 的新唯一索引。六元组在旧行上唯一 ⇔ 七元组(六元组, -1)唯一,故重建无冲突风险;
  迁移前置断言旧索引存在且唯一(防对半成品库重放)。
- **旧调用兼容**:FWB-1/2/3 写入路径**零改动**——不写 `row_index` 即落 DEFAULT `-1`,与其既有
  幂等语义逐字节等价;兼容合同以回归测试钉住(旧路径 INSERT 形状不变 + 重复投递仍被七元组拒)。
v1 曾提议 `(instanceId, rowIndex)` 二元键——同实例配两条规则/两个动作时第 0 行即碰撞,**作废**。

**类型映射(v2 更正,审阅 P1-2)**:明细叶子类型为 **8 种**(text/textarea/number/date/datetime/
select/multi-select/user),FWB 目标闭集为 text/date/select(number 待 D0-D4)。「天然咬合」为误;
delta lock 须携带**源子列类型 × 目标字段类型的逐格矩阵**(每格=转换规则或明确拒绝),v1 建议:
text/textarea→text;date→date;**datetime→v1 明确拒绝**(v3 更正:不提供「截断」选项——FWB 既有
语义防时区造值,截断即在目标时区语境下制造一个源头不存在的日期);select→select(闭集选项);
multi-select、user、number→**v1 拒绝**(number 单独依赖 D0-D4 线,不在本锁内解)。

其余三决定不变:重提交只追加+溯源列带版本;仅批准后;溯源列(instanceId/business_key/row_index/
快照时间)强制,无溯源不落行。

**定位(v2 收窄,审阅第 4 条)**:FWB v2 是**批准后的分析/联动路径**,不是导出替代——它不覆盖
草稿/驳回实例、不产出 Excel 文件、无回导。文件级导出(含主+子一并导出、编辑后回导)为**独立
缺口**,是否立项见 §7-A;§6 对标表与 §6c S1 口径已相应修正。

## 5. v1.2 明细引用桥(表→审批,重尾场景)

形态不变:行先活在受治理多维表 → 表侧选中行发起审批 → 关联记录**多行模式**引用 → 提交时
**按行投影快照**进 form_snapshot(A1 保持)→ 批准后 FWB 照常。增量:关联记录多行化、行投影
快照、表侧发起入口。

**继承口径(v2 收窄,审阅第 7 条)**:v1.2 使**提交前的编辑能力**自动继承表的更新(新列类型/
导入/AI 填充在编辑阶段全额可用);**提交后一切仍受 A1 冻结**,表的后续演化不改已冻结快照。
「自动继承全部未来更新」的旧表述作废。

**证据门(不变)**:出现真实重明细审批用例(>50 行或需协作预填/导入)前不开工。

## 6b. 回传/JS 实况与行公式的真实路径(v2 更正)

- **回传:有且治理过**——`wait_for_callback`:持久化挂起(suspension row + suspended job),
  resume 跑尾段;legacy fail-closed。**用户 JS:无,系设计立场**(executor 无 eval;可编程性=
  16 动作闭集+公式字段+按钮+AI 字段)。
- **行公式不能写「沿用审批条件引擎」**(v1 表述作废):`ApprovalConditionFormula` 公开校验/执行
  合同**强制最终结果为 boolean**(内部虽可算数值)。且仓内已有 `lineDerivation`(FE-only、仅
  product、backend 不重算)。通用行公式=**独立 delta lock**,至少定:服务端权威重算、精度/舍入
  (与 exact-number D0-D4 线的关系)、错误语义(公式错→行怎么办)、快照语义(存值还是存式+值)、
  **与 lineDerivation 的收敛路径**(取代或扩展,不允许第三套并存)。
- 三公式引擎事实不变(`formula/engine.ts`、`multitable/formula-engine.ts`、条件公式),语法/限额
  对齐为长期项。

## 6d. 能力继承通道与「从表取数」(v2 修正)

**继承通道**:
1. **v1.2 引用桥**=唯一自动通道,口径收窄为**提交前编辑能力**(§5)。
2. **共享单元格层(v2 降级为「先抽合同」)**:审阅证实成本被低估——类型名**非直接子集**
   (审批 text/datetime/user vs 表 string/dateTime/person),且 `MetaCellEditor` 内嵌 Yjs 协同、
   附件、成员、关联记录协议,直接换组件=把表的运行时协议拖进审批表单。正确的第 0 步是抽
   **域中立的 codec/editor contract**(类型名映射表+纯值进出+无协同依赖),两域各自适配;
   是否值得抽,作为独立裁决(§7-D)。
3. 类型注册表子集约定:保留,但以上述映射表为前提(名字都对不齐谈不上子集)。
4. 网格级能力永不继承。

**从表取数(表→明细行,值拷贝,A1 保持)**:
- (a) copy-in 多选导入:picker 多选化+列映射+服务端取值端点。量级:中。
- (b) 行级引用+伴生列:填单中可刷新,提交冻结为拷贝。量级:中-大。
- 安全底线:服务端以发起人身份过表 ACL;发布时目录校验;跨 org 不通。
