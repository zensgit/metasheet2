# 审批明细表 × 多维表互通设计短文(含宜搭子表单对标)

日期:2026-08-25 · 状态:**PROPOSED**(本文不 ratify 任何内容;§7 列出全部待 owner 裁决项)
输入:宜搭「子表单」官方文档全文(用户提供的 yuque.com/yida/support/in0w72 存档,2026-08-25 摘录)、
本仓 FWB0 锁(`write_approval_form_values`,已 RATIFY)、B0-B2 明细/授权线交付(#5142/#5143)。

## 1. 判据:审批明细是「证据」,多维表行是「活数据」

审批实例提交后进服务端**不可变 `form_snapshot`**(FWB 锁 D4 明文依赖:表单值永不进事件载荷,
executor 只按 instanceId 读不可变快照)。多维表行是持续演化的协作状态。由此得到两条设计公理:

- **A1(冻结边界)**:任何互通设计必须保持「提交即冻结」;不存在也不应存在审批单↔表的实时双向同步。
- **A2(三缝原则)**:生态已有三条缝——关联记录(引用进)、FWB(批准后快照出)、automation 桥
  (表事件触发审批)。新能力必须落在这三条缝上,不得开第四条(「另造更窄同类物=合同变更」纪律)。

三相成本分析(为何不做「表单内嵌可编辑网格」):提交前是 1~20 行/单人/分钟级——嵌千行级协作网格
是阻抗错配;**审批中**要把按节点字段权限(hidden/readonly per node,#5143 已交付)投影到按人/角色
的表权限上——两个权限模型的乘积,是嵌表方案真正的硬核成本;审批后「数据进表」已被 FWB 解决。
宜搭的「平铺方式」是表格在移动端不成立的自供状——嵌网格同样要接这道题。

## 2. 互通通道全景

| 通道 | 方向 | 内容 | 状态 |
|---|---|---|---|
| 关联记录 | 表→审批 | 表单引用表中行;发布时 `assertRecordLinkTargetsReadableByCreator` | ✅ 已上线 |
| 审批桥 | 表→审批 | 表事件自动发起审批(lease 机制) | ✅ 落 main,**旗 OFF** |
| FWB v1 | 审批→表 | 批准后,主表字段(text/number/date/select)建行或经关联记录锚定更新;目标不信客户端 | ✅ RATIFIED+落地,**旗 OFF** |
| **FWB v2 明细展开** | 审批→表 | 明细 N 行→表 N 行 | ❌ 本文 §4 |
| **明细引用桥 v1.2** | 表→审批 | 重明细「先建后审」:行引用+提交时投影快照 | ❌ 本文 §5,设证据门 |

自动化底盘现成:事件生产者五族、event-fires 租约、durable-delivery(六项 RC 修复已交付)、
executor 事务接线守卫。相关旗(`APPROVAL_FWB_WRITEBACK_ENABLED` + AUTOMATION 三旗)全 OFF,
启用序列归 P2 durable-delivery 线,**owner 排期**。

## 3. v1.1 原生补刀(轻明细,零架构变化)

范围:①复制行;②上/下移;③删除确认(可选文案);④xlsx 批量导入到原生明细行(复用考勤
import xlsx-guard 技术;**借鉴宜搭边界:公开免登表单禁用导入**);⑤序号列(显示行号)。
不含:平铺/主题/列冻结/自定义列宽/操作列自定义(§6)。
基线依托:row-key 焦点稳定(#5142)、min/maxRows 每字段自定义上限(已有,优于宜搭按付费版本
50/500 全局分层)、行内叶子类型+选项校验(已有)。验收:每能力判别测试+mutation;导入需
恶意文件负例(沿 xlsx-guard 语料)。

## 4. FWB v2:明细行展开投递(审批→表)

一单明细 N 行 → 目标表 N 行。类型天然咬合:明细子列本就限于 text/number/date/select,
恰为 FWB v1 闭集,D5-D8 逐列映射机器直接复用。配置形态:
`detailFieldId + 子列映射[{subColumnId→targetFieldId,targetType,selectOptions?}]`,
服务端自动附带溯源列(instanceId / business_key / rowIndex / 快照时间)。

四个设计决定(v1 立场):
1. **扇出幂等**:幂等键 `(instanceId, rowIndex)`;投递走 durable-delivery/lease 底盘。
2. **重提交语义**:只追加+溯源列带版本;不做改写/墓碑(把表当从库是复杂度陡增的错误方向)。
3. **时机门**:沿 FWB「仅批准后」——只有批过的事实落表。
4. **溯源列强制**:无溯源不落行(对账/去重/回跳审批单全靠它)。

治理:FWB0 锁点名了 v1 类型集与配置形状——**本节=delta lock,owner 裁决先行**,非顺手加 case。

## 5. v1.2 明细引用桥(表→审批,重尾场景)

形态:行先以真实数据身份活在受治理多维表(表的权限/导入/移动端,零投影)→「从表格选中行
发起审批」(桥方向已存在)→ 关联记录**多行模式**引用 N 行 → 提交时**按行投影快照**进
form_snapshot(A1 保持)→ 批准后 FWB 照常。三个增量:关联记录多行化、行投影快照、表侧发起入口。

**证据门(不满足不开工)**:出现一个真实的重明细审批用例(如备料单走审批,>50 行或需协作预填/
导入)。此前本节仅保留为设计意向。

对标结论:**不追控件形态对齐,追「毕业路径」**——宜搭的子表单再强也是表单里的残缺表格;
我们的差异化是轻明细原生、重明细毕业成真表、批后数据自动落表闭环,它没有表,做不出后两段。

## 6a. 宜搭「高级功能」(§4:操作列/回调/定制渲染)处置

其高级三件套的本质是**让用户往表单里写 JS**。对宜搭(低代码平台,JS 沙箱是核心资产)成立;
对我们照抄意味着:①每个审批人浏览器里执行模板作者的任意代码=新攻击面;②**证据问题**——
任意代码决定审批人看到什么,审计就必须回答「批的那一刻跑的哪版代码」,击穿快照教义;③长期养护。

但其 FAQ 暴露的回调**真实用途**九成有声明式等价物:

| 用户实际要什么 | 宜搭手段 | 我们的声明式等价 | 量级 |
|---|---|---|---|
| 行内计算列(金额=数量×单价) | 回调 | 受限**行公式列**(见 §6b) | 中 |
| 按主表值控制子列显隐 | 回调 | 既有字段级 visibilityRule 下沉到子列 | 小-中 |
| 子列明细内唯一性校验 | 脚本 | 子列声明式「明细内唯一」开关 | 小 |
| 行数统计/变量控条数 | 脚本 | min/maxRows 已有;行数写入表单字段 | 小 |
| 操作列自定义按钮 | 回调 | **类型化行动作闭集**(借表侧模式) | v1.1 内 |
| 定制渲染 | 组件注入 | 不做;等价物=补充叶子列类型 | — |

小项(子列显隐/明细内唯一/行数联动)并入 **v1.1.5** 第二批;行公式列单独成片。
声明式的关键收益:规则是**数据**——进快照、可审计、可迁移;JS 三样都不行。

## 6b. 多维表「回传/JS」实况与复用边界(2026-08-25 代码验证)

- **回传:有,且治理过**——`wait_for_callback` 动作:执行至此持久化挂起(suspension row +
  suspended job),executor 停,外部回调/resume 后跑尾段;legacy 规则 fail-closed(A6-2/A6-3-3)。
- **用户 JS:无,系设计立场**——executor 无 eval/new Function;可编程性=16 个类型化动作闭集 +
  公式字段(受限表达式)+ 按钮字段(record_click,同 executor 路径,审计点击)+ AI 字段。

**复用边界:模式可用,运行时不搬。**
- 行公式列走**审批自己的公式引擎扩行作用域**(`ApprovalConditionFormula.ts` 已存在:流程条件
  在用、带 dry-run、成套 DoS 界 512 字符/128 节点/16 层/64 引用)。不搬 MultitableFormulaEngine:
  表引擎语义绑着表字段/lookup/跨表引用,入表单皆悬空;且审批快照须可离线重放。
- 回传不进表单:**审批流本身即审批域的挂起-恢复模型**(节点=挂起点);表侧回传留给表自动化。
- 操作列借「闭集动作+同一执行路径+审计」模式,不开脚本口。

**登记一项事实**:仓内现有三个独立公式引擎(`formula/engine.ts`、`multitable/formula-engine.ts`、
`ApprovalConditionFormula.ts`)。各域内成立,但构成语法漂移面——**约定:行公式沿用审批引擎的
语法与同一份 LIMITS 常量**,用户在审批域内只见一种公式语言;跨产品语法对齐列为长期项,不在本文范围。

## 6d. 能力继承通道与「从表取数」(2026-08-26 补,代码验证)

事实:多维表存在通用单元格层(`multitable/components/cells/MetaCellEditor.vue`/`MetaCellRenderer.vue`,
类型分发);审批明细单元格今日为独立 el-input/number/date-picker;`ApprovalRecordLinkPicker` 现为单选
(`currentRecordId`,含 repin 竞态防护)。

**继承通道(多维表更新 → 明细)**:
1. **v1.2 引用桥 = 唯一「自动」通道**(by construction:编辑在真表内,表的一切更新天然全额惠及
   重明细)。此为 v1.2 的第二存在理由,权重不低于大行数场景。
2. **共享单元格层**(半自动):明细单元格改用 MetaCellEditor/Renderer,此后单元格级改进自动流入。
   代价明记:共享=跨域耦合——审批域校验/快照语义必须包在外层,单元格仅管输入输出,并以契约
   测试钉住两域接口;表侧破坏性改动会波及审批,需 census 级守卫。
3. **类型注册表子集约定**:明细叶子类型=表类型注册表的受限子集;表新增叶子类型后明细「解锁」
   即登记,不重写控件。
4. 网格级能力(视图/冻结/协同)**永不继承**——要即毕业(v1.2)。

**从表取数(表 → 明细行,均落关联记录缝,A1 冻结公理保持:取来即值,提交冻结)**:
- **(a) 从表导入 copy-in**:picker 多选 N 行 → 按列映射拷贝为 N 条明细行,后可编辑。xlsx 导入的
  姊妹项。需:picker 多选化、明细字段列映射配置、服务端取值端点。量级:中。
- **(b) 行级引用+伴生列**:子列=行级关联记录,伴生列自动取所选记录字段;填单中可刷新,提交冻结
  为拷贝。兼作继承通道(表字段进化经伴生列以显示拷贝进入明细)。量级:中-大。

安全底线(沿既有纪律):取值服务端以**发起人**身份过表 ACL(不信客户端拼值);发布时目录校验沿
`assertRecordLinkTargetsReadableByCreator`;跨 org 不通。两形态产物均为值,入 form_snapshot,
审计可离线重放。
