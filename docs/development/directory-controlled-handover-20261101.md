# 同企业目录受控交接：E4 → Canary

状态：开发候选，仅合成隔离环境验证。未执行线上交接、审批处置、停用或启用同步。

## 目的与范围

保留两个本地用户及其身份、授权、角色、权限和本地待办，把同一钉钉企业的目录来源由旧集成交给已核验的新集成。无需复制同企业账号，不通过解绑／重绑产生登录或成员权限空档。

首版只提供具有数据库访问权限的运维 CLI，不新增管理 API、页面按钮或后台自动任务。输入中的 `actorId` 用于校验并记录当前活跃平台管理员；CLI 的执行授权仍来自受控主机／数据库访问及另行批准的运维窗口。不得把它开放给普通用户。

## 三项阻断如何处理

| 原阻断 | 实现 |
| --- | --- |
| 同企业账号唯一键不允许再建一份 Canary 账号 | 原 `directory_accounts.id` 不变，仅在事务中移动 `integration_id`，不放宽唯一约束 |
| 同一本地用户不能同时链接两份钉钉目录账号 | 原链接、用户 ID、外部身份和登录授权全部保留，不创建第二个账号链接 |
| 解绑／重绑会短暂破坏账号、权限、待办链 | 交接及回退单事务执行，审批实例和指派不改；变化摘要不匹配即拒绝 |

源部门保留；目标缺失部门复制镜像字段，已有同 external ID 部门须在 provider、名称、父级、路径、排序、active、raw 上一致。主部门、负责人标记及原创建时间保留。部门 raw 负责人信息冲突直接拒绝。

## 先决条件与硬停止

- 两端必须是同组织、同非空 Corp ID 的活跃钉钉集成，自动同步关闭；自动准入、成员组投影关闭。
- 目标企业／应用标识必须与当前管理员核验记录一致，记录包含核验人和时间。这是管理员证据，不能替代钉钉提供方的登录／应用归属验证。
- 旧来源非空；两端合计不超过 1,000 账号、1,000 部门；整份来源交接，不支持部分账号。
- 两端没有运行中的同步、进行中的企业迁移或未回退的交接；涉及的账号均属于同一企业，目标没有冲突账号。
- 两端部门没有本地投影绑定、委派管理员范围、范围模板、e-learning ACL／统计／导出引用，也不被目录路由策略引用。存在依赖先另行设计，不能悄悄迁移授权或扩大范围。
- 没有未解决的撤权副作用；两端任何钉钉卡片所指审批仍 pending 时，拒绝交接。即使卡片发送失败也不绕过。
- E4 的在途审批依赖必须由业务负责人另行处置。本功能不完成、取消、重分配或执行审批；测试中的 9 项普通本地待办保留不能代替真实审批处置。

## 状态与操作顺序

1. **preview**：只读一致性快照，校验管理员及条件，返回摘要和数量。保留批准的摘要，不靠重新预览自动接受漂移。
2. **apply**：持两端现有 source-sync advisory 锁、用户锁、目录行锁，重核快照及摘要；移动账号和成员关系，原子写入交接日志。两端同步和新卡片创建进入冻结。
3. **离线／另批验收**：核对两个账号、角色／权限、外部身份、登录授权、本地待办、同企业应用归属。正常登录时间和身份 profile 遥测可以更新，账号身份键、密码、active、角色、授权等变化仍拒绝自动完成或回退。
4. **rollback**：仅 applied 状态、原 after 摘要仍匹配才恢复来源账号、部门映射和原时间；删除本次新增且未被引用的目标部门。新增授权／模板／配置等变化一律拒绝，绝不级联抹掉后续操作。
5. **finalize**：另行确认后仅完成日志状态；释放目标同步／卡片冻结，源同步／新卡片持续冻结。不会打开任一端同步，也不会停用集成、改凭据或全局 OAuth 配置。
6. **后续退役**：另行审批后处理旧来源用途、登录和存档。本次不提供自动删除、企业切换或退役。

## 运维命令

在已批准且完成备份的隔离／维护窗口中，以 Node 20 运行后端工作目录：

```sh
pnpm ops:directory-handover preview /restricted/preview.json
pnpm ops:directory-handover apply /restricted/apply.json
pnpm ops:directory-handover rollback /restricted/rollback.json
pnpm ops:directory-handover finalize /restricted/finalize.json
```

preview 输入必须且只能包含 `sourceIntegrationId`、`targetIntegrationId`、`actorId`。
apply 添加 preview 的 `digest` 及精确 `confirm: "apply"`。
rollback／finalize 输入必须且只能包含交接 `id`、apply 返回的 `digest`、`actorId` 和精确操作名称 `confirm`。回退和完成是二选一，不是连续必跑步骤。错误只输出固定拒绝提示，不输出 SQL、配置、原始快照或凭据。

## 并发、发送及恢复边界

交接是罕见的运维动作。为覆盖现有未参与用户 mutex 的权限写入，短事务使用权限及部门依赖表 `SHARE NOWAIT` 锁；会影响所有组织的相关写入，不阻塞普通读取。已有冲突写入立即拒绝；等待其他锁最多 5 秒，每条语句最多 30 秒（不是总事务时限）。线上必须另批维护窗口。

卡片 INSERT 触发器与同步共享冻结锁，并持集成 `FOR SHARE`。apply 更新集成 tuple 版本，旧 REPEATABLE READ 写事务也不能使用旧快照穿过冻结。该局部序列化拒绝转换为专属数据库约束错误；发送执行器只把这个确知尚未调用提供方的错误记为可重试失败。其他错误和不确定发送继续保守拒绝自动重发。

交接日志的配置、权限／身份内容只保存摘要，凭据及密码不复制到日志；目录账号和部门恢复快照只留在受限业务数据库，不进入 PR／报告。日志非空时迁移 down 拒绝，避免删除冻结历史。

applied 或 finalized 后，不得直接降级为不了解交接冻结的旧后端。优先用本版本 rollback（仅 applied 且无漂移）；已 finalize／出现变化需另行方案。数据库备份恢复只在一致维护窗口、匹配版本代码下执行，不能覆盖此后业务写入。恢复后的冻结触发器、日志、权限和待办须重新验收。
