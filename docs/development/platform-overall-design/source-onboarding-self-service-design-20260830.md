# 源接入自助化设计:「确认,不配置」(2026-08-30,DRAFT)

> **地位**:接管后(post-takeover)产品化候选,不进入当前任何门;values-free。
> **缘起**:2026-08-30 对首家客户 PLM 的手工结构分析。本文把该次手工过程系统化。
> **owner 指令(2026-08-30)**:实施系统配置时,一定要简单方便——故 §1 简单性预算是本设计的第一约束,任何后续实现与它冲突时,砍功能,不砍简单。

## 1. 简单性预算(硬约束,验收要量)

**客户侧**:
- 全程 **一屏一流程**,总投入 **≤ 10 分钟**;可中断、回来续做;
- **零术语**:客户看不到"表/列/join/映射/字典"这些词,只看到自己的数据和"对/不对"的问题;
- **零填空**:所有输入是点选(候选带真实值样本),没有一个自由文本框是必填的;
- 每个问题都带**默认答案**(系统最优猜测已选中),客户全部直接"下一步"也能走完——错了会在预览里显形。

**实施侧(我方)**:
- 探测 = **一条命令**(只读连接串进,草案 JSON 出);
- 审核 = **一个 diff 页 + 一键落文件**;
- 新厂商 preset 的录入 = 填一个 JSON 模板,不写代码。

## 2. 范式:不让客户配置,让客户确认

配置(理解对方数据模型→填表)对客户是高成本高错误率动作;**认出自己熟悉的数据**是近零成本动作。一切交互 = 系统提议 + 客户在真数据预览上确认/修正。

## 3. 五步流(客户只出现在 ③④)

| 步 | 内容 | 执行者 |
|---|---|---|
| ① 探测 | 连只读库 → 读结构 + **字典表** → 有语义列清单 | 全自动 |
| ② 提议 | 厂商预置命中 → 直接出草案;未命中 → 通用启发式(§4)+ 内置分析(§5) | 全自动 |
| ③ 确认 | 真数据预览(走受管读取路径),客户点列修正,候选带真实值样本 | 客户 |
| ④ 选择题 | 业务判断做成 A/B 预览(哪套 BOM 权威、项目号锚点、编码口径) | 客户 |
| ⑤ 生效 | 草案 → 我方审核 → **落成服务端受审文件**(pack + ext 映射) | 我方 |

## 4. 陌生厂商的通用启发式(厂商无关,一次实现)

1. **字典表探测**(首家客户实证的可泛化特征):扫描小表,若某列的行值集合 ⊆ 其他表的列名集合 → 该表是字段字典;其"启用位/显示名/类型"列随之可识别。
2. **BOM 树探测**:(head, detail) 表对——detail 带指向 head 主键的 `*pid*` 列,且 detail 部件列可回指 head 部件列(递归展开特征)。
3. **物料主表探测**:被 detail 外键指向、文本列密度高(名称/规格/材料形态)的表。
4. **数量候选**:detail 表数值型启用列;多候选进 ③ 由客户在真值样本间挑。
5. **层级形态判定**:树表(`OBJ_ID/Parent_OBJ_ID`)→ 递归构造路径串;路径串列 → 直接映射。

## 5. 内置分析步骤(把"专家问答"产品化)

预置未命中且启发式多解时,内置 LLM 分析:输入**仅表结构 + 字典标签**(values-free,零业务行),输出映射草案 + 客户选择题文案。失败/不可用回退人工——每厂商一次,产出固化为新预置(§6)。可关(on-prem 无外呼场景走纯启发式+人工)。

## 6. 厂商预置目录(飞轮)

每条 preset:字典表位置与解读法、join 拓扑、递归规则、行粒度、已知坑。**陌生厂商解决一次 → 入目录 → 同厂商后续客户零接触。** 首条 preset = 首家客户 PLM(通用扩展列 + 字典表 + 路径树形态)。

## 7. 治理不变量(不妥协;与 §1 冲突时以本节胜)

- ③ 预览 = dry-run,**必须走受管读取路径**(B2a 登记 + 一次性 claim + armed floors);配置页永不成为读取旁路。
- 页面只产**草案**;生效必经我方审核落服务端文件(复用 pack/installer)。映射错误不报错而产错数据,审核一格永不省。
- 探测/提议阶段零业务行;真值样本一律在 ③ 的受管预览里出现。
- 凭据只由 ops 输入服务端;不过页面草案、不过 git、不过分析步骤。

## 8. 节奏与验收

- **H0(现在,零开发)**:首家客户手工走完;探针脚本 + 推导规则随手工沉淀。
- **H1(接管完成后)**:③④ 确认页 + preset #1 + ⑤ 审核落文件。**验收判据两条:页面产出映射与首家手工版逐字节一致;真实客户操作全程 ≤10 分钟(计时)。**
- **H2(预置目录 ≥3 条后)**:陌生厂商全流程(§4+§5)。

## 9. 首家客户实证记录(H1 实现依据,values-free)

- 通用扩展列形态:明细 36 列中 30 列无语义占位;字典启用极稀(明细 2/30:数量 float、单位 list←取值表;表头 0/10;物料 21/73)。**结论:只要 DDL 对此类系统无效,字典表必须同取。**
- 层级是树非路径串;两套 BOM(设计 BOM 行数更多)与近空订单模块 → 权威源/锚点必须问不可推断——此即 ④ 存在的理由;首批题库 = 该客户四问(项目号锚点/BOM 权威/订单启用/编码口径)。

## 10. 对标:Maptable「数据连接」(2026-08-30 公开手册实读)

**借鉴**:逐表配置词表(同步开关/部分字段/schema/全量-增量/游标字段/主键)与我方 watermark/idempotencyKey 词表对齐,客户零学习成本;字段类型标注弹窗即 ③ 的已验证交互形态;同步频率四档(手动/日/周/月)符合 §1 简单性预算;同步记录页应做客户可见;host/database 不可改、删除重建——不可变+重建优于可编辑+校验。
**不抄的退步**:主键未指定 → 重复行(fail-open)——我方身份缺失即 hold(fail-closed)不让步;"勿切换同步模式"靠文档劝——我方配置快照绑定/契约钉结构性解决;"增量 0 行配置不生效"类安静意外——我方漂移即拒。
**其 FAQ = 坑清单入测试矩阵**:模式切换冲突、游标配错、0 行同步配置不生效、SSL 连接失败——同场景我方须响亮拒绝或行为可预期。SQL Server 兼容参照:2012-2019 + Azure(首家客户 2019 在内)。
