## Refresh and failure retention

Preview keeps the explicit `sourceKind` discriminant. Refresh does not. The refresh body for both kinds is `{ expectedVersion, rowKey }`. An extra `sourceKind` fails the strict schema as 422 `ECO_REQUEST_INVALID` and does not open a transaction.

After the source advisory lock and the locked binding read, kind is `asKind(binding.source_kind)`. `refreshKeyForKind` then requires width 4 for `eco` or width 5 for `readiness`, calls only that kind's released row-key helper, and requires the binding coordinates. A wrong width is 422 `ECO_REQUEST_INVALID` before the wire helper, so it does not surface as a wire id code and does not call the other provider. A well-formed tuple whose coordinates differ is 409 `ROW_KEY_MISMATCH`. Both refusals happen before the kind-specific capability statement, `fenceWriterEntry`, source admission, and provider egress. The shared ECO table probe and the binding read still run, because the kind comes from the stored binding.

Refresh takes the ruleset from stored key slot 4 and the Item from slot 3, which must equal the binding Item. Collection CAS is the binding version plus the frozen nullable Native version. `readinessCollaborationBusinessHash` already excludes `generated_at` and `snapshot_at`. Hash equality is a noop: the original accepted `captured_at`, cells, and history stay, and no `meta_records` update or revision insert runs. An ordered resource change, a ruleset change, or a Native version change is not a clock noop.

Confirm of an explicit target checks fresh source admission, sheet authority, and field or selected-row write authority inside the preflight transaction, before provider egress. A stored selected tuple uses `fieldAndLock(..., true)`, which takes the canonical row-auth advisory and checks row and source-field write authority. A tuple that is not stored yet uses `assertSourceFieldGrants`. That transaction commits before the provider call, so the lock is not held across HTTP. The post-HTTP publication checks remain. A selected-row ACL `none`, a read-only or hidden source field, or a concealed source field returns 403 `FORBIDDEN` with no provider call. A granted business-delta confirm calls the provider once and writes.

Confirm and refresh catch an anchor mismatch from the released parser and pass it to the existing stale path. The failure identity includes the selected row key. Before the stale update, retention rechecks the active actor, the matched binding identity, the live source fingerprint (a persistent token change changes that fingerprint), and, when a selected row is already stored, that row under `acquireRecordLinkRowAuthLockOnQuery` before `loadRecordPermissionScopeMap`. The advisory is held in the same transaction through the stale update. Record ACL `none` on that stored row returns without a stale mark. Readiness requires the selected tuple to be stored; two rulesets in one readiness binding are the same binding, not two bindings, and an absent second ruleset does not stale the collection. An ECO append of a not-yet-stored eco tuple keeps the old collection stale behavior when source, sheet, CAS, and frozen identity still match. A stored ECO row still applies the optional ACL check. An unchanged source and an unchanged selected-row authority keep the existing 401/403 stale policy for that captured identity. A later collection CAS advance or a disable returns without a stale mark. The stale update passes the stored row key as `$14` only when that row is present; a missing ECO append key passes NULL and does not demand the new row. A 502 or 503 stays a failure, writes no empty row, and does not resurrect another ruleset. The row-auth order is a unit query-order control. It is not a PostgreSQL interleaving proof. Replay rechecks current authority and fingerprint and does not call the provider. Native tenant and org still come only from the persisted source config headers and options.
